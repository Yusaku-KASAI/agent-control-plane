# 0003. ロールは Claude Code のカスタムエージェントとして定義し、プラグインで共有する

## Context

同じターゲットに役割の違うエージェントを置く（app ADR 0002）。ロールごとの指示はターゲットが宣言し
（app ADR 0001）、仕組みは Claude Code の標準機能を優先する（app ADR 0005）。同じロールは多くのターゲットで
使い回される。

Claude Code では、`.claude/agents/<名前>.md` やプラグインに含めたカスタムエージェントを `--agent <名前>` で
セッション全体に適用できる。前置きなしの名前で指定した場合、ターゲットに同名の定義があればそれが使われ、
なければプラグインの定義が使われる。カスタムエージェントを指定しても、ターゲットの `CLAUDE.md` は読み込まれる。

## Decision

- ロールは Claude Code のカスタムエージェントとして定義する。
- ロールの定義には、どのターゲットでも通用する振る舞いだけを書く。ターゲット固有の事実や規約は
  そのターゲットの `CLAUDE.md` に書き、実行時に両者が組み合わさる。
- 複数のターゲットで使うロールは、カスタムエージェントを含む Claude Code プラグインとして配布し、
  ターゲットは `.claude/settings.json` で使うプラグインを宣言する。
- control-plane はロール名を前置きなしで `claude -p --agent <ロール名>` に渡す。ターゲットが同名の
  定義を置けば、共有のロールを丸ごと差し替えられる。
- 定義の frontmatter でツールやモデルを指定してもよいが、権限の境界としては扱わない（app ADR 0003）。

## Alternatives

- **独自のロールファイルを置き、`--append-system-prompt-file` で渡す**：Claude Code の標準の置き場所と
  二重になる。対話で作業する人間やサブエージェントとして同じロールを使えない。
- **プロンプトの先頭で「このファイルに従え」と指示する**：指示に従うかどうかがモデル次第になる。
- **control-plane がロールの定義を持ち、`--agents` で渡す**：ターゲットが宣言するという方針に反する。
- **ターゲットごとにロールを書き分ける**：同じ振る舞いの記述が各ターゲットに重複する。

## Consequences

- 同じロールの定義を、control-plane からの起動、対話で作業する人間、サブエージェントのいずれでも使える。
- ターゲットでの差し替えは定義の丸ごとの置き換えになる。ターゲット固有の補足は、差し替えではなく
  `CLAUDE.md` に書くのを基本にする。
- 複数のプラグインが同名のロールを持つと、前置きなしの名前では区別できない。
- 共有のプラグインができるまで、このリポジトリの `.claude/agents/` に置くロールにもリポジトリ固有の内容は書かない。
