# 0021. ターゲットは、写した版を記録し、ひな形の新しい版に三方向のマージで合わせる

## Context

ターゲットは写す元の `target/` から写して作り（ADR 0018）、`Fill in:` の所を埋める。ひな形が新しくなったとき、
ターゲットは埋めた所を残したまま、共通の部分の変更を取り込む必要がある。`template/` の文書は差し替えて、外への
リンクを書き換える（ADR 0020）。埋めるファイルは、ひな形の変更とターゲットの埋めた所が同じファイルに混ざるので、
ファイルごとの上書きでは埋めた所を失う。

## Decision

- 写すときと合わせるときに、ターゲットの `template/base` に、その版の agent-control-plane のコミットを書く（写す元に
  コミットしていない変更があるときは書かない。そのコミットには変更がないため）。
- 合わせるときは（`template/bin/update-target`）、copier の update と同じ形で、写す元のファイルごとに、ターゲットの
  ファイル、`template/base` の版、今の版を三方向でマージする（`git merge-file`）。ぶつかった所は印を付けて残し、人か
  エージェントが直す。
  - ターゲットにないファイルは、前の版になければ足す。前の版にあれば、ターゲットが消したもの（organization の
    `CODEOWNERS` など）として足さず、ひな形の側で変わっていればぶつかったものとして挙げる。
  - `.tmpl` のひな形のうち、ターゲット自身の文書（`README.md` と `docs/`。ファイルの分類では固有）は、ないときに
    足すだけで、マージしない。`CLAUDE.md`（埋める。契約の節を持つ）はマージする。
  - 写す元から消えたファイル（名前を変えたものの古い名前を含む）は、消さずに挙げる。
- `template/` の文書は今の版に差し替える。写すときと同じ道具（`template/bin/put-template`）を使う。
- 合わせる前に、ターゲットの作業ツリーに変更がないことを求め、合わせた結果を一つの差分として読んで戻せるようにする。

## Alternatives

- **共通のファイルだけを上書きし、埋めるファイルは差分を見せて手で合わせる**：埋めるファイル（Dockerfile、ci.yml、
  Makefile など）にもひな形の変更が多く入り、手で合わせる量が減らない。どれが共通かの一覧も道具に持たせることになる。
- **ひな形の版ごとに移行の手順を書く**：版の数だけ手順が要り、写した版と今の版の間の手順を全部たどることになる。
- **copier や cruft を使う**：同じ形（写した版の記録と三方向のマージ）の確立した道具だが、ひな形を Jinja の変数と
  質問で書く形が前提で、ここでは `Fill in:` の印のまま人やエージェントが埋める。ひな形の書き方と依存が増える。
- **ターゲットを agent-control-plane の fork や subtree にして、git の履歴でマージする**：ターゲットのリポジトリに
  agent-control-plane の履歴とほかのファイルが入る。写す元は `target/` の下だけで、ルートの並びも違う。

## Consequences

- `template/base` のないターゲット（この形の前に写したもの）は、写した版を探して `--base` に渡す。写す元が `target/` の
  形になる前のコミットは、前の版がないので渡せない（`update-target` が止める）。
- 合わせるには、`template/base` のコミットを含む agent-control-plane の clone が要る。
- 写す元から消えたファイルは消さない。ターゲットが同じ名前で自分のものを持ちうるため。
