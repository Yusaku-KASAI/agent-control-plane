# 0007. マーケットプレイスは devcontainer でのパスで宣言し、隣のリポジトリのものは control-plane がそこだけマウントする

## Context

control-plane は、ターゲットの中にあるマーケットプレイスのプラグインだけを `--plugin-dir` で読み込ませていた
（ADR 0004）。共通のロールやプラグインはこのリポジトリの `platform/` にあり、他のターゲットの中にはない。
headless の Claude Code は宣言されたプラグインをインストールしないので、他のターゲットのエージェントは roles
などを使えない。devcontainer は隣のリポジトリを `/workspace` に読み取り専用でマウントするので、人が対話で
使うときは `/workspace/agent-control-plane/platform` を `directory` のマーケットプレイスとして宣言すれば届く。

## Decision

- マーケットプレイスは、`.claude/settings.json` に devcontainer でのパス（`/workspace/<リポジトリ>/...`）で
  宣言する。どのターゲットも同じ書き方になり、target-template にそのまま置ける。
- 隣のリポジトリを指すパスは、control-plane がホストでターゲットの隣にあるディレクトリに読み替え、そのディレクトリ
  だけをエージェントのコンテナの同じパスに読み取り専用でマウントし、プラグインを `--plugin-dir` で渡す。
- ターゲット自身の中を指すパスは、セッションの作業領域の中として扱う。マーケットプレイスを開発しているターゲットの
  エージェントは、作業中のブランチの版で動く。
- `/workspace` の外を指すパスは読み替えない。
- 将来別のリポジトリに切り出すマーケットプレイスは、切り出した後のリポジトリの場所で宣言する。切り出すまでは、
  ホストでその場所に今の場所を指す相対パスのシンボリックリンクを置く。切り出したら、リンクを clone に置き換える
  だけで、ターゲットの宣言は変わらない。
- 隣のリポジトリを指すパスでも、ホストでリンクをたどった先がターゲット自身の中なら、セッションの作業領域の中として
  扱う。マーケットプレイスをまだ持っているリポジトリも、他のターゲットと同じ宣言のまま、作業中のブランチの版で動く。

## Alternatives

- **control-plane の設定でマーケットプレイスの名前とディレクトリを対応させる**：人向けの宣言
  （`settings.json`）とエージェント向けの設定の二か所に書くことになる。
- **隣のリポジトリをすべてマウントする**：関係のないリポジトリまでエージェントに見える。
- **ターゲット自身の中のマーケットプレイスは相対パスで書く**：マーケットプレイスを持つリポジトリと持たない
  リポジトリで書き方が変わり、target-template に同じ宣言を置けない。
- **control-plane が GitHub などからマーケットプレイスを取得する**：取得のための認証と版の管理が要る。
  ホストに隣のリポジトリがない場合（リモートから取得するターゲットなど）に改めて考える。

## Consequences

- 人とエージェントが、同じ宣言から同じマーケットプレイスを使う。control-plane に設定は要らない。
- ターゲットの隣にマーケットプレイスのリポジトリを clone しておく必要がある。そのディレクトリの今の内容が
  そのまま使われ、コミットしていない変更も届く。
- devcontainer がリポジトリを `/workspace/<リポジトリ名>` に、隣のリポジトリを `/workspace` に置くという決まりに
  頼る。セッションの作業領域のディレクトリ名がリポジトリ名と違うと、自身の中を指すパスを読み替えられない。
