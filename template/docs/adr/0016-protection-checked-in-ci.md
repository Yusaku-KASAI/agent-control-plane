# 0016. 既定のブランチの守りを、platform の複合アクションで CI の必須の検査として確かめる

## Context

既定のブランチの守り（PR 経由、人の承認、push での取り消し、必須のチェック、バイパスの範囲）は、リポジトリの設定と
CODEOWNERS で作る（[app ADR 0027](../../../docs/adr/app/0027-require-human-approval-in-ruleset.md)、ADR 0015）。守りが外れても
何も失敗しない。CODEOWNERS の誤った行は黙って無視され、持ち主のユーザー名が変わったり書き込みの権限を失ったり
すると、ファイルを変えなくても外れる。ADR 0015 では、それを見つけるのは人が手順の確かめ方を回したときだけだった。

ブランチに効くルール（`rules/branches/<ブランチ>`）、CODEOWNERS の誤り（`codeowners/errors`）と中身（`contents`）、
ルールセット（`rulesets/<id>`）は、読み取りの権限の GitHub App のトークンでも、個人のリポジトリの CI の
`GITHUB_TOKEN`（`contents: read`）でも読めた。organization のリポジトリでは確かめていない。
ルールセットのバイパス（`bypass_actors`）は、ルールセットを書ける呼び手にしか返らないので、`GITHUB_TOKEN` では読めない。

## Decision

- github プラグインに、守りを確かめるコマンド `check-protection` と、それを CI で回す複合アクション
  （`platform/plugins/github/actions/check-protection`）を置く（ADR 0014 と同じ形。ただしアクションはリポジトリを
  チェックアウトせず、GitHub の API だけを読む）。ターゲットの `ci.yml` は
  `check-protection` ジョブでそれを呼び、`check` ジョブはそのジョブも待つ。権限は `contents: read` だけにする。
- 確かめる値は target-template の手順（`guides/github.md`）の設定で、コマンドはその API の側の写しを持つ。
- CODEOWNERS は、CI が確かめるコミット（PR では、マージしたときの版）のものを確かめる。コードオーナーの承認で人に
  限るときは、誤りがないこと、最初の規則が `*` であること、持ち主のない規則がないこと。team で人に限るときは、
  CODEOWNERS はなくてよく、あってもその問題は知らせるだけにする。
- バイパスは、読めれば確かめ（管理者の役割か organization の管理者だけ、PR のときだけ）、読めなければ読めないと
  出して失敗にしない。CI では読めないので、管理者が手元でコマンドを回すか、設定の画面で確かめる。
- 守りが外れていれば、PR の変更と関わりなく、必須のチェック `check` が落ちる。毎週の定期実行でも回る。

## Alternatives

- **人が手順の確かめ方を回すだけにする（ADR 0015 のまま）**：ファイルを変えずに外れたときに、だれも確かめ直さない。
- **必須のチェックに含めず、知らせるだけのジョブにする**：落ちても PR を止めないので、見落とされる。守りが外れたまま
  マージが進むより、設定を直すまで止まる方に倒す。
- **バイパスも CI で確かめる**：管理者の権限を持つトークンを CI に渡すことになり、守るものより強い認証情報が要る。
- **ターゲットごとに `ci.yml` に検査を書く**：検査の具体がターゲットの共通の部分に出て、ADR 0014 と同じ理由で避ける。

## Consequences

- PR が触れていない設定や CODEOWNERS の持ち主で守りが外れると、どの PR の CI も落ちる。直すのは設定で、PR の中では
  直らない。PR が CODEOWNERS を変えて外したときは、その PR の中で直る。
- organization のリポジトリで `GITHUB_TOKEN` で読めなければ、正しい設定のターゲットでも、このジョブが読めないこと
  （終了コード 2）で落ちる。
- 新しいターゲットは、ルールセットを設定するまで CI が通らない。
- CI で確かめるのは、手順の設定のうちバイパスを除いたもの。バイパスは人が確かめる。
- バイパスの役割の番号（管理者が 5）は、GitHub の文書の値ではなく、ルールセットの書き出しで使われている値に拠る。
