# 0012. ターゲットの CLAUDE.md は、プロダクトの前提を含む決まった節を持つ

## Context

2 つ目のターゲット（txt-crypter）で、エージェントはセキュリティの評価をしたが、本番が Cloudflare Pages で
ビルドした成果物を配っていること、Notion への埋め込みで使われていること、共有済みのリンクを開けるままに
しなければならないことを知らず、開発サーバーが外に公開されている前提で評価し、依頼者に指摘されてやり直した。
CLAUDE.md には、何のアプリかの一文と、完了条件、言語、共通のルールしかなかった。何を書くかの決まりがないので、
ターゲットごとに書くことがばらばらで、抜けにも気づけない。

## Decision

- ターゲットの CLAUDE.md は、決まった節を決まった順に持つ。節と書くことは[ターゲットの契約](../../../platform/docs/reference/target.md#claudemd)に置く。
- 節には、プロダクトの前提として、使われ方、公開と運用、守る互換を含める。エージェントが判断を誤るのは、コードから
  読み取れないこれらの前提を知らないとき。
- どの節も短くし、詳しいことは文書へのリンクにする（CLAUDE.md は常に読み込まれる）。当てはまらない節も
  「なし」と書いて残し、書き忘れと区別する。

## Alternatives

- **形を決めず、ターゲットごとに書く**：何が抜けているかに気づけない。txt-crypter はこの状態だった。
- **プロダクトの前提を README や docs に書き、CLAUDE.md からリンクする**：リンク先は必要と判断されたときしか
  読まれない。評価や設計の前提は、読まれないと誤った判断のまま進む。
- **節ごとに別のファイルにして CLAUDE.md から取り込む**：取り込みはリポジトリの中なら効くが、ファイルが増え、
  短い節のために分ける利点がない。

## Consequences

- ターゲットを作るとき、またテンプレートから作るときに、節を埋める必要がある。
- 節が揃っていることは、まだ検査していない。target-template を切り出すときに検査にする。
