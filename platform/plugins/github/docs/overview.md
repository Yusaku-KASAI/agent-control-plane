# github の全体像

PR の本文は、追記ではなく今のブランチの姿に合わせて書き換え、push ごとの変更はコメントにする
（[ADR 0002](../../../docs/adr/0002-pr-body-tracks-head.md)）。このプラグインは、それを `prctl` と hook で守らせる。

## 構成

```
github/
  bin/prctl            PR の作成と本文の書き換え、本文が古いかの判定、hook の本体
  hooks/hooks.json     Bash のあと（PostToolUse）とターンの終わり（Stop）に prctl hook を呼ぶ
  skills/github/       PR の本文とコメントの書き方、レビューと CI への対応
```

- `prctl` は本文に、どの head コミットまで説明したかの印（`<!-- prctl: head=<コミット> -->`）を隠して入れる。本文が今の
  head を説明しているかは GitHub の本文から読むので、セッションやコンテナをまたいでも同じ答えになる。
- hook は push のあとに本文が古いことを見つけて書き換えを促し、スキルはどう書くかを教える。

## 構成要素

### `bin/prctl`

- **責務**：今のブランチの開いている PR を作り、本文を印付きで書き換え、本文が古いかを判定する。
- **置くもの / 置かないもの**：PR はブランチ名で探す（引数なしの `gh pr view` は upstream をたどり、別のブランチの PR を
  返すことがある）。書き換えは push 済みの HEAD に対してだけ行い、前の印から push があったときは、その変更を説明する
  コメントを必ず付ける。本文の書き方は置かず、スキルに任せる。
- **関係**：`git`、`gh`、`jq` を使う。`gh` の認証はハーネスの契約で渡される（[ハーネスの契約](../../../docs/reference/harness.md)）。
- **当てはめた原則・パターン**：[単一の情報源](../../principles/docs/reference/principles.md#ssot)：どこまで説明したかは本文の印にだけ持つ。

### `hooks/hooks.json`

- **責務**：push のあとと、ターンの終わりに、本文が古いことを見つける。
- **置くもの / 置かないもの**：
  - Bash のあと（`prctl hook post-tool-use`）：今の HEAD が push 済みで、PR の本文がそれを説明していなければ、書き換えを
    促す文脈を足す。一つの push には一度だけ促す。
  - ターンの終わり（`prctl hook stop`）：この作業ツリーから push した head を本文が説明していなければ、ターンを終わらせず、
    本文を書き換えて依頼への回答全体をまとめ直すよう求める。説明済みと確かめた head は覚えて、GitHub に聞き直さない。
    hook に促されて続けたターンでは、もう止めない。
  - どちらも自分のエラー（PR がない、`gh` やネットワークが使えない）でツールの呼び出しやターンを失敗させない。覚えた
    head は作業ツリーの `.git` の中に置く。
- **関係**：`bin/prctl` を呼ぶ。
- **当てはめた原則・パターン**：[仕組みで守る](../../principles/docs/reference/principles.md#mechanisms)：本文を書き換えることをプロンプトに
  頼らず、hook で見つけて促す。

### `skills/github/`

- **責務**：PR の本文とコメントの書き方と、レビューと CI への対応の手順。
- **置くもの / 置かないもの**：エージェントが従う手順とコマンド。`prctl` と hook の仕組みの説明はこの文書に置く。
- **関係**：roles の developer が PR を作る・更新するときに使う。
