# 相談に乗る

相談を受けた人（人でもエージェントでも）が、相談や壁打ちの依頼を受けてから、考えを返し、残す考えがあれば Issue に残すまでの
手順。目的の手順で、段の中で共通の手順を使う（[手順と役割](../architecture/documentation.md#procedures)）。
決まりは[課題の扱い方](../reference/issues.md "在りか")にある。

相談は、依頼者が決めたいこと、整理したいことについて考えを求める依頼で、事実を聞くだけの質問は含まない。同じ問いの
続き（壁打ちの次の回）は続きで、6 段で答えたあとも 2 段から繰り返す。途中で目的が変わったら（変更にする、課題を
整えるなど）、新しい依頼として振り分けから入る。

1. **始めに読む**：次を全体まで読む。この段は省かない。このセッションですでに全体まで読んだ文書は、読み直さなくてよい。
   - [課題の扱い方](../reference/issues.md)：相談の前提になる Issue をどう読み、考えをどこにどう残すか（キャンバス、
     ラベル、ADR にするとき）。
2. **問いを読む**：依頼と、それが指す Issue、PR、スレッドを読み、何を決めたいのか、何が前提で、何が決まっていないかを
   言い直す。読み方に迷いがあれば、どう読んだかを答えに書く（聞いて待てないときは、妥当な読み方で進める）。
3. **調べる**：問いが関わる仕組みの今の姿と前提を、文書、ADR、コード、Issue で確かめる。確かめていないことは推測と
   書く。
4. **広げて絞る**：選択肢を挙げる。頼まれた手段や依頼者の案だけでなく、目的に立ち返った別の手段、より単純な形、一つ上の
   枠組みでの解き方も挙げる（[前提を問い直す](../../../principles/docs/reference/principles.md#double-loop)）。確立した原則や
   パターンがあれば名前を挙げる（principles スキル）。比べる軸を決めて比べ、勧めるものとその理由、決めるのに足りない
   情報を書く。
5. **キャンバスに残す**：壁打ちが何回かにわたるとき、数式、図、長い表を使うとき、決まったことや論点を後に残すときは、
   [キャンバス](../reference/issues.md#canvas)の Issue に書く（Issue に書かないものと、ほかの人のコメントの扱いも、そこにある）。本文を今の姿に書き直し、
   回ごとの考察はコメントに書く。
   依頼が決める Issue（[Issue の本文](../reference/issues.md#body)）を指すときは、答えが出たら、その Issue の `## 今の姿` に答えを書いて範囲の中の項目にチェックを付ける。
   決まったことのうち、やることは Issue（[Issue の本文](../reference/issues.md#body)の形）に分け、決まりや設計の判断は ADR にする変更の Issue にする。自分の書ける範囲で
   Issue に書けないときは、残す中身を答えに書き、書けるロールに頼むよう案内する。
6. **答える**：結論か勧めを先に書き、根拠、ほかの選択肢と選ばなかった理由、決めてほしいこと、次の一歩を続ける。キャンバスに
   残したら、その Issue へのリンクと、何を書いたかを添える。チャットで読めないもの（数式、図、長い表）は答えに写さず、
   キャンバスを指す。
