# 課題を整える

課題を整えるよう頼まれた人（人でもエージェントでも）が、頼まれてから、Issue とロードマップを整っている状態に合わせ、
整えたことのまとめを答えるまでの手順。目的の手順で、段の中で共通の手順を使う（[目的の手順と共通の
手順](../architecture/documentation.md#procedures)）。決まりは[課題の扱い方](../reference/issues.md "在りか")にある。

まとめを答えたら終わる。そのあとの依頼（まとめに書いた決めてほしいことへの答えを受けて直すなど）は、新しい依頼として
振り分けから入る。整える中で文書やコードを直す要に気づいたら、この手順では直さず Issue にする（その場で直すなら、
変更を届けるに入り直す）。

1. **始めに読む**：次を全体まで読む。この段は省かない。このセッションですでに全体まで読んだ文書は、読み直さなくてよい。
   - [課題の扱い方](../reference/issues.md)：Issue の分類、ロードマップ、整っている状態。
   - リポジトリのラベルの決まり（どこを変えるかのラベルの名前と意味）：リポジトリの参照の文書にある（索引の
     `docs/README.md` からたどる）。なければ、ないことをまとめに書く（[課題の扱い方](../reference/issues.md)の分類の下の箇条と、
     [整っている状態](../reference/issues.md#tidy)の人が決めるもの）。
2. **範囲を決める**：依頼が指す Issue、テーマ、ラベルがあればそれ、なければ開いているすべての Issue とロードマップに
   する。一度に見きれないときは、ロードマップの今の焦点と、最近動いた Issue から見て、見なかった範囲をまとめに書く。
3. **今の姿を確かめる**：範囲の Issue ごとに、本文、コメント、ラベル、依存関係と、それに触れた PR（マージされたか、
   閉じたか）を読み、リポジトリの今の姿（文書、ADR、コード）と照らして、終えたか、本文が古いかを確かめる。
4. **ずれを挙げる**：[整っている状態](../reference/issues.md#tidy)と照らし、合わないものを Issue ごとに挙げる。
   それぞれを、直すものと人が決めるもの（同じ節の表の下）に分ける。
5. **整える**：直すものを直す。
   - 本文を書き直す前に、消える記述がコメントかほかの Issue に残っているかを確かめる
     （[失われうるものを先に挙げる](../../../principles/docs/reference/patterns.md#loss-first)）。書き直したら、何をなぜ変えたかを
     コメントに書く。
   - 閉じる前に、終えた根拠（PR、まとめた先の Issue）をコメントに書く。重なる Issue は一つにまとめ、ほかは、まとめた先を
     書いて閉じる。
   - Issue を作るとき（分ける、抜けていたやることを足す）は、同じものがないかを先に探し、ラベルを付け、読む人がその
     Issue とリポジトリから読み取れることだけで続けられるように書く。
   - 最後に、範囲にロードマップを含むか、この手順で Issue を閉じたときは、ロードマップの今の焦点を整っている状態と
     照らし、合わなければ、閉じた Issue を外し、PR はそれが閉じる開いている Issue に書き換え、このリポジトリにない
     番号は直すか外し、依存関係と方針に合う順に書き直す。PR が開いている Issue を閉じないときは、閉じた PR なら外し、
     開いている PR は人が決めるもの（整っている状態の節）としてまとめに書く。
   - 自分の書ける範囲で直せないものは、まとめに書く。
6. **まとめを答える**：整えたこと（Issue ごとに何をしたか、リンク付き）、人が決めること（案を添えて）、見なかった範囲と
   確かめていないことを書く。
