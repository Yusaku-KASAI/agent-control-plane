# セッションを締める

セッションで作業した人（人でもエージェントでも）が、締めるよう頼まれてから、持ち越すものを Issue に残し、作業領域を
片付けられる状態にして、締めのまとめを答えるまでの手順。目的の手順で、段の中で共通の手順を使う（[目的の手順と共通の
手順](../architecture/documentation.md#procedures)）。決まりは[課題の扱い方](../reference/issues.md "在りか")にある。

締めのまとめを答えるか、2 段で締めずに人に返したら終わる。そのあとの依頼（開いている PR の指摘に答える、持ち越した
Issue に取りかかるなど）は、新しい依頼として振り分けから入る。人に返したあとにもう一度締めるよう頼まれたら、1 段から
入り直す。締めたあとも同じセッションに依頼してよい。

1. **始めに読む**：次を全体まで読む。この段は省かない。このセッションですでに全体まで読んだ文書は、読み直さなくてよい。
   - [課題の扱い方](../reference/issues.md)：持ち越すものの置き場所と、Issue とロードマップの決まり。
2. **開いている PR を確かめる**：このセッションの名前のブランチ（control-plane 経由なら `$ACP_SESSION_BRANCH` と
   `$ACP_SESSION_BRANCH-<内容>`）と push したブランチを挙げる（push したブランチの見分け方は、動き方ごとにハーネスの
   契約にある。control-plane 経由なら、platform の[ハーネスの契約](../../../../docs/reference/harness.md#work-area "在りか")の
   作業領域とブランチ）。それを head ブランチか base ブランチとする開いている PR（下書きも含む）があれば、締めない。
   その PR を並べ、マージするか閉じてから、もう一度締めるよう頼んでほしいと答えて終える。
3. **洗い出す**：このセッションでしたことを見返し、[持ち越すもの](../reference/issues.md#carry-over)を種類ごとに挙げる。
   覚えていることだけで挙げず、依頼のスレッドや会話、このセッションで作ったか更新した PR の本文（確かめていないこと）と
   レビュー（打ち切った提案、範囲の外とした提案）、作業領域（`git status`、`git stash list`、push していないコミット、
   `git worktree list` で見えるサブエージェントなどの worktree とその `git status`）を読み直す。
4. **残す**：挙げたものを、持ち越すものの置き場所（Issue）に残す。すでにある Issue に当たるものはそこに書き足し、同じ
   ものを二つ作らない。新しい Issue は、ラベルを[課題の扱い方](../reference/issues.md)に沿って付け、読む人がその Issue と
   リポジトリから読み取れることだけで続けられるように書く。文書やコードを直すべきものは、この手順では直さず Issue に
   する（その場で直すなら、締めをやめて[変更を届ける](deliver-change.md "在りか")に入り直し、その PR を終えてから締め
   直す）。自分の書ける範囲の外に置くものは、置き場所とともに締めのまとめに書いて、人に渡す。
5. **課題の今の姿を合わせる**：このセッションが扱った Issue（依頼の Issue、PR が閉じたか触れた Issue、分けて作った
   Issue）ごとに、終えたなら閉じ、範囲を分けたなどで本文の今の姿が古くなったなら書き直す。そのうえで、閉じたか起きた
   Issue があれば（PR のマージで閉じたものを含む）、ロードマップの今の焦点が古くなっていないかを確かめ、古ければ本文を
   書き直す。
6. **片付けられる状態にする**：片付けを止める条件は、動き方ごとにハーネスの契約にある（control-plane 経由なら、platform の
   [ハーネスの契約](../../../../docs/reference/harness.md#lifetime "在りか")のコンテナの寿命）。
   - 作業領域にしかないもの（条件のうち作業領域にあるもの。ほかの worktree の変更も含む）は、残す価値のある中身を
     Issue に書いてから捨て、捨てたものを締めのまとめに書く。要らない worktree は `git worktree remove` で消し、その
     worktree のブランチも消す。
   - このセッションの名前のブランチのうち、どこにも入っていないコミットのために片付けを止めるもの（条件は契約）は、
     中身を Issue に残してから、リモートのブランチと手元の同じ名前のブランチを消す。リモートだけを消すと、手元の
     コミットがどこにもないコミットになり、片付けを止める。消すブランチのうち今いるものは、手元を作られたときと同じ形
     （既定のブランチの先頭から切った、upstream のないブランチ）に切り直し、締めたあとも同じブランチで続けられるように
     する（`git fetch origin <既定のブランチ>`、`git switch --detach origin/<既定のブランチ>`、`git branch -D <ブランチ>`、
     `git switch --no-track -c <ブランチ>`）。ほかの名前のリモートのブランチは消さない。
7. **締めのまとめを答える**：最後の回答に、次をこの順で書く。
   - 残したもの：Issue へのリンクと、それぞれ何を残したか。
   - 人がすること：決めてほしいこと、書ける範囲の外に置いてほしいもの。
   - 片付けを止めているもの：残る理由。なければ、片付けられる状態になったこと。
   - 続け方：別のセッションで続けるときは、このスレッド（か会話）の在りかと、持ち越した Issue を渡せばよいこと。
