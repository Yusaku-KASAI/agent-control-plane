# セッションを締める

セッションで作業した人（人でもエージェントでも）が、締めるよう頼まれてから、持ち越すものを Issue に残し、片付けを
止めているもののうち自分で解けるものを解いて、締めのまとめ（解けずに残るものを含む）を答えるまでの手順。目的の手順で、段の中で共通の手順を使う（[目的の手順と共通の
手順](../architecture/documentation.md#procedures)）。決まりは[課題の扱い方](../reference/issues.md "在りか")にある。

締めのまとめを答えるか、2 段で締めずに人に返したら終わる。そのあとの依頼（開いている PR の指摘に答える、持ち越した
Issue に取りかかるなど）は、新しい依頼として振り分けから入る。人に返したあとにもう一度締めるよう頼まれたら、1 段から
入り直す。締めたあとも同じセッションに依頼してよい。

1. **始めに読む**：次を全体まで読む。この段は省かない。このセッションですでに全体まで読んだ文書は、読み直さなくてよい。
   - [課題の扱い方](../reference/issues.md)：持ち越すものの置き場所と、Issue とロードマップの決まり。
2. **片付けを止めているものを確かめる**：片付けを止めているもの（残す理由）の確かめ方と、理由の種類ごとに次のどの
   扱いに当たるかは、動き方ごとにハーネスの契約にある（control-plane 経由なら、platform の
   [ハーネスの契約](../../../../docs/reference/harness.md#lifetime "在りか")のコンテナの寿命）。それで確かめ、扱いごとに分ける。
   - **続く作業**：このセッションのブランチを head か base とする開いている PR（下書きも含む）のように、まだ依頼が
     ありうるもの。この段で人に返す。
   - **作業領域にしかないもの**：作業領域の中にしかなく、作業領域の中で捨てられるもの。6 段で解く。
   - **人が解くもの**：作業領域の外にあって消すと失われるもの（どこにも入っていないリモートのブランチなど）と、
     ほかの書き手の作業に関わるもの。エージェントは消さない。6 段で中身を残し、まとめに書く。

   続く作業があれば、締めない。その PR を並べ、マージするか閉じてから、もう一度締めるよう頼んでほしいと答えて終える。

   確かめ方が契約にない動き方（片付けのない動き方）か、確かめ方が判定できずに終わったときは、自分で確かめる。
   このセッションで作業して push したブランチを head とする開いている PR を挙げ、判定できなかったときは、このセッションの
   ブランチ（見分け方は契約）を base とする開いている PR も挙げる（片付けのない動き方では、消すと閉じる base の PR は
   見ない）。あれば同じく人に返す。なければ、3 段で作業領域を自分で読み直し、6 段は飛ばす。判定できなかったときは、
   理由がないとはみなさず、確かめられなかったことと出力を 7 段のまとめの人がすることに書く（片付けられる状態とは
   書かない）。
3. **洗い出す**：このセッションでしたことを見返し、[持ち越すもの](../reference/issues.md#carry-over)を種類ごとに挙げる。
   覚えていることだけで挙げず、依頼のスレッドや会話、このセッションで作ったか更新した PR の本文（確かめていないこと）と
   レビュー（打ち切った提案、範囲の外とした提案）、作業領域（2 段で確かめた理由が指すもの。2 段で自分で確かめたときは、
   作業ツリーの変更、stash、push していないコミット、サブエージェントなどの worktree とその中身、このセッションの
   ブランチ（リモート）のうち、開いている PR がなく、その先頭が既定のブランチにも、マージしたか閉じた PR の head
   コミットにも入っていないものと、push したブランチのうち、最後に push したコミットが既定のブランチにも、マージしたか
   閉じた PR の head コミットにも、そのリモートのブランチにも入っていないもの）を読み直す。
4. **残す**：挙げたものを、持ち越すものの置き場所（Issue）に残す。すでにある Issue に当たるものは、
   [Issue に書き足すとき](../reference/issues.md#append)の扱い（それだけで成り立つなら切り出し、関わりが強ければ範囲の中の
   項目にして、閉じていれば開き直す）でそこに書き足し、同じものを二つ作らない。新しい Issue は、ラベルを[課題の扱い方](../reference/issues.md)に沿って付け、[Issue の本文](../reference/issues.md#body)の
   形で、読む人がその Issue とリポジトリから読み取れることだけで続けられるように書く。文書やコードを直すべきものは、この手順では直さず Issue に
   する（その場で直すなら、締めをやめて[変更を届ける](deliver-change.md "在りか")に入り直し、その PR がマージされたか
   閉じてから締め直す）。自分の書ける範囲の外に置くものは、置き場所とともに締めのまとめに書いて、人に渡す。
5. **課題の今の姿を合わせる**：このセッションが扱った Issue（依頼の Issue、PR が閉じたか触れた Issue、分けて作った
   Issue）ごとに、終えたなら閉じ、範囲を分けたなどで本文が今を表さなくなったなら書き直す。範囲の中にこのセッションの PR の番号を末尾に添えた
   項目は、その PR がマージされたならチェックを付け、マージされずに閉じたなら番号を外す。済んだ項目は消さない
   （[依頼の範囲](../reference/issues.md#scope)）。そのうえで、閉じたか起きた
   Issue があれば（PR のマージで閉じたものを含む）、ロードマップの今の焦点に閉じた Issue が残っていないかを確かめ
   （[整っている状態](../reference/issues.md#tidy)のロードマップの行）、残っていれば外す。ここで直すもののほかに気づいた課題の
   ずれ（今の焦点の順番、PR、このリポジトリにない番号、上の条件に当たらないときの閉じた Issue、ほかの整っている状態との
   ずれ（ラベル、blocked by など。このセッションが扱った Issue のものも含む））は、直さず締めのまとめに書く
   （[ADR 0030](../adr/0030-close-session-leaves-other-drifts.md)）。
6. **片付けを止めているものを解く**：2 段で確かめた理由を、扱いごとに解く。理由に当たらないもの（変更のない worktree、
   先頭がどこかに入ったブランチ、作業領域そのものなど）は、作業領域の中のものでも扱わない。片付けが消す。
   - 作業領域にしかないもの：残す価値のある中身を Issue に書いてから捨て、捨てたものを締めのまとめに書く。捨て方は
     契約の種類ごとの扱いにある。
   - 人が解くもの：残す価値のある中身を Issue に書き、消さずに残す。締めのまとめに、残る理由として書く。

   解いたら、もう一度確かめ、残る理由を 7 段のまとめに使う。2 段で自分で確かめたときは、この段は飛ばす（作業領域に
   しかないもので持ち越すものは、3 段と 4 段で Issue に残してある）。
7. **締めのまとめを答える**：最後の回答に、次をこの順で書く。
   - 残したもの：Issue へのリンクと、それぞれ何を残したか。
   - 人がすること：決めてほしいこと、5 段で直さなかった課題のずれ、書ける範囲の外に置いてほしいもの、下の片付けを
     止めているもののうち人が解くもの。
   - 片付けを止めているもの：6 段のあとにもう一度確かめて残る理由と、そのうち人が解くものはその印と、中身を残した
     Issue。なければ、片付けられる状態になったこと。人が片付けさせるやり方（承知して消させるやり方を含む）は、動き方
     ごとに契約にあるので、それも添える。
   - 続け方：別のセッションで続けるときは、このスレッド（か会話）の在りかと、持ち越した Issue を渡せばよいこと。
