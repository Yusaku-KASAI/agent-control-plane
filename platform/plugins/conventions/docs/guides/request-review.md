# レビューを頼んで答える

変更した人が、自分の変更（PR）の差分をレビューしてもらい、指摘に答えて、終えられるようにするまでの手順。共通の
手順で、目的の手順（[変更を届ける](deliver-change.md "在りか")など）の段の中で使う（[目的の手順と共通の手順](../architecture/documentation.md#procedures)）。
決まりは[レビューの扱い方](../reference/reviews.md "在りか")にある。

## 頼む

1. **いつ頼むか**：PR を作る前（PR 全体の差分のレビュー）と、push で PR の head が進んだとき（前回のレビューからの差分）。
   範囲が細部の指摘への意味の変わらない直しだけなら頼まず、レビューしない直しとして残す（[差分のレビュー](../reference/reviews.md#diff)）。
2. **頼む相手と渡すもの**：変更した人とは別の人か、別の文脈のエージェントに頼む。自分では見ない。エージェントなら、
   reviewer ロールがあればそのサブエージェントに頼む（ロールの指示が、レビューする手順と、その始めに読む文書を並べて
   いる）。どの相手でも、頼む文に、目的の手順の[レビューする](review.md "在りか")と、その 1 段の文書（文書の体系、
   レビューの扱い方）の在りかと、結果を返し GitHub には残さないこと（残すのは自分）を書く。ほかに渡すのは、依頼の
   内容、変更の意図、差分（コミットの範囲）の三つだけにする。たどった考えは渡さない（[差分のレビュー](../reference/reviews.md#diff)）。
3. **残す**：結果を[結果の形](../reference/reviews.md#record)で、見た最後のコミットに付けた PR のレビューとして残す。PR を
   作る前のレビューは、作ったあとに残す。

## 答える

1. **答えを決める**：指摘ごとに、元の文書とコードで根拠を確かめてから、答え（直す、直さない、Issue にする、質問に答える）を決める。
   根拠のない指摘には合わせず、違う点は理由を書いて残す。提案と細部は、直さずに理由を書いて終えてよい。Issue に
   するのは、この PR の範囲の外の直しになるものだけにする。
2. **直す**：直すものをすべて直してから、まとめて push する。
3. **次のレビューに回すか決める**：細部の指摘への、意味の変わらない直しだけなら、その範囲を次のレビューに回さず、レビューしない直しとして PR の
   レビューに残す。ほかの直しがあれば、次のレビューに回す（上の「頼む」に戻る）。
4. **答えを書く**：すべての指摘に、番号ごとに答えを書く（[結果の形](../reference/reviews.md#record)、答える場所は
   [差分のレビュー](../reference/reviews.md#diff)）。直したら、PR の本文も今の中身に合わせる。

## 終える

終えたと報告する前に、PR 全体の差分のレビューをすべての観点で頼み、[終える前](../reference/reviews.md#ending)を満たすまで、
上の「答える」で進める。満たしたら PR の下書きを外す。上限の回数（同じく「終える前」）しても満たせなければ、残っている
ことを添えて依頼者に返す。
