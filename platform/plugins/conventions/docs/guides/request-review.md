# レビューを頼んで答える

変更した人が、自分の変更（PR）の差分をレビューしてもらい、指摘に答えて、終える前を満たすまでの手順。共通の
手順で、目的の手順の段の中で使う（[手順と役割](../architecture/documentation.md#procedures)）。
決まりは[レビューの扱い方](../reference/reviews.md "在りか")にある。

## 頼む

1. **回し方を決める**：依頼者が念入りに頼んだ PR なら念入り、ほかは通常にする
   （[回し方](../reference/reviews.md#ways)）。念入りなら、PR を作る前のレビューから観点ごとに並べ、PR を作ったらすぐに
   PR に印を付ける。印がなければ、PR は通常として扱われる。
2. **いつ頼むか**：PR を作る前（PR 全体の差分のレビュー）と、push で PR の head が進んだとき（通常なら PR 全体、念入りなら
   前回のレビューからの差分。念入りでも、終える前の PR 全体のレビューの指摘への直しなら PR 全体）。範囲が細部の指摘への
   意味の変わらない直しだけなら頼まず、レビューしない直しとして残す（[差分のレビュー](../reference/reviews.md#diff)）。
3. **頼む相手と渡すもの**：変更した人とは別の人か、別の文脈のエージェントに頼む。自分では見ない。通常なら一人に、念入りなら
   観点ごとに一人ずつ並べて頼み、それぞれに見る観点を書く。エージェントなら、reviewer ロールがあればそのサブエージェントに
   頼む。どの相手でも、頼む文に、レビューする人が沿う手順とその始めに読む文書の在りかと、結果を返し GitHub には残さない
   こと（残すのは自分）を書く。ほかに渡すのは、依頼の内容（依頼の Issue がなければ、依頼の範囲を含める）、変更の意図、
   差分（コミットの範囲）、検討した別の形（PR の本文の同じ名前の節）の四つだけにする。たどった考えは渡さない
   （[差分のレビュー](../reference/reviews.md#diff)）。変更の意図と検討した別の形は、頼む文の最後の見出しの下にまとめ、
   レビューする人が依頼から別の形を挙げたあとで読めるようにする。
4. **PR を作って残す**：PR は下書きで作り、途中のあいだは下書きのままにする（[終える前](../reference/reviews.md#ending)）。
   結果を[結果の形](../reference/reviews.md#record)で、見た最後のコミットに付けた PR のレビューとして残す。観点ごとに
   頼んだ結果は、一つにまとめて残す。PR を作る前のレビューは、作ったあとに残す。

## 答える

1. **答えを決める**：指摘ごとに、元の文書とコードで根拠を確かめてから、答え（直す、直さない、Issue にする、質問に答える）を決める。
   根拠のない指摘には合わせず、違う点は理由を書いて残す。提案と細部は、直さずに理由を書いて終えてよい。Issue に
   するか依頼の Issue に積むのは、この PR の範囲の外の直しになるものだけにし、
   [済んでいないものの置き場所](../reference/issues.md#append)に沿う。
2. **直す**：すべての指摘の答えを決め、直すものをすべて直してから、まとめて push する。指摘ごとに push しない。
3. **次のレビューに回すか決める**：細部の指摘への、意味の変わらない直しだけなら、その範囲を次のレビューに回さず、
   レビューしない直しとして PR のレビューに残す。ほかの直しがあれば、次のレビューに回す（上の「頼む」の 2 段に戻る）。
4. **答えを書く**：すべての指摘に、番号ごとに答えを書く（[結果の形](../reference/reviews.md#record)、答える場所は
   [差分のレビュー](../reference/reviews.md#diff)）。直したら、PR の本文も今の中身に合わせる。

## 終える前を満たす

1. **終える前のレビューを頼む**：終えたと報告する前に、PR 全体の差分のレビューをすべての観点で頼み、
   [終える前](../reference/reviews.md#ending)を満たすまで、上の「答える」で進める。通常の回し方では、打ち切ってよいときに
   打ち切り、そのレビューの提案には、理由を「打ち切り」で始めて直さないと答える（[回し方](../reference/reviews.md#ways)）。
