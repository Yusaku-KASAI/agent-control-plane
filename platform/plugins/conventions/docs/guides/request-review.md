# レビューを頼んで答える

変更した人が、自分の変更（PR）の差分をレビューしてもらい、指摘に答えて、終えられるようにするまでの手順。共通の
手順で、目的の手順の段の中で使う（[目的の手順と共通の手順](../architecture/documentation.md#procedures)）。
決まりは[レビューの扱い方](../reference/reviews.md "在りか")にある。

## 頼む

1. **回し方を決める**：依頼者が念入りに頼んだか、全体のレビューの報告から作る PR なら念入り、ほかは通常にし、念入りなら
   PR に印を付ける（[回し方](../reference/reviews.md#ways)）。
2. **いつ頼むか**：PR を作る前（PR 全体の差分のレビュー）と、push で PR の head が進んだとき（通常なら PR 全体、念入りなら
   前回のレビューからの差分）。範囲がレビューしない直し（回し方の表）だけなら頼まず、レビューしない直しとして残す
   （[差分のレビュー](../reference/reviews.md#diff)）。
3. **頼む相手と渡すもの**：変更した人とは別の人か、別の文脈のエージェントに頼む。自分では見ない。通常なら一人に、念入りなら
   観点ごとに一人ずつ並べて頼み、それぞれに見る観点を書く。エージェントなら、reviewer ロールがあればそのサブエージェントに
   頼む（ロールの指示が、レビューする手順と、その始めに読む文書を並べている）。どの相手でも、頼む文に、目的の手順のレビューする（conventions の `docs/guides/review.md`）と、その 1 段の文書（文書の体系、
   レビューの扱い方）の在りかと、結果を返し GitHub には残さないこと（残すのは自分）を書く。ほかに渡すのは、依頼の
   内容、変更の意図、差分（コミットの範囲）の三つだけにする。たどった考えは渡さない（[差分のレビュー](../reference/reviews.md#diff)）。
4. **残す**：結果を[結果の形](../reference/reviews.md#record)で、見た最後のコミットに付けた PR のレビューとして残す。観点ごとに
   頼んだ結果は、一つにまとめて残す。PR を作る前のレビューは、作ったあとに残す。

## 答える

1. **答えを決める**：指摘ごとに、元の文書とコードで根拠を確かめてから、答え（直す、直さない、Issue にする、質問に答える）を決める。
   根拠のない指摘には合わせず、違う点は理由を書いて残す。提案と細部は、直さずに理由を書いて終えてよい。Issue に
   するのは、この PR の範囲の外の直しになるものだけにする。
2. **直す**：直すものをすべて直してから、まとめて push する。
3. **次のレビューに回すか決める**：レビューしない直し（[回し方](../reference/reviews.md#ways)の表）だけなら、その範囲を次のレビューに
   回さず、レビューしない直しとして PR のレビューに残す。ほかの直しがあれば、次のレビューに回す（上の「頼む」の 2 段に戻る）。
4. **答えを書く**：すべての指摘に、番号ごとに答えを書く（[結果の形](../reference/reviews.md#record)、答える場所は
   [差分のレビュー](../reference/reviews.md#diff)）。直したら、PR の本文も今の中身に合わせる。

## 終える

1. **終える前を満たす**：終えたと報告する前に、PR 全体の差分のレビューをすべての観点で頼み、
   [終える前](../reference/reviews.md#ending)を満たすまで、上の「答える」で進める。満たしたら PR の下書きを外す。満たせない
   まま回し方の表の「依頼者に返すとき」に当たったら、残っていることを添えて依頼者に返す。
