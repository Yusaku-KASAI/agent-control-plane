# レビューする

差分のレビューと全体のレビューの手順。決まりは[レビューの扱い方](../reference/reviews.md "在りか")にある。

## 差分のレビュー

1. 依頼の内容、変更の意図、差分を集める。自分が変更した差分なら、自分では見ずに、変更した人とは別の人か別の文脈の
   エージェントに渡す。渡すのはこの三つだけにする（[差分のレビュー](../reference/reviews.md#diff)）。
2. 差分と、それが前提にする所、それを前提にする所を読み、関わる観点を選んで、その拠り所に照らして読む
   （[観点](../reference/reviews.md#perspectives)）。PR 全体の差分のレビューでは、すべての観点で読む。当てはめるパターンは[パターンを当てはめる](design.md "在りか")で選ぶ。
3. 指摘を決まった形で書き、[結果の形](../reference/reviews.md#record)にまとめる（[指摘](../reference/reviews.md#findings)）。
4. 自分の変更のレビューなら、結果を PR のレビューとして残し、指摘に答える。ほかの人の PR のレビューなら、
   PR 全体の差分のレビューにして、結果を PR のレビューとして残す（[差分のレビュー](../reference/reviews.md#diff)）。

指摘に答えるときは、次の順に進める（[差分のレビュー](../reference/reviews.md#diff)）。

1. 指摘ごとに、答え（直す、直さない、Issue にする、質問に答える）を決める。提案と細部は、直さずに理由を書いて
   終えてよい。
2. 直すものをすべて直してから、まとめて push する。
3. 細部の指摘への、意味の変わらない直しだけなら、その範囲を次のレビューに回さず、レビューしない直しとして PR の
   レビューに残す。ほかの直しがあれば、次のレビューに回す。
4. すべての指摘に、番号ごとに答えを書く（[結果の形](../reference/reviews.md#record)）。

## 全体のレビュー

[全体のレビュー](../reference/reviews.md#audit)の 7 段に沿って進める。各段で使う道具は次のとおり。

1. **範囲と観点を決める**：地図は `python3 tools/check-docs.py --map` で一覧できる。各項目の置き場所（範囲にする
   ファイル）は、その項目を宣言する地図の表にある。前回の報告は
   `gh issue list --state all --search '"の全体のレビュー" in:title'` で探し、報告であることと範囲を本文で確かめる
   （タイトルの言葉を含む、報告ではない Issue も出る）。重点にする前回からの決まりの変更は、principles と conventions の履歴が
   前回の報告の head と同じリポジトリにあれば、その head からの `git log` で見る。なければ重点は足さない。
2. **検査を回す**：そのリポジトリの、CI と同じ検査を回す。
3. **範囲ごとに読む**：範囲ごとに読む人（エージェントならサブエージェント）を分ける。それぞれに、範囲、観点、指摘の形
   （[指摘](../reference/reviews.md#findings)）を渡し、ファイルを変えないよう頼む。
4. **指摘を確かめる**：戻ってきた指摘を、自分で元の文書とコードを開いて確かめる。
5. **まとめる**：決まりの 5 段のとおり（使う道具はない）。
6. **報告して直す**：報告は `gh issue create` で作る。答えを受けてから直す。
7. **仕組みに戻す**：検査を足せる指摘は、`tools/check-docs.py` などに検査を足す PR にする。
