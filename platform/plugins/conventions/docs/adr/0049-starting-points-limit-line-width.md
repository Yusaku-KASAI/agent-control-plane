# 0049. いつも読み込まれる文書は、行数に加えて行の表示幅も上限で確かめる

## Context

いつも読み込まれる文書（リポジトリの `CLAUDE.md`、共通のルール、役割ごとの指示）は、形式の量の上限で行数を確かめて
いる。全体のレビュー #283 の D は、developer と reviewer の指示が行数の上限ちょうどで、表示幅 130 を超える行（developer
に 8、reviewer に 5）を伸ばして収めていることを挙げた。行数の検査は、行を伸ばせば通せてしまう。判断 13 で、依頼者は
おすすめの (b)（表示幅の上限も検査に足す）で進めると決めた（#284）。

## Decision

- いつも読み込まれる文書の、frontmatter のほかの行の表示幅を 130 までにする。全角を 2、ほかを 1 として数え、リンクの
  行き先は数えない（読み手が読むのは文で、行き先の長さは書き方で縮められない）。
- 形式の量の上限に置き、check-docs の量の検査で確かめる。上限に当たったときは、行を伸ばしたり言い回しを詰めたりせず、
  載せるものを減らすか移す。

## Alternatives

- **今の行数のまま、長い行はレビューで見る（判断 13 の (a)）**：判断の要らない決まりを読むことに任せ、実際に破られて
  いた。
- **文字数で測る（判断 13 の (c)）**：上限の意味（読み込まれる量）には近いが、今の行数の決まりと文書を書く人の目安が
  変わる。行数の上限を保ったまま、伸ばすことだけを止める方が小さい。
- **リンクの行き先も数える**：相対パスの深さで行の幅が変わり、文の量と関わりなく落ちる。

## Consequences

- 共通のルールの、リンクの行き先を除いても長かった二行を折り返した。
- 上限は frontmatter の `description` には当てない（Claude Code が一行で読む）。
