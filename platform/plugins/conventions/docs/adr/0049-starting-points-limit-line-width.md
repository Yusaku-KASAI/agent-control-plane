# 0049. いつも読み込まれる文書は、行数に加えて行の表示幅も上限で確かめる

## Context

いつも読み込まれる文書（リポジトリの `CLAUDE.md`、共通のルール、役割ごとの指示）は、形式の量の上限で行数を確かめて
いる。全体のレビュー #283 の D は、developer と reviewer の指示が行数の上限ちょうどで、表示幅 130 を超える行（developer
に 8、reviewer に 5）を伸ばして収めていることを挙げた。行数の検査は、行を伸ばせば通せてしまう。判断 13 で、依頼者は
おすすめの (b)（表示幅の上限も検査に足す）で進めると決めた（#284）。

## Decision

- いつも読み込まれる文書の、frontmatter のほかの行の表示幅を 130 までにする。Unicode の East Asian Width が W か F の
  文字を 2、ほかを 1 として数え（曖昧幅は 1）、リンクの括弧の中（行き先とタイトル）は数えない（行き先の長さと在りかの
  印は、書き方で縮められない）。ADR 0010 の量の上限に、行数と並べて足す。
- 形式の量の上限に置き、check-docs の量の検査で確かめる。表示幅を超えた行は折り返し、そのうえで行数の上限に当たったときは、
  行を伸ばしたり言い回しを詰めたりせず、載せるものを減らすか移す。

## Alternatives

- **今の行数のまま、長い行はレビューで見る（判断 13 の (a)）**：判断の要らない決まりを読むことに任せ、実際に破られて
  いた。
- **文字数で測る（判断 13 の (c)）**：上限の意味（読み込まれる量）には近いが、今の行数の決まりと文書を書く人の目安が
  変わる。行数の上限を保ったまま、伸ばすことだけを止める方が小さい。
- **リンクの行き先も数える**：相対パスの深さで行の幅が変わり、文の量と関わりなく落ちる。
- **各行を 130 の幅で折り返した行数を、今の行数の上限で数える**：伸ばして収めることはできなくなるが、依頼者が決めた
  (b)（表示幅の上限を足す）と違い、原文の一行が読める幅に収まることも保てない。
- **どの作業でも始めに全体まで読む文書（文書の体系）にも量の上限を当てる**：ADR 0039 が、起点の量の検査を見直す
  変更で扱うとした形。この変更は依頼の範囲（判断 13：行の表示幅）にとどめ、当てるかは依頼の Issue（#284）に積んで
  別に決める。上限の値を決めるには、文書の体系の今の量と、分けたあとの姿を見て決める必要がある。

## Consequences

- 共通のルールの、リンクの括弧の中を除いても長かった二行を折り返した。
- 上限は frontmatter の `description` には当てない（Claude Code が一行で読む）。`description` もロールとスキルの一覧として
  毎回読み込まれるので、別の上限を当てるかは依頼の Issue（#284）に積んで別に決める。
- conventions を使うほかのターゲットの、いつも読み込まれる文書も、この検査に掛かる。
