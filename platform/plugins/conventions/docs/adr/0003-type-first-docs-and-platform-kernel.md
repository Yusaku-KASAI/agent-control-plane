# 0003. 文書は種類のディレクトリに置き、platform を全区切りが前提にしてよい共有の核にする

## Context

ADR 0002 で文書を届く先で区切り、区切りの中を種類で分けることにした。種類ごとにディレクトリを分けるかは文書の数で
決めるとし、区切りをまたぐのは契約と用語集だけとした。置き直してみると、次のことが分かった。

- 原則、文書の体系と形式、作業の進め方（PR と Issue）は、どのリポジトリでも同じで、すべてのエージェントが使う。
  契約でも用語でもないが、区切りをまたいで要る。
- 種類で分けないと、一つの文書に解説、手順、参照が混ざったまま残る（ターゲットと platform の README がそうだった）。
- 考え方（原則）とこのプロジェクトでの形を一つの表で 1 対 1 に結ぶと、一つの原則が多くの場所や粒度に効くことが
  表せない。

## Decision

- どのリポジトリも、`docs/` の下を種類のディレクトリ（`architecture/`、`guides/`、`reference/`、`adr/`）と、
  `README.md`（唯一の一覧）、`overview.md`（全体の解説）で構成する。関心の違う部分は `<関心>/` で分ける。
- 設計の記述を、原則（platform の `reference/principles.md`）、アーキテクチャ（`overview.md` と各文書の冒頭）、
  構成要素の説明（`architecture/` の各文書。決まった形）の 3 層に分け、構成要素の説明から原則へ多対多でリンクする。
  原則の側には、どこで使うかを書かない。
- platform は、すべての区切りが前提にしてよい共有の核にする。原則、文書の体系と形式、作業の進め方、用語集を置く。
  platform はほかの区切りを前提にしない。platform 以外の区切りの間は、契約だけでつなぐ。
- target-template の文書は、切り出すときにそのまま持ち出せるよう、最上位の `template/docs/` に置く。
- 作業の進め方を platform に移すので、その判断（target ADR 0006）も platform の ADR 0006 に移す。
- 日本語の見出しを指すリンクは、`<a id>` で英字の id を付けて指し、検査する。
- ADR の本文は書き換えないが、文書を移したときのリンクの付け替えはしてよい。

## Alternatives

- **数が少ないうちは種類で分けない（ADR 0002 のまま）**：混ざった文書が残り、どこに書くかが人によって変わる。
- **原則とこのプロジェクトでの形を一つの表にする**：一つの原則が多くの場所に効くことを表せない。
- **共有の文書をそれぞれの区切りにコピーする**：区切りの間でずれていく。
- **target-template の文書を `docs/target/` に置いたままにする**：control-plane の文書の中に別の区切りが入れ子になり、
  区切りが見えない。
- **ADR を移さず、文書だけ platform に置く**：判断と今の姿が別の区切りに分かれる。

## Consequences

- control-plane とターゲットの文書は、platform の文書へリンクしてよい。platform の文書から、ほかの区切りへはリンクしない。
- 移したことで、ADR や他の文書の中の「target ADR 0006」などの呼び方の一部が古くなる。リンクは検査で守る。
- `architecture/` の文書を構成要素の形式に書き直すのは、置き直しのあとに順に行う。
