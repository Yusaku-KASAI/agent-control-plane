# 0029. どこを変えるかに GitHub の既定のラベルを使わず、ロードマップの今の焦点には開いている Issue を #番号 で並べる

## Context

ADR 0001 は、今の焦点と順番をピン留めした「ロードマップ」の Issue に置くと決めたが、本文の形は決めていなかった。
2026-10-22 に数えると、ロードマップの今の焦点は閉じた Issue を 15 件挙げたままで、多くは経緯として触れたもの
だった（「#110 と #134 で変えた共通の決まり」など）。どこを変えるかのラベルは、リポジトリの参照の文書で名前と意味を
決めるが、GitHub が最初から用意するラベル（`bug`、`documentation` など）を使うかは決めていなかった。

Issue の決まりのうち判断の要らないものを、GitHub を扱う区切りの検査で確かめることにした（platform の ADR 0023）。
検査は、決まりにある形だけを知る（ADR 0027、0028）。

## Decision

- どこを変えるかのラベルに、GitHub が最初から用意するラベルは使わない。名前と意味をリポジトリの参照の文書で決めた
  ラベルだけを使う。既定のラベルは意味がリポジトリの区切りと合わず、どこを変えるかを示さない。
- ロードマップの本文は、`## 今の焦点` の節に、取りかかる順に開いている Issue を `#<番号>` で並べる。閉じた Issue には
  触れない（経緯はその Issue に書く）。閉じた Issue を経緯として触れてよいとすると、古くなった項目と見分けるのに
  判断が要り、今の焦点が古いことを機械で見つけられない。

## Alternatives

- **今の焦点で閉じた Issue に経緯として触れてよいとし、検査が項目の先頭の番号だけを数える**：書き方を検査に合わせる
  ことになり（ADR 0028）、項目の中の閉じた Issue が古いのか経緯なのかは見分けられない。
- **既定のラベルも、リポジトリが参照の文書で決めれば使ってよい**：検査がリポジトリの参照の文書を読むことになり、
  ラベルの名前を知らない汎用の検査にできない。既定のラベルは消すか、使わずに置けば足りる。

## Consequences

- 今のロードマップは今の焦点で閉じた Issue に触れていて、この決まりに合わない。課題を整える手順で書き直す。
- 決まりを確かめる仕組みは、GitHub を扱う区切りに置く（platform の ADR 0023 の `check-issues`）。conventions からは
  その名前を出さない。
