# 0050. check-docs は、コードブロックとコードスパンを、依存を持たず CommonMark に倣う行ごとの走査で見分ける

## Context

check-docs は、リンク、見出しのアンカー、地図、手順の段、ロールの節を読むときに、コードブロックとコードスパンの中を
除く。行の表示幅は、コードの中ではリンクの括弧も数える。前は、フェンス（囲みのコード）を一つの正規表現（字下げ 3
までの ``` か ~~~ から、同じ文字の次の行まで）で、コードスパンを ` 一つの組で見分けていた。全体のレビュー #283 と
PR #301 のレビューは、閉じないフェンス、深い字下げ、4 個の ` のフェンス、情報文字列付きの行で CommonMark と食い違い、
コードの中のリンクを検査したり、フェンスのあとを検査しなかったりすることを挙げた（#305）。見分けの誤りは、文書の
誤りを黙って通すか、誤りのない文書を落とす。

## Decision

- 標準のライブラリだけで、行ごとに読む走査で見分ける。CommonMark の次の規則に倣う。
  - フェンスは、同じ文字の同じ長さ以上の並びだけの行で閉じる。` のフェンスの情報文字列に ` があれば開かない。
  - フェンスを開き閉じる字下げは、そこにあるリストの項目の文の始まりから 3 まで（項目の印のすぐ後も含む）。項目の
    文の始まりは、開いている項目ごとに印の行から取り、それより浅い行で項目が終わる。
  - 文の始まりから 4 先の字下げは、空行、閉じたフェンス、字下げのコードの行のあとなら、字下げのコードとする。
  - HTML のコメント（`<!--` から `-->` まで）の中の ``` の行は、フェンスを開かない。
  - コードスパンは、` の並びで開き、同じ長さの並びで閉じる（一行の中に限る）。
- 閉じの行がどこにもないフェンスだけ、リストの項目の中のものは項目が終わると閉じ、ほかは末尾まで続く。閉じの行が
  あとにあるフェンスは、項目より浅い行（ヒアドキュメントの終わりなど）もコードとして閉じの行まで続く。slack
  プラグインの check-markdown と同じ読み方（platform の ADR 0029）。
- 遅延の続きの行、引用の中、コメントのほかの HTML ブロック、タブの字下げ、バックスラッシュの escape、行をまたぐ
  コードスパンは見分けない。見分ける形と見分けない形は、check-docs の試験（`tests/check-docs-test.sh`）の場合で
  押さえる。

## Alternatives

- **Markdown の解析ライブラリ（markdown-it-py など）を使う**：CommonMark に正しく沿うが、check-docs は依存を持たない
  一つのファイルで、ターゲットの CI とハーネスのイメージに入れるものが増える。
- **参照の実装（commonmark.js など）を試験の答えにだけ使い、場合ごとに突き合わせる**：本体は依存を持たないまま
  ずれを見つけられるが、`make check` が node とパッケージの取得に頼る。場合ごとの答えを試験に書く形にした。
- **slack プラグインの check-markdown の走査を使う、またはそれを conventions に移して共有する**：conventions は
  principles だけを前提にする区切りで、slack を前提にできない。逆に conventions に置いて slack が使う形は、プラグインが
  実行時にほかのプラグインのコマンドに頼ることになる。読み方は、閉じの行のあるフェンスの扱いでそろえた。
- **CommonMark どおり、項目より浅い行で、閉じの行のあるフェンスも閉じる**：書き手の閉じの行が新しいフェンスを開き、
  あとの本文をすべてコードとして読んで、文書の誤りを黙って通す（ADR 0029 が退けた理由と同じ）。
- **正規表現を直さず、ずれる形を試験で押さえるだけにする**：ずれたままだと、コードの中のリンクを検査し、フェンスの
  あとを検査しない形が残る。
- **読めない形（閉じないフェンスなど）を文書の誤りとして落とす**：走査は小さく済むが、文書の形の決まりを足すことに
  なる。#305 の範囲の外。

## Consequences

- リストの項目の印のすぐ後で開き、項目の外の閉じの行で閉じるフェンスは、CommonMark では項目の終わりで閉じるが、
  check-docs は閉じの行までをコードとして読む。
- 手書きの走査は、PR のレビューで CommonMark とのずれが続けて見つかった（#305）。ずれが見つかるたびに、試験の場合を
  足して直す。続くなら、解析ライブラリへの置き換えを、依存を持たせるかと一緒に考え直す。
- このリポジトリの Markdown では、前の見分け方とリンク、アンカー、行の表示幅の結果が同じだった。ほかのターゲットでは、
  コードの中だったリンクが検査から外れるか、フェンスのあとのリンクが検査に入るかで、結果が変わりうる。
