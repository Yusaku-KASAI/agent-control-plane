# 0046. 目的の手順の終わりは目的の手順に置き、共通の手順は目的の手順を名指ししない

## Context

全体のレビュー #283 の A と B は、手順について次を挙げた。

- 共通の手順のレビューを頼んで答えるの「終える」の 2〜5 段（閉じる Issue を確かめる、下書きを外す、返す、続ける）は、
  変更を届けるの終わりそのものだった。そのため変更を届けるでは、7 段「確かめていないことを書く」が終えた後に来ていた。
- 変更を届けるの 2 段が、依頼を読むことと範囲を決めることを一つに持っていた。
- レビューを頼んで答えるが、目的の手順のレビューするの在りかと、その段番号を名指ししていた。共通の手順は目的の手順を
  前提にしない決まり（ADR 0021）に反していた。

## Decision

- 変更を届けるに「終える」の段（範囲の項目に PR の番号を添える、`Closes` と `Refs` を合わせる、下書きを外す、上限で返す、
  続ける）を足し、「確かめていないことを書く」をその前に置く。「依頼を読む」と「範囲を決める」を分ける。
- レビューを頼んで答えるは、終える前を満たすまでにする。
- 共通の手順は、目的の手順を名指しせず、「レビューする人が沿う手順の在りか」のように使う側が渡すものとして書く。

## Alternatives

- **レビューを頼んで答えるに終わりを残し、変更を届けるから指す**：終わりの段（Issue、下書き）はレビューではなく変更を
  届けることの終わりで、レビューを頼まない変更の届け方ができたときに、終わりが共通の手順に取り残される。

## Consequences

- 変更を届けるの段の番号が変わる（依頼を読むが 2 段、範囲を決めるが 3 段、レビューが 7 段、確かめていないことが 8 段、
  終えるが 9 段）。段の番号を出典に書いた要約（役割ごとの指示など）を合わせる。
