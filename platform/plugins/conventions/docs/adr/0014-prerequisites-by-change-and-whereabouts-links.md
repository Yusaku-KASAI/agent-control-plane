# 0014. 前提は変更が伝わる関係で定め、在りかを示すだけのリンクの名前とタイトルを「在りか」にする

## Context

ADR 0007 で、在りかを示すだけのリンクにタイトル「案内」を付け、依存の向きの確かめから外した。ADR 0008 で、前提か
案内かは、リンク先を読まなくてもリンクを含む文がそれだけで分かり、正しいかで決めることにした。

起点（いつも読み込む要約、ロール、スキル）から何をどれだけ読ませるかを決めるにあたり、要約を持たず、どこを読むかだけを示す
書き方を「案内」と呼ぶことにした。依存の関係の「案内」と同じ言葉が二つの意味になる。また、前提の決め方は読み手が
理解できるかに寄っていて、この区別の目的である依存の向き（どちらが変わると、どちらの見直しが要るか）と合って
いなかった。

## Decision

- 前提は、リンク先の中身が変わったときに、リンクを含む文を見直す要がある関係とする。ソフトウェアの依存の一般的な
  定義（変更が伝わる向き）に合わせる。
- 在りかを示すだけで、リンク先の中身が変わっても在りかが変わらなければ直さなくてよい関係を「在りか」と呼び、そのリンクの
  タイトルを `"在りか"` にする。
- 印は今のまま、前提でない側（在りか）にだけ付け、タイトルのないリンクは前提として扱う。

## Alternatives

- **書く中身の側に別の言葉を使い、リンクの「案内」を残す**：読み手から見て、要約を持たずに読む場所を示すものは「案内」
  が最も自然で、リンクの印は在りかを示すだけという意味が言葉からそのまま読める方がよい。
- **前提の側に印を付け、印のないリンクを在りかとして扱う**：付け忘れた依存が向きの確かめから漏れる。
- **すべてのリンクに前提か在りかの印を付ける**：どのリンクにも印が要り読みにくいが、確かめで得るものは片方の印と
  変わらない。

## Consequences

- 新しい決め方は前より厳しい。リンク先の事実を言い直している文（用語集の「文書の種類」の行など）は、前の決め方では
  案内だったが、新しい決め方では前提になる。今の在りかのリンクは、この決め方で一つずつは見直していない。見直しは
  #118 で行う。
- `check-docs` は、リポジトリの中へのリンクのタイトルを `"在りか"` だけに限る。古いタイトル `"案内"` が残っていると、
  黙って前提として数えずに落とす。
- ADR はタイトルが「案内」のリンクを持っていない。ADR からのリンクは依存の向きの確かめから外れるので、残っていても
  確かめには影響しない。
