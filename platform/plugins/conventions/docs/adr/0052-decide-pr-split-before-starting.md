# 0052. 範囲の中の項目を何本の PR で扱うかは、取りかかる前に範囲を決める段で決める

## Context

変更を届けるの 6 段は「最初の PR は小さく保つ。広がったら一つの目的ごとに分ける」とし、課題の扱い方の「依頼の範囲」は
範囲の中を何本かの PR に分けるときの扱いを持つ。ただ、分けるかを決める段はなく、作っている途中で広がったと気づいた
ときにだけ分けることになっていた。

依頼 #305 は範囲の中に 7 項目を持ち、一つの PR（#319）で扱った。そのうち一つ（コードの見分け方の作り直し）が大きく、
レビューの指摘が出続けたため、ほかの 6 項目も同じ PR でマージを待った。依頼者は、Issue を頼まれたときに、全項目を
一つでやるか分けるかをエージェントが判断して進めるのがよいと考えた（#328）。

## Decision

- 変更を届けるの 3 段（範囲を決める）で、範囲を書いたあとに、範囲の中の項目を何本の PR で扱うかを決める。項目の目的が
  別々か、一つの項目が大きくてほかの項目を待たせうるなら、一つの目的ごとに分ける。
- 分けたときの依頼の Issue と PR の扱いは、課題の扱い方の「依頼の範囲」のまま変えない。6 段は、広がったら 3 段の分け方を
  見直す段として残す。

## Alternatives

- **範囲の中の項目を、いつも項目ごとに一つの PR にする**：小さな文書の直しが並ぶ依頼でも PR とレビューが項目の数だけ
  増える。項目の大きさと目的のまとまりで決める方が、レビューの回数を抑えられる。
- **6 段の「広がったら分ける」だけで足りるとして変えない**：#305 では広がりに気づいたときには、ほかの項目がすでに同じ
  PR に入っていた。取りかかる前に決める方が、分けるための手戻りがない。

## Consequences

- 3 段で、範囲の中の項目の大きさを見積もる手間が増える。見積もりが外れたら、6 段で分け方を見直す。
