# 0026. 文書のメタデータは手で書かず、一次の情報から check-docs で導いて一覧にする

## Context

Issue #87：すべての文書のメタデータ（タイトル、種類、更新日、状態、持ち主、テーマ、関連と前提）を一覧したい。人と
エージェントが文書を探すときと、全体のレビュー（監査）で古い文書を見つけるときに使う。

挙げた属性の多くは、すでにほかの場所に一次の情報がある。タイトルは見出し、種類は置き場所（文書の体系の種類と届け方の
形）、更新日は git の履歴、状態は ADR の frontmatter、持ち主とテーマは地図の項目、前提はリンク（在りかのリンクと
それ以外）。principles のパターン「機械で読める属性」は、使いどころを状態と参照を持つ記録に絞り、よくある失敗に同じ
属性を二か所に書くことを挙げている。Issue の表では、テーマとタグの一次の情報を「地図の項目、Issue のラベル」としている。

## Decision

- 手で書く frontmatter は、今のとおり ADR（と、Claude Code が読むロールとスキルの定義）に限る。ほかの文書には足さない。
- `check-docs --catalog` が、文書ごとに次の属性を導いて、タブ区切りの一覧（見出しの行と、文書ごとに一行）に出す。
  - 区分：その文書が何か。入口（ルートの README.md と CLAUDE.md）、索引（`docs/README.md`）、overview（`overview.md`）、
    置き場所のディレクトリからの文書の種類（解説、手順、参照、判断）、届け方の形（役割ごとの指示の `agents/`、共通の
    ルールの `rules/`、スキルの `skills/`）。どれでもなければ「その他」。用語集の「文書の種類」と「全体」は、それぞれ
    この列の一部の値と、地図での位置（子を持つ項目の直下か）を指し、この列とは別の言葉なので、列の名前を「区分」にする。
  - タイトル：最初の `# ` の見出し（コードブロックの外）。なければ frontmatter の `name`（ロールの定義）。
  - 版と更新日：その文書を最後に変えたコミットの短い hash と日付。コミットしていなければ `-`。そのあと作業ツリーで
    書き換えていれば、版に `+` を付ける（タイトルや前提は作業ツリーから読むので、版と食い違うことを示す）。
  - 状態：ADR の `status`。
  - 項目：地図でその文書を含む項目（持ち主）。
  - 前提と在りか：リポジトリの中へのリンクの先を、前提にするもの（関連のうち前提）と、在りかを示すだけのもの（関連の
    うち在りか）に分けて出す。在りかのリンク、ADR へのリンク、索引と ADR からのリンクは在りかに入れる。どれを前提に
    数えるかは、地図の検査と同じ一つの関数で決める。役割ごとの指示は、定義の在りかをリンクでなくパスで書く（形式の
    役割ごとの指示）ので、リンクからは導けない。その行の前提と在りかは、何も前提にしないと読まれないよう `-` でなく
    `?` にする。
- テーマとタグは、地図の項目（列「項目」）で表し、Issue のラベルは文書の属性ではないので一覧に入れない。
- 手で書く frontmatter の決まりは、形式の ADR の節に一文で置き、`check-docs` で確かめる（`adr/`、`agents/`、`skills/`、
  `commands/` の外の文書が frontmatter で始まれば落とす。`commands/` は Claude Code のプラグインのコマンドの定義）。
- 一次の情報がない属性（レビューした日、決めた人など）が要るとわかったら、そのときに frontmatter に足すかを決める。

## Alternatives

- **すべての文書に frontmatter を書く**：同じ事実が二か所になり（SSOT）、片方だけ古くなる。手で書いた属性と一次の情報が
  食い違わないかを確かめる検査も要る。
- **一覧を文書として生成してコミットする**：変更のたびに作り直しが要り、作り直し忘れで古くなる。要るときに出せば足りる。
- **Markdown の表や JSON で出す**：人には読みやすいが、`awk` や `sort` で絞り込みにくい。タブ区切りなら、表にしたいときにも
  変えられる。
- **別のコマンドにする**：文書の集め方、リンクの読み方、地図の読み方を `check-docs` と共有する。`--map` と同じく、同じ
  コマンドの出力の一つにする。

## Consequences

- 監査で、長く変わっていない文書や、変わった文書を前提にする文書を、一覧から探せる（レビューするの全体のレビューの 1 段）。
- 一覧の形を変えても、文書に手で書いた属性を直す必要はない。
