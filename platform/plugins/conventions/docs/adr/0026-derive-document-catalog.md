# 0026. 文書のメタデータは手で書かず、一次の情報から check-docs で導いて一覧にする

## Context

Issue #87：すべての文書のメタデータ（タイトル、種類、更新日、状態、持ち主、テーマ、関連と前提）を一覧したい。人と
エージェントが文書を探すときと、全体のレビュー（監査）で古い文書を見つけるときに使う。

挙げた属性の多くは、すでにほかの場所に一次の情報がある。タイトルは見出し、種類は置き場所（文書の体系の種類と届け方の
形）、更新日は git の履歴、状態は ADR の frontmatter、持ち主とテーマは地図の項目、前提はリンク（在りかのリンクと
それ以外）。principles のパターン「機械で読める属性」は、使いどころを状態と参照を持つ記録に絞り、よくある失敗に同じ
属性を二か所に書くことを挙げている。

## Decision

- 手で書く frontmatter は、今のとおり ADR（と、Claude Code が読むロールとスキルの定義）に限る。ほかの文書には足さない。
- `check-docs --catalog` が、文書ごとに次の属性を導いて、タブ区切りの一覧（見出しの行と、文書ごとに一行）に出す。
  - 種類：入口（ルートの README.md と CLAUDE.md）、索引（`docs/README.md`）、全体（`overview.md`）、置き場所の
    ディレクトリから解説、手順、参照、判断と、届け方の役割ごとの指示（`agents/`）、共通のルール（`rules/`）、スキル
    （`skills/`）。どれでもなければ「その他」。
  - タイトル：最初の `# ` の見出し。なければ frontmatter の `name`（ロールの定義）。
  - 更新日：その文書を最後に変えたコミットの日付。コミットしていなければ `-`。
  - 状態：ADR の `status`。
  - 項目：地図でその文書を含む項目（持ち主）。
  - 前提：リポジトリの中へのリンクのうち、在りかのリンクと ADR へのリンクを除いたもの。地図の検査（`check_map`）と同じく、
    索引と ADR からのリンクは前提に数えない。
- テーマ（Issue のラベル）は、文書ではなく Issue の属性なので、一覧に入れない。
- 一次の情報がない属性（レビューした日、決めた人など）が要るとわかったら、そのときに frontmatter に足すかを決める。

## Alternatives

- **すべての文書に frontmatter を書く**：同じ事実が二か所になり（SSOT）、片方だけ古くなる。手で書いた属性と一次の情報が
  食い違わないかを確かめる検査も要る。
- **一覧を文書として生成してコミットする**：変更のたびに作り直しが要り、作り直し忘れで古くなる。要るときに出せば足りる。
- **Markdown の表で出す**：人には読みやすいが、`awk` や `sort` で絞り込みにくい。タブ区切りなら、表にしたいときにも
  変えられる。
- **別のコマンドにする**：文書の集め方、リンクの読み方、地図の読み方を `check-docs` と共有する。`--map` と同じく、同じ
  コマンドの出力の一つにする。

## Consequences

- 監査で、長く変わっていない文書や、変わった文書を前提にする文書を、一覧から探せる（レビューするの全体のレビューの 1 段）。
- 一覧の形を変えても、文書に手で書いた属性を直す必要はない。
