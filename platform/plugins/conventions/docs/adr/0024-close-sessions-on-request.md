# 0024. セッションの締めを目的の手順にし、人が頼んだときにエージェントが持ち越すものを Issue と PR に残す

## Context

Issue #62：セッションを終えるときと、別のスレッドへ引き継ぐときの手順がない。セッションの締めは、目的の手順の
ない依頼として扱われ（ADR 0021）、そのつど依頼文で何をするかを伝えていた。control-plane の片付け（control-plane の
app ADR 0026）は、使われないまま保持期間を過ぎたセッションを、残す理由がなければ消すだけで、会話の中にしかない
もの（終えていない作業、打ち切った提案、確かめていないこと、決めたこと、ハーネスへの気づき）は拾わない。

依頼者の考えは次のとおり。

- Claude Code の SessionEnd の hook で締めるのは、思い描く形と違う。コンテナはセッションの間に何度も止まって消える
  （休む、再起動）ので、コンテナの終わりはセッションの終わりではない。
- 人の指示をきっかけに、エージェントが手順に照らして判断し、締める。
- 締めでしたいのは、会話にしかなく残しておくべきものの洗い出しと引き継ぎ（終えていない作業、打ち切った提案、次に
  回したもの、確かめていないこと、起こすべき Issue、ハーネスへの気づき、課題の今の姿の整理）と、control-plane が
  片付けられる状態にすること。
- control-plane の側でも片付けをさせたいときは、リアクションを印にしてもよい（要るなら）。

## Decision

- 目的の手順「セッションを締める」（`guides/close-session.md`）を足す。人が締めるよう頼んだときに振り分けで入る。
  段は、始めに読む（課題の扱い方）、洗い出す、残す、課題の今の姿を合わせる、片付けられる状態にする、締めのまとめを
  答える。
- 持ち越すものの種類と置き場所は、課題の扱い方の「持ち越すもの」の表に置く。置き場所は、すでにある Issue と PR
  （本文、コメント）と新しい Issue だけにし、引き継ぎのための文書やファイルは作らない。別のセッションへの引き継ぎは、
  締めのまとめを書いたスレッドの在りかと、持ち越した Issue を渡すことで行う。
- 締めでは文書やコードを直さず、Issue にする。その場で直すなら、変更を届けるに入り直す。作業領域にしかないものを
  PR に載せるときも同じで、終えた PR にレビューしていないコミットを足さない。載せないものは中身を Issue に書いてから
  捨てる。このセッションの名前のブランチで、開いている PR がなく、どこにも入っていないコミットのために片付けを止める
  もの（条件はハーネスの契約に任せ、手順では書き並べない）も同じように、リモートと手元の両方を消す（リモートだけを
  消すと、手元のコミットがどこにもないコミットになり、片付けを止める）。今いるブランチも、リモートは消し、手元は消さずに
  既定のブランチの先頭に（upstream を持たない形で）置き直して、締めたあとも同じブランチで続けられるようにする。ほかの名前のブランチは消さない（作ったかどうかは
  名前でしか見分けられない）。
- レビューで直さなかった指摘（打ち切り、範囲の外）は、レビューの扱い方の答える場所にすでに置き場所があるので、
  答えが抜けていないかを確かめるだけにし、Issue に重ねて置かない。
- このセッションが扱った Issue を、終えたなら閉じ、本文が古くなったなら書き直す。閉じたか起きた Issue があれば、
  ロードマップの今の焦点を確かめて、古ければ書き直す（Issue #102 のきっかけのうち、締めのときの分）。課題の整理の
  ほかの部分（pm ロールの #28、決まりを仕組みで確かめる #111）は、締めの範囲に入れない。
- 片付けを止める条件と、セッションが push したブランチの見分け方は、動き方ごとの事実なので、ハーネスの契約に置き、
  手順からは在りかで指す。
- 届け方：共通のルールの振り分けに並べ、close-session スキルで手順を届ける。developer と reviewer は受け持ち
  （reviewer は書ける範囲の外に置くものを締めのまとめに書く）、guide は受け持たず、洗い出したものを回答に書く。
- 締めのあとも、同じセッションに依頼してよい。締めは、セッションを消すことでも、作業を禁じることでもない。

## Alternatives

- **SessionEnd の hook で締める**：コンテナはセッションの間に何度も止まるので、hook はセッションの終わりでなく
  コンテナの終わりに走る。今の止め方（標準入力を閉じ、時間内に終わらなければ SIGKILL）では走らないこともある。
  何を残すかは会話を読んで判断するもので、hook の決まった処理には向かない。
- **引き継ぎのまとめを、リポジトリのファイルや決まった Issue に書く**：同じ事実が Issue、PR、まとめの二か所に
  分かれ、古くなる。続きは、置き場所の決まった Issue と PR と、まとめを書いたスレッドから読める。
- **締めの中で、見つけた文書やコードの直しまでする**：締めが変更を届けるの段（レビュー、検査）を抱え込み、いつ
  終わるかが読めなくなる。Issue にしておけば、別の依頼として扱える。
- **control-plane が、リアクション（`:wastebasket:` など）で片付けを保持期間より前に回すことを、同時に決める**：
  エージェントの締めと、control-plane の片付けは別の仕組みで、片付けの判定（app ADR 0026）はそのまま使える。
  保持期間を待たずに消す必要が出たときに、別に決める（Issue #208 に分けた）。
- **片付けの促し（保持期間ごとのスレッドへの知らせ）で、締めを勧める**：人が締めを頼まないまま放っておかれた
  セッションのきっかけになるが、促しの文面は control-plane の変更なので、#208 で合わせて決める。
- **片付けの判定を、作業領域の中から出す道具を同時に作る**：残される理由を文で読んで判断するより確かだが、
  control-plane のコードとコンテナに道具を足す変更で、手順とは別に決められる。上と合わせて Issue #208 に分けた。
- **締めをロールの固有の振る舞いにする**：手順は目的で切り、ロールでは切らない（ADR 0021）。締めはどのロールの
  セッションでも頼まれうる。
- **振り分けに並べず、スキルだけで届ける**：振り分けの節には、すべての目的の手順を並べる（ADR 0021）。

## Consequences

- 「締めて」と頼まれると、エージェントは決まった段で持ち越すものを残し、片付けを止めているもの（開いている PR など）を
  まとめに書く。片付け自体は、今までどおり保持期間を過ぎてから control-plane が行う。
- 持ち越すものが Issue と PR に残るので、別のセッションはスレッドの在りかと Issue から続けられる。
- 共通のルールの振り分けが 1 行増える。
- guide のセッションを締めても、持ち越すものは回答に書かれるだけで、Issue にはならない。
- 締めの手順は、会話を見返す分だけトークンを使う。
