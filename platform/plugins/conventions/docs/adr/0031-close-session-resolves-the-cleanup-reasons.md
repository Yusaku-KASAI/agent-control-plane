# 0031. 締めでは、片付けを止めている理由を確かめて扱いごとに解き、リモートのブランチは消さない

## Context

ADR 0024 の締めの手順は、片付けを止める条件をハーネスの契約から読んで、エージェントが自分で判断していた。2 段
（開いている PR）と 6 段（片付けられる状態にする）で、このセッションのブランチの名前、作者の確かめ（`GIT_AUTHOR_NAME`）、
`--force-with-lease` でのリモートのブランチの削除、今いるブランチの切り直しを、文で並べていた。

片付けの役割の分け方（Issue #220）で、次のとおり決めた（B2）。

- 判定は control-plane だけが持ち、エージェントは同じ判定を道具で見る（control-plane の app ADR 0045 の
  `acp cleanup-check`）。
- エージェントは、判定が残す理由を解いて、control-plane が消せる状態にするところまでを持つ。理由に当たらないもの
  （変更のない worktree、先頭がどこかに入ったブランチなど）は、作業領域の中のものでも扱わない。
- 締めでリモートのブランチを消すのは control-plane だけにする。どこにも入っていないリモートのブランチは、中身を Issue に
  残して、残る理由として締めのまとめに書く。人は、理由を承知して消させられる（app ADR 0046）。
- platform のプラグインと conventions は control-plane を前提にせず、ハーネスの契約だけでつながる。締めの手順には、
  control-plane 経由のときの名前（環境変数、コマンド、リアクション）を書かない。

## Decision

- 締めの 2 段を「片付けを止めているものを確かめる」にする。確かめ方と、理由の種類ごとの扱いは、動き方ごとに
  ハーネスの契約にあると案内する。扱いは、締めの手順が次の三つで定める。
  - 続く作業：開いている PR（head か base）のように、まだ依頼がありうるもの。2 段で人に返す（ADR 0024 のとおり）。
  - 作業領域にしかないもの：作業領域の中で捨てられるもの。6 段で、残す価値のある中身を Issue に書いてから捨てる。
  - 人が解くもの：作業領域の外にあって消すと失われるものと、ほかの書き手の作業に関わるもの。エージェントは消さず、
    中身を Issue に書いて、残る理由として締めのまとめに書く。
- 6 段は、2 段で確かめた理由を扱いごとに解き、もう一度確かめて、残る理由を締めのまとめに使う。理由に当たらない
  ものは扱わない。作者の確かめ、`--force-with-lease`、今いるブランチの切り直しは外す。リモートのブランチを
  消さないので、どれも要らなくなる。
- 確かめ方が判定できずに終わったら、理由がないとはみなさず、片付けのない動き方と同じく 2 段と 3 段を自分で確かめ
  （base の PR も見る）、6 段は飛ばし、確かめられなかったことを締めのまとめの人がすることに書く。判定を見る形に
  したので、道具の失敗が「片付けられる」に化けないようにし、作業領域の中身を読み直さずに終えないようにする。
- 締めの終わりは、片付けられる状態になることに限らない。人が解くものが残れば、それをまとめに書いて終える。
  用語集の締めと、手順の 6 段の名前（片付けを止めているものを解く）をそれに合わせる。
- 締めのまとめには、残る理由と、人が解くものの印と中身を残した Issue を書く。人が片付けさせるやり方は、動き方
  ごとに契約にあるので、それを添える。
- control-plane 経由のとき、種類（`open-pull` など）から扱いと捨て方を引く表は、ハーネスの契約のコンテナの寿命の
  種類の表に「締めでの扱い」の列として置く。種類は control-plane の判定のもので、契約が持つ。
- 片付けのない動き方（devcontainer で直接）では、2 段は、このセッションで作業して push したブランチを head とする
  開いている PR を自分で挙げる。消すと閉じる base の PR は、片付けがないので見ない。3 段は作業領域を自分で読み直し、
  6 段は飛ばす。作業領域は人のものなので捨てず、持ち越すものは 3 段と 4 段で Issue に残す。

## Alternatives

- **今の 6 段を残し、条件の写しだけを契約の種類の表への案内に変える（B1）**：エージェントがリモートのブランチを
  消し続けるので、作者の確かめと `--force-with-lease` の文の手順が残る。消す主体が二つになる。Issue #220 で
  依頼者が B2 を選んだ。
- **種類ごとの扱いを、締めの手順に表で直に持つ**：種類は control-plane の判定の名前で、conventions が control-plane を
  前提にすることになる。種類が増えたとき、契約と手順の二か所を直すことにもなる。
- **扱いの三つも契約に持たせ、手順は「契約に沿って解く」とだけ書く**：エージェントが消さないこと（B2）は動き方に
  よらない締めの決まりで、契約に置くと、別の動き方の契約で抜けうる。
- **ロールの側で、隔離して動くロール（guide、reviewer、pm）が自分の worktree に残した試しの編集を、終える前に戻す
  と決める**：判定が `changes` として拾い、締めで worktree ごと消せるので、締めの手順を変えるこの ADR には入れない。
  ロールの決まりを変えるかは、別に決める。

## Consequences

- 締めの手順が短くなり、エージェントが消すのは作業領域の中のものだけになる。
- どこにも入っていないリモートのブランチがあると、締めても片付けられる状態にならず、人が承知して消させる操作が
  要る。そうなるのは、PR を作らずに push したか、PR を閉じたあとに push したときだけ。
- ハーネスの契約の種類を変えたら、「締めでの扱い」の列も直す。締めの扱いの三つを変えたら、契約の列も直す。
- 締めたあとも、今いるブランチは切り直さずに残る。
