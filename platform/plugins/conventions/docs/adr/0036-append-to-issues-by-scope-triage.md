# 0036. すでにある Issue に書き足すものは、依頼の範囲と同じ線引きで、切り出すか、範囲の中の項目にして閉じていれば開き直すか、記録として書く

## Context

依頼の範囲の振り分け（ADR 0032）は、範囲の外の指摘を、依頼の Issue を閉じたあとも、それだけで依頼として成り立つなら
新しい Issue に、成り立たないなら依頼の Issue のコメントに積む、と決めていた。積んだものが残れば、PR を終えるときに範囲の
中の項目にし、`Refs` で依頼の Issue を開けておく（ADR 0034）。この線引きは、依頼の Issue が開いている間（PR を終えるまで）を
前提にしていた。

すでにある Issue に、その間の外で書き足す場面がある。セッションを締めるときの持ち越すもの（ADR 0024）と、マージのあとに
出た指摘や、確かめていなかったことの結果である。持ち越すものの表は、置き場所を「依頼の Issue のコメント」とし、閉じて
いるかを区別していなかった。締めるときは PR がマージされたか閉じているので、依頼の Issue は `Closes` で閉じていることが
多い。閉じた Issue は閉じたことが済んだ印として読まれ（ADR 0034）、課題を整える手順も開いている Issue だけを見るので、
閉じた Issue のコメントに置いた済んでいないものは埋もれる。開いている Issue でも、コメントから本文へ移すと決めていたのは
決まったことと、ほかに分けた範囲だけで、確かめていないことや保留にした提案は本文に届かなかった（ADR 0035 の Consequences）。

PR #264 の 4 回目のレビューの指摘 3 から control-plane の Issue #265 に分け、依頼者の指摘（2026-10-25、Slack）で、締めに限らず
閉じた Issue に済んでいないものを書き足すときの一般の扱い（切り出す、閉じたまま追記する、追記して開き直す）として決めた。

## Decision

- **書き足すときの扱いを、依頼の範囲と同じ線引きで決める**：課題の扱い方に「Issue に書き足すとき」の節を足す。PR のあいだに
  積むもの（依頼の範囲）のほかに、すでにある Issue に書き足すものは、開いているかによらず次のとおりにする。
  - 済んでいないもの（終えていない作業、直していない指摘、確かめていないこと、保留にした提案）で、その Issue を閉じても
    それだけで依頼として成り立つなら、新しい Issue に切り出し、元の Issue にリンクをコメントする。
  - 済んでいないもので、その Issue と関わりが強いなら、範囲の中にどこで出たかを添えてチェックのない項目として足し、
    コメントする。Issue が閉じていれば開き直す。範囲を持たない形の Issue（テーマ、ロードマップ、キャンバス、全体の
    レビューの報告）には足さず、新しい Issue に切り出す（それぞれの本文の形を崩さない。キャンバスでは、やることは
    Issue に分ける）。
  - 済んでいないものがない（確かめた結果、決まったことの記録）なら、開いていれば本文の `## 今の姿` に、閉じていれば
    コメントに書き、閉じたままにする。
- **済んでいないものは範囲の中の項目にする**：確かめていないことは確かめること、保留にした提案は決めることとして足す
  （ADR 0035 の決める Issue と確かめる Issue の書き方）。`## 確かめていないこと` と `## 保留` の節だけに置くと、
  チェックで済んだかを表せず、Issue を閉じる根拠（整っている状態の「開いているか」）にもならない。待つ理由があれば、`## 保留` には
  理由だけを書き、項目からそこを指す（同じ項目を二つの節に並べない）。
- **開き直すときは、先に済んだ項目にチェックを付ける**：範囲の中の番号を添えたのにチェックのない項目を、マージされた PR の
  ものはチェックを付け、マージされずに閉じた PR のものは番号を外してから、項目を足す。閉じたことを済んだ印として読む
  （ADR 0034）のは閉じている間だけで、開くとその印がなくなるため。
- **依頼の範囲の積むは今のまま**：PR のあいだに依頼の Issue のコメントに積み、PR を終えるときに範囲の中の項目にする
  （ADR 0032、0034）。閉じた Issue に新しい依頼で取りかかるときは、変更を届けるの 2 段で開き直してから範囲を書く
  （そうしないと、`Refs` の PR のあとに、チェックのない項目が閉じた Issue に残る）。依頼の Issue がすでに閉じているときに
  出たもの（マージのあとの指摘など）は、積まずに書き足すときの扱いにする。
- **持ち越すものの表と整っている状態を合わせる**：持ち越すもの（ADR 0024）のうち、終えていない作業と保留にした提案、
  確かめていないこと、答えのないレビューの指摘は、書き足すときの扱いで依頼の Issue に書き足すか切り出す。会話で決まった
  ことは、依頼の Issue が開いていれば本文の `## 今の姿`、閉じていればコメントにする。整っている状態の「本文」に、コメントに
  書き足された済んでいないもの（PR を終えるまでの積んだ指摘のほか）が本文に入っていることを足す（ADR 0035 が #265 に
  回したもの）。どこで出たかを添えて関わりが強いとしたものを範囲の中に移すのは、書き足した時点で決めたものとして、
  課題を整えるときに直す（人が決める「範囲や狙いを変えること」に当たらない）。
- **pm ロールの書ける範囲に開き直すを足す**：pm も締めを受け持ち、持ち越すものを Issue に残す。

## Alternatives

- **閉じた Issue に追記して、いつも閉じたままにする（今の持ち越すものの表のまま）**：手間はないが、済んでいないものが
  課題を整えるときに拾われず埋もれる。#265 が直す問題そのもの。
- **済んでいないものは、いつも新しい Issue に切り出す**：閉じた Issue を開き直さずに済み、閉じたことを済んだ印として
  読み続けられる。ただ、それだけでは成り立たないもののために Issue を作り、文脈を書き写すことになる。ADR 0032 で積むことを
  選んだ理由と同じ。
- **閉じた Issue のコメントも、課題を整えるときに読む**：決まりは変えずに拾えるが、閉じた Issue はふえ続け、読む量が
  かさむ。コメントのどれが済んでいないかは中身を読まないと分からず、拾われたあとも、どこで扱うかの判断は同じく要る。
- **確かめていないことと保留にした提案を、範囲ではなく `## 確かめていないこと` と `## 保留` の節に移す**：本文の形の節に
  合うが、済んだかをチェックで表せず、残っていても Issue を閉じてよいかが読めない。PR の本文の「確かめていないこと」は、
  PR のあいだの注意書きで、Issue の続く作業とは役目が違う。
- **PR を終えるとき、依頼の Issue と関わりが強い確かめていないことも範囲の中の項目にして `Refs` にする**：`Closes` で
  閉じた Issue を締めで開き直す往復は減るが、PR の本文の確かめていないことの多くは、使ううちに見ること（注意書き）で、
  やることではない。それらまで項目にすると、依頼の Issue がいつまでも閉じない。往復は、締めで本当に済んでいないと
  判断したものにだけ起きるので、今は「終える」を変えない。
- **開き直すときに、済んだ項目のチェックを付けない**：手間は減るが、開いた Issue で番号を添えた項目が済んでいないように
  読める。マージされたかは PR から機械的に決まるので、そのときに合わせる。

## Consequences

- conventions の決まりなので、それを使うすべてのターゲットに効く。どのターゲットも、プラグインの更新で受け取り、
  ターゲットの側で直すファイルはない。
- 締めのあとに、依頼の Issue が開き直されることがある。`Closes` でマージされた PR の確かめていないことや保留にした
  提案が、依頼の Issue と関わりが強いと判断されると、閉じた直後に開き直されるので、少なくない。開き直した Issue は、足した項目が済めば閉じる。閉じたか起きた Issue と
  して、締めの 5 段でロードマップの今の焦点を確かめる対象に入る（今の焦点に足すかは今までどおり人が決める）。
- すでに閉じた Issue のコメントに埋もれているものは、この決まりでは拾わない。洗い出すなら、課題を整える依頼として別に頼む。
- 書き足すときの扱いを確かめる検査はない（どれが済んでいないか、それだけで成り立つかは判断が要り、ADR 0028 の条件を
  満たさない）。
