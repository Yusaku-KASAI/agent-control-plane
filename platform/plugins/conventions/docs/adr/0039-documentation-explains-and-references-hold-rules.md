# 0039. 文書の体系は仕組みの解説に絞り、決まりを形式、届け方、検査の扱い方の参照に移し、地図で決まりを一つの項目にまとめる

## Context

ADR 0020 で、文書の体系（`architecture/documentation.md`）を、どの作業でも始めに全体まで読む文書にした。そのときの量は
約 22KB だった。その後、届け方、起点、手順の層、検査の置き場所の決まりが足され、全体のレビュー #283 の時点で 36.6KB に
なっていた。

#283 は次を挙げた。

- 決まりの定義の多くを、解説の場所（`architecture/`）に置いている。形式の `reference/` の説明（決まりは参照に置く）と合わない。
- ほぼすべての作業に要るわけではないもの（検査の条件と置き場所、手順の層の細則、器の構成要素）が、毎回読まれている。
- 同じ決まり（全体の扱い、地図の置き場所、全体まで読ませる文書の並べ方、役割ごとの指示の決まり）を、文書の体系と形式の
  いくつもの所で定義している。
- 検査の置き場所は、コードだけを変える人にも要る決まりなのに、「文書の体系」の名前の下にあって見つけにくい。
- conventions の地図で、「定義」の子が、関心で切った 4 つ（用語集、文書、変更と課題、レビュー）と、層で切った手順で
  並んでいる（兄弟をそろえる）。

依頼者は、判断 1 と 8 をおすすめの形（下の Decision）で進めると決めた（#284）。

## Decision

- 文書の体系は、仕組みの解説だけにする：3 つの層、区切りと依存の向き、項目の階層と地図、文書の根と種類、定義と届け方
  （届ける形を構成要素として、効き方の強い順に）、手順と役割。どの作業でも始めに全体まで読むのは、この解説だけにする
  （ADR 0020 の、どの作業でも文書の体系を全体まで読むことは変えない）。
- 決まりは参照の文書に移す。
  - 文書の検査の範囲（構造に限ること）、文書の根と器（各器に置くもの / 置かないもの）、全体の扱い、地図、役割ごとの
    指示の節と受け持つ手順の書き方：形式（`reference/formats.md`）。それぞれ、ここだけで定義する。
  - 要約と案内、起点に何をどう載せるか、全体まで読ませる文書の示し方、目的の手順と共通の手順：届け方の決まり
    （`reference/delivery.md`）。ADR 0028 が文書の体系に置いた、目的の手順を足したときに直す所の一覧も、ここに移す。
  - 何を検査にし、どこに置くか：検査の扱い方（`reference/checks.md`）。ADR 0027 が文書の体系に置いた決まりを移す。
    文書にもコードにも当てはまり、コードだけを変える人も読む。
  - 決まりを守るための破壊的な書き換え：変更の扱い方。
- conventions の地図の「定義」の子を、用語集、決まり、手順にし、決まりの下に、検査、文書、変更と課題、レビューを置く。
  文書は検査を、変更と課題は文書を、レビューは検査、文書、変更と課題を前提にする。文書の体系はどの項目にも入れず、
  conventions の全体の解説として、conventions の中のどの文書からも前提にされる。
- 索引の説明の列は一行の要旨にし、手順は目的の手順と共通の手順に分けて並べる。用語集は意味だけを持ち、地図の項目に
  合わせて節に分ける。

## Alternatives

- **全体を参照に移し、`changes.md` などとそろえる（#283 の判断 1 の (b)）**：どの作業でも全体まで読む文書が、決まりの
  細部まで持つことになり、量は変わらない。仕組みを理解するための解説が、置き場所の上でなくなる。
- **今のまま、毎回読む文書にも量の上限を当てる（同じく (c)）**：上限で量は抑えられても、決まりの細部と仕組みの解説が
  一つの文書に混ざったままになる。分けたうえで上限を当てることは、この判断と両立する（量の上限の検査で扱う）。
- **文書の体系を「決まり」の下の「文書」の項目に置く**：文書の体系は区切り、定義と届け方、手順と役割まで解説し、検査の
  扱い方もそれを前提にする。文書の項目に置くと、検査の扱い方が形式と届け方の決まりまで含む項目を前提にすることになり、
  文書の検査の範囲を形式に置くと循環する。
- **地図を今のまま、理由を書く（判断 8 の (a)）**：関心で切った項目と層で切った項目が並び、兄弟がそろわない。
- **変更と課題も分ける（判断 8 の (c)）**：変更と課題は互いを前提にし合う（依頼の範囲は PR の本文を、PR は依頼の範囲を
  指す）ので、分けると循環する。

## Consequences

- どの作業でも読む量が、約 37KB から約 13KB に減る。決まりの細部は、手順の段と起点の要約から、要るときに読まれる。
- 決まりの細部を毎回読まなくなるので、それが要る作業で読まれるかは、手順の段とスキルの案内に頼る。変更を届ける手順の
  「始めに読む」の段は、文書の体系と変更の扱い方のまま変えない。
