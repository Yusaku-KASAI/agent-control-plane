# 0010. いつも読み込むものは、ほぼすべての作業に関わり破られやすく検査で守れない決まりだけに絞り、量に上限を設ける

## Context

ADR 0009 で、共通のルールと役割ごとの指示を、定義の写しとして出典を示す形にした。何を写すかの基準がなく、変更の
進め方の手順や、文書を書くときだけに要る決まりまで、いつも読み込む要約に入っていた。いつも読み込むものは毎回の
作業の前に読まれるので、載せるほど要ることへの注意が薄れる。スキルが決まりの写しなのか、プラグインの道具の定義
なのかも決まっていなかった。

## Decision

- いつも読み込む要約に載せるのは、ほぼすべての作業に関わり、破られやすく、検査で守れない決まりだけにする。特定の
  作業にだけ要る決まりは、その作業のスキルや役割ごとの指示で届ける。
- いつも読み込まれる文書（CLAUDE.md、`rules/`、役割ごとの指示）に行数の上限を設け、`check-docs` で確かめる。
- スキルは定義の写しで新しい決まりを持たない。ただし、そのプラグインが持つ道具の使い方は、スキル自身が持ち主になって
  よい。
- 「必要十分」を原則にする。削るのは重複、経緯、置き場所違いからで、構成、言葉の定義、前提は削らない。

## Alternatives

- **基準を決めず、大事だと思うものを載せる**：載せるものが増え続け、要約がいつの間にか定義と同じ量になる。
- **いつも読み込むものを置かず、すべてをスキルにする**：スキルは要ると判断されたときしか読まれず、毎回守るべきことが
  抜ける。
- **短さを最優先にする**：前提や言葉の定義まで削ると、読み手が推測で補うことになる。

## Consequences

- 上限は、今の量に余裕を持たせた値にしている。上限に当たったら、載せる基準に照らして削るか、スキルや出典に移す。
