# 0041. 理由は種類で置き場所を分け、守らないと壊れる制約の理由は今の姿として書いてよい

## Context

理由の置き場所が、二通りに読めた。書き方の「コミットメッセージ」と共通のルールは「変更の理由と経緯はコミットメッセージに」、
文書を書く手順と形式の手順は「理由は ADR に」としていた。一方で、文書の体系は「参照には理由を置かない」とし、
control-plane の解説には、守らないと壊れる制約の説明として「〜ため」が約 20 か所あった。コードのコメントの決まりは、
コードで表しきれない制約や理由を残すとしている。

全体のレビュー #283 の判断 7 で、解説と参照の文書に理由を書いてよいかが問われ、依頼者はおすすめの (a) で進めると決めた（#284）。

## Decision

- 理由を三つの種類に分け、置き場所を文書の体系の「今の姿と理由の置き場所」で一度だけ定める（道筋と予定を Issue に置く
  ことと並べる）。コメント、文書、コミットにまたがり、決まりのどの文書も前提にできる所に置く。
  - 守らないと壊れる制約の理由（なぜその順か、なぜそれを避けるか）：今の姿として、その制約のそばに一文で書く。コメント、
    解説、手順、参照のどれでもよい。
  - 選んだ理由と、選ばなかった案：ADR。
  - 変更の理由と経緯：コミットメッセージと PR。
- 参照の文書が持たないのは、手順の順序と、選んだ理由（ADR に置くもの）にする。

## Alternatives

- **文書から理由を消す（判断 7 の (b)）**：守らないと壊れる制約は、理由がないと、読み手が守る意味を取れず、別の書き方に
  直されうる。コメントの決まりとも線がずれる。
- **理由はすべて ADR に置く**：制約のそばの一文の理由まで ADR の連鎖をたどることになり、ADR を今の姿の説明に使う形になる。

## Consequences

- 解説、手順、参照の「〜ため」は、壊れる制約の説明なら残し、選んだ理由の説明なら ADR への参照に置き換える。今ある文書は、
  次に触れるときに合わせる。
