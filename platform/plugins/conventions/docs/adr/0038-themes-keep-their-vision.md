# 0038. テーマの Issue は、狙いと進め方に加えて、そのテーマの切り口での目指す姿を持つ

## Context

ADR 0037 で、テーマの Issue を閉じずに続く軸とし、本文を狙いと進め方にして、終えたときの状態を持たないとした。
control-plane の #263 でテーマの本文を合わせたところ、終えたときの状態の多くを外すことになった。依頼者は、それに違和感を
示した（Slack、2026-10-26）。終えたときの状態に書いてあったのは、終わりの条件ではなく、そのテーマでやれたらよいこと、
こうなっているべきこと、理想の姿で、よくなかったのは「終えたときの状態」という名前だけ、という見方である。基本の部分は
すでに overview の目指す姿にあるので、overview に足す必要はないとも示した。

外してしまうと、テーマを読む人は、狙い（何のためか）の一文と進め方だけから、そのテーマで何を実現したいかを読み取る
ことになる。メンバーの Issue はそれぞれの範囲を持つが、テーマとしてどこへ向かうかは、どの Issue にも書かれない。

## Decision

- テーマの本文は、狙い（何のためか）、目指す姿、進め方（取りかかる方針とその理由）にする。目指す姿には、そのテーマの
  切り口での理想の状態を書く。届いたら終わる条件ではなく、テーマは今までどおり閉じずに続く。
- 言葉は、overview の「目指す姿」と同じにする。どちらも、終わりの条件ではない今の方針としての理想で、overview はリポジトリ
  全体、テーマはその切り口という違いだけになる（一つの言葉は一つの意味）。リポジトリ全体の方針は overview に置き、
  テーマの目指す姿は、それをテーマの切り口で細かくしたものにする。
- 目指す姿にも、メンバーの番号を並べない（進め方と同じく、メンバーが変わるたびに古くなる）。
- 整っている状態の「テーマ」の行に、目指す姿が overview の目指す姿や今の決まり（ADR）と食い違わず、overview を書き写して
  いないことを足す。ADR 0037 が終えたときの状態を退けた理由の一つ（overview と重なる）を、課題を整えるときに見つけるため。
  目指す姿はメンバーとは合わせなくてよい（ADR 0001 の、メンバーが変わってもテーマの本文は書き換えなくてよい）。

ADR 0037 のほかの決定（閉じずに続く軸、終えたときの状態を持たない、区切りのある目標はふつうの Issue にする、進め方の番号を
メンバーの Issue に移す）は変えない。

## Alternatives

- **狙いの節の中に、理想の状態を箇条で書く（決まりを変えない）**：狙いは「何のためか」で、理想の状態（どうなっていたいか）とは
  問いが違う。一つの節に二つの問いが混ざり、読む人が見分けにくい。
- **名前を「理想の姿」や「向かう先」にする**：overview の「目指す姿」と同じものに別の言葉を使うことになる。
- **ADR 0037 のまま外す**：テーマとして何を実現したいかが、どこにも書かれなくなる。ADR 0037 が退けた「テーマに目指す姿を
  持たせ、overview からは外す」は、全体の目指す姿を一か所で読めなくなるのが理由だった。この決定は overview から何も外さないので、
  その理由には当たらない。
- **目指す姿を overview に移す**：テーマの切り口での細かい理想まで overview に置くと、全体の解説が子の細部を書き写す形になる
  （文書の体系の項目の階層と関係）。依頼者も、overview に足す必要はないと示した。

## Consequences

- conventions の決まりなので、それを使うすべてのターゲットに効く。どのターゲットも、プラグインの更新で受け取り、
  ターゲットの側で直すファイルはない。
- 今あるテーマの Issue は、終えたときの状態に書いていた理想を、目指す姿の節に移す（control-plane では #263 で、課題を
  整える手順で行う）。ADR 0037 に沿ってすでに外したものも、編集の履歴から読み直して戻す。ほかの Issue や overview で扱って
  いることは、目指す姿から外す理由にならない（overview の書き写しになるものは除く）。ほかの決まりと食い違うもの（control-plane の #40 の、CI でビルドしたイメージを取得する形は、
  レジストリを使わない判断と食い違う）は、移すときに直す。
