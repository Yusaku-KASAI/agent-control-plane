# 0015. ほかの文書の中身には要約か案内で触れ、丸ごと読み込まれる起点には載せるものを選び、読ませる範囲を「（全体を読む）」で示す

## Context

#96 のやりとりで、文書の置き場所の決まり（定義と届け方）が、判断の軸として使われなかった。いつも読み込む要約には、
その決まりへのリンクがあった。ただ、CLAUDE.md と食い違ったときの決まりの出典として置かれていた。「同じ事実は一か所に」
の項目は principles の SSOT にだけつながり、それを決まりの置き場所に具体化した定義には届いていなかった。対話の
Claude は `documentation.md` を読んでいたが、要約の書き方どおりに SSOT の一般論で考えた。

いつも読み込む要約の項目には、どれを判断の軸にし、どこを深く読むかの区別がなかった。決まりの中身を書くことと、
読みに行かせることも、書き分けられていなかった。

## Decision

- 文書がほかの文書の中身に触れるときは、要約（中身を短く言い直し、出典を付ける）か、案内（中身を言い直さず、どの場面で
  どこを読むかだけ）で書く。どの文書にも当てはまる書き分けで、全体（overview、索引）から子へは案内で書く、という今の
  決まりもその一つの例になる。リンクの種類（前提か在りか）は、これとは別に ADR 0014 の決め方で決める。
- エージェントがリンクをたどって選ぶのではなく、丸ごと読み込む文書（入口の CLAUDE.md、いつも読み込む要約、役割ごとの
  指示、スキル）を起点と呼ぶ。起点が principles と conventions の定義を載せるときは、要約にするか案内にするかを、
  ADR 0010 の基準（ほぼすべての作業に関わり、破られやすく、検査で守れない）を、その起点の範囲に当てはめて選ぶ。
- 一般的な原則と、それを具体化した決まりがあるときは、具体化した決まりを要約にし、原則は理由として添える。
- 判断の軸になる決まりを、細かい作法より先に載せる。読み手が先に書かれたものから読むためで、並び順で大事さを
  表すためではない（並べ替えを退けた理由は Alternatives）。
- 起点が自分で持つもの（CLAUDE.md のリポジトリの決まり、役割に固有の振る舞い、スキルの道具の使い方）は、この選び方に
  限らない。
- 文書の体系の構成を、置き場所と関係（区切り、項目の階層、文書の根、種類）と、読み手への届け方（定義と届け方、要約と
  案内、起点、読む範囲）の二つのまとまりに分ける。
- 読む範囲は、リンクの直後の「（全体を読む）」で示す。付けたリンクは、その場面ではリンク先を全体まで読み、その中の
  「（全体を読む）」もたどる。付けないリンクは、要るときにリンク先の節を読む。場面を限って付け、いつも要るものは要約に
  するか、いつも読み込む要約に載せる。
- 量の上限に当たったときに減らす方法の一つとして、要約を案内に下げることを足す。

## Alternatives

- **決まりの間に優先順位を付ける（プロジェクトの決まりを原則より先に引く）**：問題は食い違いではなく、書いてあるのに
  読まれない・使われないことにある。一般的な原則の上に具体的な決まりを組む向きは自然で、変えなくてよい。
- **すべての項目を重要度の順に並べ替える、「大事」の印を付ける**：並び順は優先として伝わらず、印は増えるほど平らに
  なる。判断の軸を先に載せるのは、読まれる順のためで、重要度の順を表すものではない。
- **起点の冒頭に「先に読む」の節を置き、いつも読む文書を並べる**：いつも読むなら、読み込ませるのと同じコストで、
  読まれるかが確かでなくなるだけ。
- **読む範囲に段を増やす（ある程度読む、前提までたどって読む）**：まず二つで効くかを確かめる。
- **起点を索引と全体（overview）まで広げ、起点に要約と案内の書き分けを持たせる**：リンクを持つ文書のほとんどが起点に
  なり、言葉を作った意味がなくなる。要約と案内の書き分けをどの文書にも当てはまる決まりにすれば、起点を広げずに
  全体と索引も同じ書き分けで扱える。
- **principles と `documentation.md` を hook で読み込ませる**：principles の原則とパターン、`documentation.md` を
  合わせて約 780 行あり、毎回のセッションとサブエージェントのコストが大きい。

## Consequences

- 「（全体を読む）」で本当に全体が読まれるか、読んだ決まりが判断に使われるかは確かめていない。何回かの依頼のあと、
  セッションの記録で数える。足りなければ、読み込ませるか、仕組みで守る形を考える。
- 使った決まりを出力（PR の本文、レビューの指摘）に書かせる仕組みは、ここでは決めていない。
- 起点の各項目が要約か案内かは検査していない。「写し」と「いつも読み込む要約」の言葉の整理、ロールとスキルの整理も
  まだしていない。
