# 0048. ロールに共通の但し書きは conventions で一度だけ定義し、ロールの指示には固有の振る舞いだけを置く

## Context

全体のレビュー #283 の D は、ロールの指示について次を挙げた。

- reviewer の「固有の振る舞い」が、レビューする手順とレビューの扱い方の書き写しになっている（必須）。
- 四つのロールに同じ但し書き（聞いて待てないとき、Slack への投稿はハーネスの契約による）があり、三つのロールに
  「試すときは自分の worktree か `mktemp -d`」がある。developer と reviewer は行数の上限ちょうどで、行を伸ばして収めている。
- pm の要約が出典（整っている状態）の「依頼者かエージェントが」の限定を落としている。ロールがハーネスの契約をパスなしで
  指している。

#297 で、聞いて待てないときの決まりを文書の体系の「手順と役割」に定義し、共通のルールに載せ、迷うなら取り消せる方、
公開や権限を広げない方を選ぶことを足した。書ける範囲の外の書き先がハーネスの契約によることは、形式の役割ごとの指示に
置いた。

## Decision

- ロールに共通の但し書きは、conventions で一度だけ定義し、ロールの指示から外す。
  - 聞いて待てないとき：文書の体系の「手順と役割」。どの手順でも、どの役割でも当たる横断の決まりで、どの作業でも
    始めに全体まで読む文書に置く。共通のルールはその要約を載せる。迷うときの向き（取り消せる方、公開や権限を広げない方）
    は、拒否を既定にする考え方による。
  - 書ける範囲の外の書き先（チャットへの投稿など）：形式の役割ごとの指示の「書ける範囲」の意味に置く。
  - 試すときの場所：文書の体系の「手順と役割」に、作業領域を書ける範囲に持たない役割は、試すための編集や検査を作業領域の
    外（隔離された自分の作業ツリーか、一時的な場所）でする、と置く。隔離の仕組みは roles の全体像が持つ。
- reviewer の「固有の振る舞い」は、reviewer だけの定義（何も指さなければリポジトリ全体を範囲にする、HEAD を確かめて読む
  読み方、報告）にし、手順と決まりの書き写しは「使う決まり」の出典付きの一行にする。
- developer の「レビュー」の節は、レビューを頼んで答える手順への案内と、破られやすい二つ（差分を自分で見ず頼むことと
  渡すもの、根拠を確かめて答え終える前を満たすこと）にする。
- ロールの指示の行は、表示幅で伸ばして上限に収めない。

## Alternatives

- **共通の但し書きを共通のルールにだけ書く**：共通のルールは要約と案内で、定義は conventions の `docs/` に置く決まり
  （定義と届け方）に反する。
- **試すときの場所を roles の全体像にだけ置く**：ロールの指示とスキルからしか読まれず、ロールを使わないセッションの
  サブエージェントに届かない。文書の体系はどの作業でも始めに読まれる。
- **ロールの指示に但し書きを残し、出典だけを付ける**：同じ一文が四つのロールに残り、定義を変えたときに直す所が増える。

## Consequences

- ロールの指示は、受け持つ手順、使う決まりの要約、固有の振る舞いだけになり、行数と行の長さに余裕ができる。
- 役割に共通の決まりを足すときは、文書の体系の「手順と役割」に置き、ロールの指示には書かない。
