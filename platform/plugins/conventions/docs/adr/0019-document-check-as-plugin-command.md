# 0019. 文書の検査を conventions のコマンドにし、Markdown を変えたターンの終わりに hook が回す

## Context

文書の形式のうち機械で確かめられるものは、`tools/check-docs.py` が確かめていた。これは target-template の共通の
ファイルで、どのターゲットにも同じものを置き、ターゲットの契約が「`make check` は `make check-docs` を含む」と
求めていた。

検査は conventions の決まりを守らせる仕組みで、確かめる中身も conventions の形式が決める。それなのに、置き場所と
配り方はターゲットの共通のファイルで、決まりを変えるたびにすべてのターゲットの写しを直すことになっていた。写しが
遅れると、届いている決まりと手元の検査が食い違う（Issue #131 の txt-crypter の `"在りか"`）。

## Decision

- 検査を conventions プラグインのコマンド `bin/check-docs` にする。作業ディレクトリを含むリポジトリの Markdown を
  確かめる。Claude Code は有効なプラグインの `bin/` をエージェントの `PATH` に入れるので、どのターゲットでも
  `check-docs` で呼べる。
- conventions の Stop の hook が、ターンの終わりに検査を回す。対象は、ブランチが既定のブランチから分かれてから変えた
  Markdown か、作業ツリーで変えたか足した Markdown があるときだけ。誰が変えたか（エージェントか人か）は区別しない。
  既定のブランチが分からないときは作業ツリーだけを見る。落ちていれば、その出力を示してターンを止める。同じ出力で
  止めるのは一度だけにし、通れば忘れる。ほかの Stop の hook で続けたターンの終わりにも回す。
- ターゲットの契約と target-template からは、文書の検査を外す。ターゲットの `make check` と CI は文書の検査を含まなくてよい。
  [Docs as Code](../../../principles/docs/reference/patterns.md#docs-as-code) のうち、文書の検査を CI で回す部分から外れ、
  Issue #117 で挙げた「人も CI も同じ検査を回す」前提も外す。依頼者の判断で、検査の配り方を決まりの持ち主（platform）
  の外に残さないことを選んだ。
- platform を同じリポジトリに持つ control-plane は、`make check-docs` でこのコマンドを呼び、CI でも回す。これは
  control-plane のリポジトリの選択で、契約ではない。

## Alternatives

- **ターゲットの CI が platform を取ってきて回し、契約にも残す**：人も CI も同じ検査を回せる。ただし、platform の
  在りかと版をターゲットごとに CI に書くことになり、決まりの持ち主の外に検査の配り方が残る。
- **コマンドだけを用意し、手順（文書を書く）で回させる**：決まりはあっても破られうる（仕組みで守る）。
- **Markdown を書き換えるたびに PostToolUse の hook で回す**：書きかけの途中の食い違い（足した文書をまだ一覧に
  載せていない）まで毎回示し、知らせるだけで止めない。
- **作業領域の pre-push で回す**：pre-push は control-plane が置くもので、devcontainer で直接動くときには働かない。
  platform だけで閉じない。

## Consequences

- conventions を有効にしたどのターゲットでも、ブランチか作業ツリーに Markdown の変更があるターンは、検査が落ちていれば
  一度は止まる。検査は、変えたファイルだけでなくリポジトリのすべての文書を確かめるので、前から壊れていた文書も
  直すことになる。人が書きかけの文書を作業ツリーに置いたまま、関係のない依頼をしても止まる。
- 同じ出力では一度しか止めないので、エージェントが直せない失敗は止め続けない。そのまま終えたときは、報告で
  それを伝えることになる。
- ターゲットの CI は文書の検査を回さない。人が Claude Code を通さずに変えた文書は、次にエージェントのセッションで
  そのブランチか作業ツリーに Markdown の変更があるときに見つかる。人がターゲットで回すときは、マーケットプレイスの
  `plugins/conventions/bin/check-docs` を、確かめるリポジトリの中で実行する。
- hook が回すのは、入れた conventions の版。ブランチが check-docs と形式を一緒に変えているとき（control-plane）は、
  入れた古い版が新しい形を誤りとして止めうる。そのときはリポジトリの `make check-docs` の結果に従う（止めるときの
  理由にも書く）。
- 検査はエージェントの環境の `python3`、`git`、`jq` を使う。
- 決まりを変えると、マーケットプレイスから届く版の検査がすぐにどのターゲットにも効く。写しを直す必要はない。
