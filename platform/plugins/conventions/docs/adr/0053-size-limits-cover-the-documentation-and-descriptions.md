# 0053. 量の上限を、文書の体系と description にも当て、折り返せない行は幅でなく折り返した行数で数える

## Context

量の上限（ADR 0010、0049）は、いつも読み込まれる文書（`CLAUDE.md`、共通のルール、役割ごとの指示）の行数と、行の表示幅
130 を確かめていた。その狙いはいつも読み込まれる量を抑えることだが、次の三つが残っていた（#308。PR #301 のレビューの
提案から積んだ）。

- どの作業でも始めに全体まで読む文書の体系に、上限がない。ADR 0039 は「起点の量の検査を見直す変更で扱う」と先送りし、
  ADR 0049 の Alternatives に挙げて積んだ。
- 役割とスキルの frontmatter の `description` は、どのセッションでも一覧として読み込まれるのに、行数と幅の上限の外にある
  （このときいちばん長い harness スキルで幅 338）。載せきれないものを寄せる道が開いている。
- 表の行とコードブロックの行は折り返せないのに幅の上限が当たり、「折り返す」という直し方が使えない。表を箇条に組み直す
  しかない。

## Decision

- 共通のルールの「始めに読む」の節が、節を指さないリンクで指す文書（どの作業でも全体まで読む文書。今は文書の体系）に、
  合計 150 行の上限と、いつも読み込まれる文書と同じ幅の上限を当てる。対象は、どの作業でも全体まで読ませる示し方
  （届け方の決まり）から導き、パスで名指さない。節を指すリンク（`#starting-points` など）は、その節だけを読ませるので
  数えない。150 は、下の数え方で 130 行の今の量に余裕を持たせた値。共通のルールがあるのに、その節が全体を指す文書が
  一つもない（節の名前を変えた、節を指すリンクだけにしたなど）ときは、上限が黙って外れないよう検査で落とす。
- 役割ごとの指示とスキルの `description` は、一行に畳んで表示幅を 390（行の幅の上限の 3 行分）までにする。幅の数え方は
  ADR 0049 と同じ。
- 表の行（`|` で始まる行）とコードブロックの行（行の始めの HTML のコメントを含む。折り返せない行）には幅の上限を
  当てず、130 で折り返したときの行数（切り上げ）で行数に数える。伸ばした分は行数で数えるので、伸ばして収める抜け道に
  はならない。見分け方は、ほかの検査と同じコードの見分け方（ADR 0050）と行の始めの `|` にする。表でない `|` で始まる
  行や、行の始めの HTML のコメントも折り返せない行に入るが、行数で数えるので量は抑えられる。
- どれも形式の量の上限に置き、check-docs の量の検査で確かめる。

## Alternatives

- **文書の体系には上限を当てず、レビューで見る**：ADR 0049 が行数の上限の外で破られていたことを挙げたのと同じで、判断の
  要らない決まりを読むことに任せることになる。
- **文書の体系をパスで名指して上限を当てる**：単純だが、どの作業でも全体まで読む文書を変えたり足したりしたときに検査が
  追わない。届け方の決まりが「始めに読む」の節に直に並べると決めているので、そこから導く方が一つの出典に沿う。
- **文書の体系は文字数で測る**：行数の上限と測り方が分かれる。ほかの起点と同じ行数と幅にそろえた方が、書く人の目安が
  一つで済む。
- **目的の手順の「始めに読む」の段の文書（変更を届ける、変更の扱い方など）にも当てる**：どの作業でも読まれるわけでは
  なく、手順の段として要るときに読まれる。いつも読み込まれる量を抑える狙いの外なので、当てない。
- **`description` を文字数で測る**：ADR 0049 が行で選ばなかったのと同じで、ほかの上限と数え方が変わる。
- **`description` の合計に上限を当てる**：一覧に並ぶ数は、どのプラグインを有効にするかでターゲットごとに変わり、一つの
  リポジトリの検査では決められない。一つずつに当てる。
- **`description` を 130（一行）までにする**：今の 13 のうち 11 が超え、使う場面（「〜ときに使う」）を書ききれなくなる。
- **折り返せない行を幅の上限から外し、行数も 1 と数える**：ADR 0049 が閉じた、行を伸ばして収める抜け道が、表とコードで
  また開く。
- **すべての行を 130 で折り返した行数で数え、幅の上限をなくす**：ADR 0049 が選ばなかった形で、折り返せる行が一行で読める
  幅に収まることを保てない。折り返せない行にだけ当てれば、そこではもともと保てないので失うものがない。

## Consequences

- 文書の体系は、今の 130 行（表の 3 行が折り返して 2 行ずつ）で上限の中にある。足すときは、ほかの起点と同じく、減らすか
  参照へ移す。
- 今の `description` はすべて 390 の中にある。
- 起点の表をそのまま保てるようになり、表を箇条に組み直さなくてよい。表の長い行は、その分だけ行数を使う。
- conventions を使うほかのターゲットの、いつも読み込まれる文書と、その `.claude/agents/` と `.claude/skills/` の
  `description` も、この検査に掛かる。文書の体系の上限は、共通のルールを持つリポジトリ（platform を同居させる
  リポジトリ）でだけ掛かる。
