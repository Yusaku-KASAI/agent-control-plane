# 0043. 課題の扱い方を Issue の形ごとに分け、範囲の項目の付け合わせと済んでいないものの置き場所を一か所で決める

## Context

全体のレビュー #283 の A は、課題の扱い方（`reference/issues.md`）に例外が積み重なり、種類の違う節が混ざっていると挙げた。

- 「それだけで依頼として成り立つか」で振り分ける表が三つ（依頼の範囲の振り分け、Issue に書き足すとき、持ち越すもの）
  あり、閉じた Issue の但し書きはそれぞれ別に足されていた。2 週間で、テーマの直しが 6 本、閉じた Issue への書き足しの
  直しが 5 本あった。
- テーマの形は、分類の表の一つのセルに約 400 字で入っていた。
- 範囲の項目の PR 番号とチェックの扱いを、課題の扱い方の三か所と、変更を届ける、レビューを頼んで答える、セッションを
  締めるの手順が言い直していた。
- セッションを締めるの 2 段が、残す理由の扱いの分類（続く作業、作業領域にしかないもの、人が解くもの）を定義していた。

あわせて、打ち切りで直さなかった提案のうち課題の扱い方に当たるもの（#283 の L）が残っていた。数える書き足しの
コメントを書いた人で絞っていない（246-1）、依頼者が範囲を広げたときと「範囲の中を広げない」が食い違う（246-2）、範囲を
どの段で書き換えるかが二か所にある（246-4）、`Refs` の行をすべて依頼の Issue と読む（246（c8cb23e）-1）、閉じた Issue で
開き直しが先に当たり、「人に渡す」の渡し先がない（267（57dc351）-1、2）、テーマの節の見出しの名前が決まっていない（275-1）。

## Decision

- 課題の扱い方を、分類、どの Issue にも当たること、Issue の形（ふつうの Issue、テーマ、ロードマップ、キャンバス、全体の
  レビューの報告への案内）、依頼の範囲（その中に範囲の項目と PR の付け合わせ）、済んでいないものの置き場所、整っている
  状態、締め（持ち越すもの、残す理由の扱い）の順に組み直す。分類の表のセルは一行にし、形は Issue の形の節に置く。
- 済んでいないものの置き場所を一か所で決める。それだけで依頼として成り立つものは、いつも新しい Issue にし、書き足そうと
  した Issue があればそのリンクをコメントする（PR を進めているあいだの範囲の外の指摘も同じで、依頼の Issue にリンクを
  残す）。成り立たないものは、書き足す先の Issue の形と状態（ないかふつうの Issue でない、移って閉じた、済んで閉じた、
  ほかの理由で閉じた、開いている）の一つの表で、上から順に最初に当たる行を取る。PR を進めているあいだに依頼の Issue に
  積むことも、この表の開いている行に入れる。ほかの理由で閉じた Issue に残す済んでいないものは、締めのまとめか依頼への
  答えに書いて人に渡す。
- 範囲の項目と PR の付け合わせ（番号を添える、マージされたらチェック、閉じたら番号を外す）は依頼の範囲の中の一つの節で
  決め、手順は「付け合わせる」と書いてそこを指す。付け合わせは、その Issue に次に手を入れる人（次にその Issue の変更を
  依頼された人、開き直す人、締める人）が、手を入れる前に行う。
- 作業する人は自分から範囲の中を広げず、依頼者が（依頼のスレッドか、依頼者が書いたコメントで）範囲を広げたときは範囲の
  中に足す。依頼者とエージェントのほかの人が書いたもの（Issue と PR のコメント、PR のレビュー。依頼者のものと確かめられない
  ものを含む）の扱いは、どの Issue にも当たることの一か所に置き、範囲を広げることにも、本文に移すことにも、Issue に
  積むことにも、新しい Issue にすることにも、PR の指摘を直す義務に数えることにも当てる。
- 範囲を何本かの PR に分けるとき、途中の PR は作るときから依頼の Issue を閉じない書き方にし、閉じないことのコメントは
  求めない（範囲の項目と番号が残りを表す）。並べた PR がどれも閉じないままマージされたら、付け合わせで範囲の中が
  すべてチェックされたときに閉じる。PR を終える人も、閉じるかを決める前に付け合わせる。
- PR の本文の `Closes` と `Refs` の行には依頼の Issue だけを置き、ほかの Issue には文の中で触れる（書き方の PR）。
- テーマの本文は、`## 狙い`、`## 目指す姿`、`## 進め方` の節にし、整っている状態のテーマの行で確かめる。
- Issue に書かないもの（秘密、個人の情報、見える範囲の狭い場所の中身）を、キャンバスだけでなくどの Issue にも当て、
  同じ範囲に見える PR、コミットメッセージ、リポジトリの文書にも当てる。定義は、何を書くかを持つ書き方に置き、課題の
  扱い方はそこを指す。
- 残す理由の扱いの分類は、課題の扱い方の「残す理由の扱い」に置き、セッションを締めるの段と、ハーネスの契約の理由の
  種類ごとの扱いはそこを指す。conventions の言葉で「残す理由」を定め、締めはハーネスの言葉（片付け）に頼らない。
- 整っている状態の本文の行で、範囲の中に移す書き足しは、依頼者かエージェントがコメントに書いたものに限る。

## Alternatives

- **振り分けの表を三つのまま、閉じた Issue の但し書きをそろえる**：同じ線引きが三か所に残り、閉じた Issue への書き足しの
  ように、一か所を直すと別の表が古くなる形が続く。
- **テーマ、ロードマップ、キャンバスをそれぞれ別の参照の文書にする**：どれも短く、分類の表と整っている状態から同じ文書の
  中で指す方が引きやすい。
- **残す理由の扱いを用語集に置く**：扱い（どうするか）は決まりで、用語集は言葉の意味だけを持つ。
- **締めの決まり（持ち越すもの、残す理由の扱い）を別の参照の文書にする**：持ち越すものの置き場所は済んでいないものの
  置き場所と一体になる。残す理由の扱いは一つの表と短い箇条で、別の文書にすると、締めの手順が読む文書が一つ増えるだけで
  得がない。課題の扱い方の「締め」の節にまとめた。
- **閉じた Issue には書き足さず、いつも新しい Issue にする**：閉じた Issue の文脈を新しい Issue に書き写すことになる
  （ADR 0036 の理由が今も成り立つ）。
- **範囲を分けたら、どの PR も閉じない書き方にし、付け合わせだけで閉じる**：PR 一本の Issue と分けた Issue で閉じ方が
  変わり、最後のマージから次の付け合わせまで、済んだ Issue が開いたまま残る。

## Consequences

- 課題の扱い方の節の名前とアンカーが増える（`#kinds`、`#general`、`#forms`、`#theme`、`#roadmap`、`#scope-items`、`#leftovers`）。今ある
  アンカー（`#body`、`#scope`、`#append`、`#tidy`、`#canvas`、`#carry-over`）は保つ。
- ハーネスの契約の理由の種類ごとの扱いの表が指す先は、セッションを締めるの 2 段から課題の扱い方の「残す理由の扱い」に
  変わる。
- 今あるテーマの Issue のうち、節が `## 狙い`、`## 目指す姿`、`## 進め方` でないもの（メンバーを並べる節を持つものなど）は、
  課題を整えるときに合わせる。
