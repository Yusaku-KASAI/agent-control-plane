# 0037. テーマの Issue は閉じずに続く軸とし、本文は狙いと進め方にして、終えたときの状態を持たない

## Context

ADR 0001 は、テーマ（何のためか）をラベル `theme:<名前>` で表し、テーマの説明（狙い、終えたときの状態、進め方とその理由）を
テーマごとの Issue の本文に書くと決めた。メンバーは本文に並べず、ラベルで決まる。Consequences には「テーマ Issue の本文は、
メンバーが変わっても書き換えなくてよい」とある。

一方、課題の扱い方の整っている状態の「テーマ」の行は、狙いと終えたときの状態が今のメンバーと合っていることを求めた。
メンバーが足されるたびに終えたときの状態の見直しが要り、ADR 0001 と向きが食い違っていた。テーマを閉じる条件はどこにも
なかった。

control-plane の 5 テーマ（複数ターゲット、隔離と安全、運用と可視化、実行基盤の拡張、ロールと共通の能力）は、作られてから
新しいメンバーが足され続け、終わらない軸として使われていた。2026-10-25 の課題の整理では、運用と可視化と、ロールと共通の
能力の終えたときの状態の一部がすでに達成され、今のメンバー（トークンの節約など）が表れていないことが、ずれとして挙がった。
全体の目指す姿は、control-plane の `docs/overview.md` の「目指す姿」にもあり、テーマの終えたときの状態と重なりうる。
依頼者は、テーマがメンバーを並べるものか、閉じる前提のものかを問い、control-plane の #270 で、続く軸とする案を選んだ。

## Decision

- **テーマは閉じずに続く軸にする**：テーマの Issue は、何のためかを表し続ける。やめるか（閉じるか）は人が決める。
- **本文は狙いと進め方にする**：狙い（何のためか）と進め方（取りかかる方針とその理由）を書き、終えたときの状態は持たない。
  メンバーは今までどおり本文に並べず、ラベルで決まる。進め方にもメンバーの番号と順を並べない。何が先かは blocked by が、
  今の焦点と順番はロードマップが持ち、個々の Issue に取りかかる条件（「困ったときに」など）や依存の理由はその Issue の本文の節
  （待つ条件は `## 保留`、依存の理由は `## 関係`）に書く。番号を並べるとメンバーが変わるたびに古くなる。方針の理由として、決めた Issue を指すのはよい。
- **区切りのある目標はテーマにしない**：終えたときの状態を持つ目標は、ふつうの Issue（依頼の範囲で終わりを持つ）にする。
  リポジトリ全体の目指す姿は、そのリポジトリの `overview.md` に置く（文書の体系の `docs/overview.md`）。
- **整っている状態の「テーマ」の行**は、狙いと進め方が今のメンバーと合っていて、本文に終えたときの状態とメンバーの番号の
  並びがないこと、にする。

ADR 0001 のほかの決定（関心とテーマを多対多のラベルで表す、メンバーは本文に並べない、依存と焦点を別の仕組みで持つ）は
変えない。

## Alternatives

- **テーマを目標にし、終えたときの状態に届いたら閉じる**：区切りは付くが、今のテーマは終わらない関心として使われていて、
  閉じたあとに同じ関心の Issue が出るたびに新しいテーマとラベルを作ることになる。ラベル `theme:<名前>` が閉じたテーマを
  指し続けるか、付け替えが要る。
- **終えたときの状態を残し、メンバーが変わるたびに書き直す（今の整っている状態のまま）**：ADR 0001 の「書き換えなくてよい」と
  食い違ったままで、課題を整えるたびにテーマの本文がずれとして挙がる。終えたときの状態が overview の目指す姿と重なる。
- **テーマに「目指す姿」を持たせ、overview からは外す**：テーマごとに目指す姿が分かれ、全体の目指す姿を一か所で読めなく
  なる。overview は全体の解説として目指す姿を持つ（文書の体系の `docs/overview.md`）。
- **テーマの Issue をなくし、ラベルの説明だけにする**：GitHub のラベルの説明は短く、進め方（方針とその理由）を書けない。

## Consequences

- conventions の決まりなので、それを使うすべてのターゲットに効く。どのターゲットも、プラグインの更新で受け取り、
  ターゲットの側で直すファイルはない。
- 今あるテーマの Issue の本文から、終えたときの状態を外す（control-plane では #263 で、課題を整える手順で行う）。外す前に、
  overview の目指す姿にないことをどこに残すかを確かめる。進め方の記述は、失われないように振り分けて移す：Issue ごとの待つ条件はその Issue の `## 保留`、依存の理由は
  `## 関係`（依存は blocked by にも入れる）、ほかの Issue への制約は `## 気をつけること` に移し、番号によらない優先の方針は
  テーマの進め方に方針として残す。
- テーマを閉じる場面は、人がその関心をやめると決めたときだけになる。閉じたテーマのラベルを付けた開いている Issue の扱い
  （付け替えるか）は、そのときに人が決める。
