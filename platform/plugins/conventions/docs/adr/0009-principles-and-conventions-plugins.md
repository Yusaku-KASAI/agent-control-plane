# 0009. どこでも通用する知識とこのプロジェクト群の決まりを、platform の製品の話から分け、それぞれプラグインにする

## Context

ADR 0007 で platform を全区切りが前提にしてよい共有の核にし、原則、パターン、文書の体系と形式、作業の進め方を
`platform/docs/` に置いた。そこには一般性の違う 3 つが混ざっていた。どこでも通用する原則とパターン、このプロジェクト群
の決まり（文書の体系、形式、作業の進め方、書き方、設計の観点）、platform という製品の話（プラグイン、ハーネスの契約）。
原則とパターンはエージェントにも、このプロジェクトにも依存しないのに、platform の文書の一部としてしか使えなかった。
書き方の決まり（rules）と設計の観点（review）は別のプラグインで、決まりの文書とも離れていた。

ほかのターゲットのエージェントに届くのは、マーケットプレイス（`platform/`）の中だけ。

## Decision

- どこでも通用する原則とパターンを principles プラグインにする。ほかの何も前提にしない。
- このプロジェクト群の決まりを conventions プラグインにする。rules と review を統合し、文書の体系、形式、作業の進め方、
  文書と作業の用語集と、それらの ADR（0005〜0008）を持つ。principles だけを前提にする。
- `platform/docs/` は platform 自身（プラグインの構成、ハーネスの契約、エージェントの用語、対話の準備、プラグインの ADR）
  だけにする。
- どちらも、スキル（必要なときに読む）と、プラグインの中の `docs/`（人が読む入口、標準の器）で届ける。いつも守らせる
  決まりは conventions の hook が読み込ませ、文書の在りかも示す。

## Alternatives

- **`platform/` の外に最上位のディレクトリ（`template/` と同じ形）を作る**：ほかのターゲットのエージェントに届かない。
- **`platform/` の中に、プラグインではないディレクトリを作る**：エージェントには届くが、配る単位にならず、このプロジェクト
  の外で使えない。読み込ませ方も別に要る。
- **principles と conventions を一つのプラグインにする**：原則とパターンだけを使いたい場面で、このプロジェクト群の決まりも
  入る。依存の向きも一つのプラグインの中に隠れる。
- **rules と review を残し、文書だけを動かす**：一緒に変わる決まりが三か所に分かれる。

## Consequences

- ターゲットは rules と review の代わりに principles と conventions を有効にする（`.claude/settings.json`）。
- ADR 0005〜0008 は conventions の ADR として番号のまま移り、platform の ADR は 0001〜0004 になる。
- principles は、エージェント基盤と関係なく使える。要るようになれば、そのまま別のリポジトリに切り出せる。
