# 0047. principles には名前と文献のあるものだけを載せ、文献のない項目は文献を足すか conventions に移す

## Context

principles の原則とパターンの一覧は、冒頭で「名前と出典があり、広く良いとされているものだけ」を載せるとしている。
全体のレビュー #283 の E は、この基準に合わない項目（原則：今と経緯を分ける、必要十分、確立した考え方に拠る。
パターン：状態を軸で洗い出す、失われうるものを先に挙げる、手順を実装と突き合わせる、一つの目的の小さな変更、
関係を種類で分ける、入口と唯一の一覧）と、出典の書き方のばらつき、原則の分類が MECE でないことを挙げた。B は、
principles が conventions の言葉（前提のリンク、在りかのリンク、索引）と置き場所を持つことを挙げた。判断 4 で、依頼者は
おすすめの (a) と (c) の組み合わせで進めると決めた（#284）。

## Decision

- 基準は保つ。基準に合わない項目は、次のどちらかにする。
  - 確立した名前と文献があれば、それを見出しと本文に足して残す：必要十分（YAGNI、Omit Needless Words）、状態を軸で
    洗い出す（Decision Table）、失われうるものを先に挙げる（FMEA、Pre-mortem）、一つの目的の小さな変更（Small CLs）。
    確立した考え方に拠るは、見出しはこの一覧の名前のまま、もとにある確立した考え方（A Pattern Language と Design
    Patterns の、名前の付いた解き方を共有の語彙にする考え方）を文献として足す。
  - 文献が見つからず、このプロジェクト群の決まりとして持つものは、conventions に移す：今と経緯を分ける（文書の体系の
    「今の姿と理由の置き場所」が持つ）、関係を種類で分ける（文書の体系の「項目の階層と地図」が持つ）、手順を実装と
    突き合わせる（変更の扱い方の変更とパターンの節が、表の下に持つ）。入口と唯一の一覧は、形式の文書の根の器の表が同じ
    決まりを持つので、外す。
- 文献（出どころの文書）は、原則では「原則」の行の、パターンでは「形」の行の終わりに「文献は …。」の形で書き、一覧の
  冒頭にその書き方を置く。#283 の E が挙げなかった項目も、文献のないものには足す。用語集の「出典」（要約が拠る
  文書）と分けるため、「文献」と呼ぶ。
- 原則の分類を、決め方と進め方、分割、依存と約束、階層と並び、一意さ、量と見せ方、確かめ方、守り方にする。関心の
  分離（知識の種類）と単一責任（変更を求める相手）は、分ける軸で書き分ける。
  パターンの「状態を軸で洗い出す」は変更の組み立てに、「設計構造行列」は構造に移す。種類の違うものは、1 項目でも
  分類にしてよい。アンカーは変えない。
- principles から conventions の言葉と置き場所を外し、一般の言い方にする（依存関係の逆転の契約の置き場所は、使う側に
  届く契約を指す）。

## Alternatives

- **基準を「名前の付いた考え方（文献があれば添える）」に緩める（判断 4 の (b)）**：このプロジェクト群で決めたことと
  広く確かめられた考え方の区別がなくなり、principles が共有の核として小さく保てない。
- **文献のない項目をすべて conventions に移す（判断 4 の (c) だけ）**：決定表やプレモーテムのように、確立した名前の
  ある考え方まで conventions の決まりに見え、外の文献をたどれない。
- **移す項目を conventions の新しい参照の文書にまとめる**：どれも conventions にすでに持ち主の節（今の姿と理由の
  置き場所、項目の階層と地図、変更の扱い方、形式の文書の根）があり、二か所の定義になる。

## Consequences

- principles の各項目は、文献から元の考え方をたどれる。
- conventions の文書から、移したか外した項目のアンカー（`#present-state`、`#relation-kinds`、`#verify-procedures`、
  `#single-index`）へのリンクは、conventions の持ち主の節を指すか、その場に決まりを書く形に変わる。
