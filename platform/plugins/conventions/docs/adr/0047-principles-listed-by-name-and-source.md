# 0047. principles には名前と出典のあるものだけを載せ、出典のない項目は出典を足すか conventions に移す

## Context

principles の原則とパターンの一覧は、冒頭で「名前と出典があり、広く良いとされているものだけ」を載せるとしている。
全体のレビュー #283 の E は、この基準に合わない項目（原則：今と経緯を分ける、必要十分、確立した考え方に拠る。
パターン：状態を軸で洗い出す、失われうるものを先に挙げる、手順を実装と突き合わせる、一つの目的の小さな変更、
関係を種類で分ける、入口と唯一の一覧）と、出典の書き方のばらつき、原則の分類が MECE でないことを挙げた。B は、
principles が conventions の言葉（前提のリンク、在りかのリンク、索引）と置き場所を持つことを挙げた。判断 4 で、依頼者は
おすすめの (a) と (c) の組み合わせで進めると決めた（#284）。

## Decision

- 基準は保つ。基準に合わない項目は、次のどちらかにする。
  - 確立した名前と出典があれば、それを見出しと本文に足して残す：確立した考え方に拠る（A Pattern Language と
    Design Patterns）、必要十分（The Elements of Style と YAGNI）、状態を軸で洗い出す（Decision Table）、失われうる
    ものを先に挙げる（Pre-mortem、FMEA）、一つの目的の小さな変更（Small CLs）。
  - 出典が見つからず、このプロジェクト群の決まりとして持つものは、conventions に移す：今と経緯を分ける（文書の体系の
    「今の姿と理由の置き場所」が持つ）、関係を種類で分ける（文書の体系の「項目の階層と地図」が持つ）、手順を実装と
    突き合わせる（変更の扱い方の変更とパターンの表の行が持つ）。入口と唯一の一覧は、形式の文書の根の器の表が同じ
    決まりを持つので、外す。
- 出典は、原則では「原則」の行の、パターンでは「形」の行の終わりに「出典は …。」の形で書く。
- 原則の分類を、決め方、分割、依存と約束、階層と並び、一意さ、量と見せ方、進め方と確かめ方、守り方にする。
  パターンの「状態を軸で洗い出す」は変更の組み立てに移す。アンカーは変えない。
- principles から conventions の言葉と置き場所を外し、一般の言い方にする（依存関係の逆転の契約の置き場所は、使う側に
  届く契約を指す）。

## Alternatives

- **基準を「名前の付いた考え方（出典があれば添える）」に緩める（判断 4 の (b)）**：このプロジェクト群で決めたことと
  広く確かめられた考え方の区別がなくなり、principles が共有の核として小さく保てない。
- **出典のない項目をすべて conventions に移す（判断 4 の (c) だけ）**：決定表やプレモーテムのように、確立した名前の
  ある考え方まで conventions の決まりに見え、外の文献をたどれない。

## Consequences

- principles の各項目は、出典から元の考え方をたどれる。
- conventions の文書から、移した項目のアンカー（`#present-state`、`#relation-kinds`、`#verify-procedures`、
  `#single-index`）へのリンクは、conventions の持ち主の節を指すか、その場に決まりを書く形に変わる。
