# 0053. 量の上限を description にも当て、折り返せない行は折り返した行数で数え、どの作業でも全体まで読む文書には当てない

## Context

量の上限（ADR 0010、0049）は、いつも読み込まれる文書（`CLAUDE.md`、共通のルール、役割ごとの指示）の行数と、行の表示幅
130 を確かめていた。その狙いはいつも読み込まれる量を抑えることだが、次の三つが決まっていなかった（#308。PR #301 の
レビューの提案から積んだ）。

- どの作業でも始めに全体まで読む文書の体系に、上限を当てるか。ADR 0039 は「起点の量の検査を見直す変更で扱う」と
  先送りし、ADR 0049 の Alternatives に挙げて積んだ。
- 役割とスキルの frontmatter の `description` は、どのセッションでも一覧として読み込まれるのに、行数と幅の上限の外にある
  （このときいちばん長い harness スキルで幅 338）。載せきれないものを寄せる道が開いている。
- 表の行とコードブロックの行は折り返せないのに幅の上限が当たり、「折り返す」という直し方が使えない。表を箇条に組み直す
  しかない。

## Decision

- どの作業でも全体まで読ませる文書（共通のルールの「始めに読む」の節に並べた文書）には、量の上限を当てない。並べるかは、
  読むコストと、どの作業でも前提になる効果とを比べて決める。長くなったら、内容を失わないように分けるか組み直してよい。
  そのときは始めに読まれる範囲も変わる（分けた先を並べなければ、その中身はどの作業でも読まれなくなる）ので、分けた先の
  どれを並べるかも同じ比べ方で決め直す。届け方の決まりの起点の節に置く。
- 役割ごとの指示とスキルの `description` は、一行に畳んで表示幅を 390（行の幅の上限の 3 行分）までにする。幅の数え方は
  ADR 0049 と同じ。
- 表の行（字下げのあとの `|` で始まる行）とコードブロックの行（行の始めの HTML のコメントを含む。折り返せない行）には
  幅の上限を当てず、130 で折り返したときの行数（切り上げ）で行数に数える。伸ばした分は行数で数えるので、伸ばして収める
  抜け道にはならない。見分け方は、ほかの検査と同じコードの見分け方（ADR 0050）と行の始めの `|` にする。表でない `|` で
  始まる行や、行の始めの HTML のコメントも折り返せない行に入るが、行数で数えるので量は抑えられる。
- 後の二つは形式の量の上限に置き、check-docs の量の検査で確かめる。

## Alternatives

- **どの作業でも全体まで読む文書にも、行数の上限を当てる（共通のルールの「始めに読む」の節から対象を導き、合計 150 行）**：
  量の上限が効くのは、いつも読み込まれる文書が要約と案内
  （届け方）で、上限に当たったら定義へ移しても内容が失われないから。始めに読む文書は要約でなく定義（正典）で、上限に
  当たったときの直し方（減らす、移す、案内に下げる）を当てると、どの作業でも前提にすべき内容が読まれなくなりうる。
  入れるかは数ではなく、読むコストとその効果で決めるもの。ADR 0039 が文書の体系を解説と参照に分けたように、内容を
  失わない分割や再編で量を整える。
- **`description` を文字数で測る**：ADR 0049 が行で選ばなかったのと同じで、ほかの上限と数え方が変わる。
- **`description` の合計に上限を当てる**：一覧に並ぶ数は、どのプラグインを有効にするかでターゲットごとに変わり、一つの
  リポジトリの検査では決められない。一つずつに当てる。
- **`description` を 130（一行）までにする**：今の 13 のうち 11 が超え、使う場面（「〜ときに使う」）を書ききれなくなる。
- **折り返せない行を幅の上限から外し、行数も 1 と数える**：ADR 0049 が閉じた、行を伸ばして収める抜け道が、表とコードで
  また開く。
- **すべての行を 130 で折り返した行数で数え、幅の上限をなくす**：ADR 0049 が選ばなかった形で、折り返せる行が一行で読める
  幅に収まることを保てない。折り返せない行にだけ当てれば、そこではもともと保てないので失うものがない。

## Consequences

- 文書の体系の量は検査で守らない。始めに読むに並べるものを足すか、長くなった文書を分けるか、分けた先を並べるかは、変更と
  レビューで読むコストと効果から判断する。
- `description` は `description` の上限の中に収め、当たったら載せるものを減らすか、スキルや定義へ移す。今はすべて 390 の
  中にある。
- 起点の表をそのまま保てるようになり、表を箇条に組み直さなくてよい。表の長い行は、その分だけ行数を使う。
- conventions を使うほかのターゲットの、いつも読み込まれる文書と、その `.claude/agents/` と `.claude/skills/` の
  `description` も、この検査に掛かる。
