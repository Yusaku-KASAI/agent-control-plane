# 0023. 作る前に別の形を挙げ、PR の本文の決まった節に残して、レビューで問い直す

## Context

Issue #171：レビューで、一つ上の枠組みから問い直す指摘（観点「別の形」、拠り所は前提を問い直す）が出にくい。
#130 で数えると、14 件の PR の指摘 171 件のうち、観点「別の形」は 4 件で、どれも PR の中の手段の置き換えだった。目的や
枠組みまで遡る問い直しは、依頼者がしていた。

#171 の見立ては次の三つだった。

- 一人のレビュアーが 7 つの観点を一度に見るので、見つけやすい文書と正しさに寄る。
- レビュアーは差分と変更の意図を受け取り、選んだ枠組みの中で読む（アンカリング）。
- 枠組みの問い直しは作る前の方が安いが、変更した人が作る前に問い直したかは、記録にも検査にもない。

一つ目は、platform の ADR 0021 で、念入りの回し方と全体のレビューで観点ごとに読む人を分けた。既定の通常の回し方では、
トークンを抑えるため、一人がすべての観点で読む。

依頼者は、作る前に選ぶ形の理由を書かせるなら、ADR がその手順に含まれていないと指摘した。どの変更で ADR を書くかは、
変更を届ける手順にも変更とパターンの表にもなく、文書を書く手順の「理由は ADR に置く」だけだった。

## Decision

- 変更を届けるの 4 段を「形を選び、壊れうる場面を挙げる」にし、その始めに、ほかの形（目的に立ち返った別の手段、
  より単純な形、一つ上の枠組みでの解き方）を挙げ、選ぶ理由を決める、を足す。壊れうる場面を詰めたあとでは、形を
  捨てる費用が上がるため、その前に置く。
- 後から理由を知りたくなるか、間違えそうな判断なら、ADR にも書く。変更とパターンの表に、判断の記録のパターンを足し、
  4 段から案内する（ADR を書くかは、形を選ぶときの判断だから）。
- PR の本文に、決まった節 `## 検討した別の形` を `## 何を変えるか` の次に足す（書き方の「PR」）。挙げた形と選ばなかった
  理由を書き、挙がらなければ、別の形がない理由を書く。ADR があれば、その Alternatives へのリンクと一行の要約でよい
  （同じ中身を二か所に持たない）。`prctl create` と `prctl update` は、ほかの節と同じく、ないか空なら
  断る（platform の ADR 0012 を改める）。
- 観点「別の形」の探すものに、その節の選ばなかった理由が成り立つか、挙がっていない形がないかを足す。
- レビューを頼むときに渡すものに、検討した別の形を足す（依頼の内容、変更の意図、差分と合わせて四つ）。最初のレビューは
  PR を作る前で、本文をまだ読めないため。挙げた形と選ばなかった理由は、残すと決めた記録で、渡さない「たどった考え」
  （そのほかの試行や迷い）とは分ける。
- 選んだ形に引きずられないよう（アンカリング）、レビュアーは観点「別の形」で、差分と変更の意図を読む前に、依頼と Issue の
  目的だけから別の形を挙げ、そのあとで変更の意図と渡された形を読み、差分と照らす（レビューするの 2 段と 4 段）。
  いちばん強い引きずりの元は、選んだ形をそのまま表す差分と変更の意図なので、その前に挙げる。頼む人は、変更の意図と
  検討した別の形を頼む文の最後の見出しの下にまとめる（レビューを頼んで答えるの「頼む」の 3 段）。

## Alternatives

- **最初の PR 全体のレビューで、観点「別の形」だけを見るレビュアーを分ける**（#171 の案の一つ）：通常の回し方でも、PR ごとに
  サブエージェントが一つ増える。依頼者はトークンを抑えたいと考えていて、観点ごとに分けるのは念入りと全体のレビューに
  限った（platform の ADR 0021）。
- **作る前に、方針をサブエージェントに見せる段を足す**：別の目で問い直せるが、作る前にもう一往復増え、方針を文で
  まとめる手間もかかる。まずは変更した人が挙げて残す形で試す（[小さく試して確かめる](../../../principles/docs/reference/principles.md#small-experiments)。
  効かないときの扱いは #201）。
- **作る前に、依頼者に形の候補を見せて選んでもらう**：今この問い直しをしているのは依頼者なので、いちばん直接に効く。
  ただ、control-plane 経由ではターンの途中で聞いて待てず、依頼者はラリーを減らしたいと考えている。
- **ADR を書く場面を、文書を書く手順に足す**：文書を書く手順は、書くと決めた文書をどこにどう書くかの手順で、書くか
  どうかは、形を選ぶとき（変更を届けるの 4 段）に決まる。そこで引く変更とパターンの表に置いた。
- **節を任意にする**：書かれないことが多くなり、作る前に問い直したかが記録に残らない。決まった節にして、prctl で確かめる。

## Consequences

- どの PR の本文にも、節が一つ増える。小さな直し（番号の振り直しなど）でも、別の形がない理由を一行書く。
- 渡すものが一つ増え、頼む文が少し長くなる。
- 前に作った PR の本文は、次に `prctl update` で書き換えるときに、この節を足すまで断られる。
- 効き目（観点「別の形」の指摘が増えるか、依頼者の問い直しが減るか）は、まだ分からない。確かめることと、効かないときの
  次の手は #201 にある。
