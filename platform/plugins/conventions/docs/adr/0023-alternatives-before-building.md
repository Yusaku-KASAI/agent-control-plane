# 0023. 作る前に別の形を挙げ、PR の本文の決まった節に残して、レビューで問い直す

## Context

Issue #171：レビューで、一つ上の枠組みから問い直す指摘（観点「別の形」、拠り所は前提を問い直す）が出にくい。
#130 で数えると、14 件の PR の指摘 171 件のうち、観点「別の形」は 4 件で、どれも PR の中の手段の置き換えだった。目的や
枠組みまで遡る問い直しは、依頼者がしていた。

#171 の見立ては次の三つだった。

- 一人のレビュアーが 7 つの観点を一度に見るので、見つけやすい文書と正しさに寄る。
- レビュアーは差分と変更の意図を受け取り、選んだ枠組みの中で読む（アンカリング）。
- 枠組みの問い直しは作る前の方が安いが、変更した人が作る前に問い直したかは、記録にも検査にもない。

一つ目は、platform の ADR 0021 で、念入りの回し方と全体のレビューで観点ごとに読む人を分けた。既定の通常の回し方では、
トークンを抑えるため、一人がすべての観点で読む。

## Decision

- 変更を届けるの 5 段（作る）の始めに、選ぶ形のほかの形（目的に立ち返った別の手段、より単純な形、一つ上の枠組みでの
  解き方）を挙げ、選ぶ理由を決める、を足す。
- PR の本文に、決まった節 `## 検討した別の形` を `## 何を変えるか` の次に足す（書き方の「PR」）。挙げた形と選ばなかった
  理由を書き、挙がらなければ、別の形がない理由を書く。`prctl create` と `prctl update` は、ほかの節と同じく、ないか空なら
  断る（platform の ADR 0012 を改める）。
- 観点「別の形」の探すものに、その節の選ばなかった理由が成り立つか、挙がっていない形がないかを足す。レビュアーは、
  変更した人がたどった考えは受け取らないが、PR の本文は読むので、選んだ枠組みを問い直す手がかりになる。

## Alternatives

- **最初の PR 全体のレビューで、観点「別の形」だけを見るレビュアーを分ける**（#171 の案の一つ）：通常の回し方でも、PR ごとに
  サブエージェントが一つ増える。依頼者はトークンを抑えたいと考えていて、観点ごとに分けるのは念入りと全体のレビューに
  限った（platform の ADR 0021）。
- **作る前に、方針をサブエージェントに見せる段を足す**：別の目で問い直せるが、作る前にもう一往復増え、方針を文で
  まとめる手間もかかる。まずは変更した人が挙げて残す形で試し、別の形の指摘が増えないなら、この段を足す
  （[小さく試して確かめる](../../../principles/docs/reference/principles.md#small-experiments)）。
- **節を任意にする**：書かれないことが多くなり、作る前に問い直したかが記録に残らない。決まった節にして、prctl で確かめる。

## Consequences

- どの PR の本文にも、節が一つ増える。小さな直し（番号の振り直しなど）でも、別の形がない理由を一行書く。
- 前に作った PR の本文は、次に `prctl update` で書き換えるときに、この節を足すまで断られる。
- 効き目（観点「別の形」の指摘や、依頼者の問い直しが減るか）は、#130 と同じ数え方で、いくつかの PR のあとに確かめる。
