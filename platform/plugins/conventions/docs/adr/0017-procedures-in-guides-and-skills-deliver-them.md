# 0017. 手順はエージェントが使うものも `guides/` に定義し、スキルはそれを要約か案内で載せる

## Context

文書の体系は、プラグインでは、エージェントが使う手順を `guides/` ではなくスキルに置くとしていた。一方、定義と届け方
（ADR 0009、0010）は、スキルを定義の届け方として扱っていた。write-docs と design の手順はスキルにしかなく、スキルが
定義の置き場所になっていた。review スキルは、レビューの扱い方を出典にしつつ、道具の使い方と手順を持っていた。

ADR 0015 で、スキルを、使うと決めたときに丸ごと読み込まれる起点とし、起点には定義を要約か案内で載せるとした。
「（全体を読む）」で、起点から定義の文書を全体まで読ませることもできるようになった。

## Decision

- 手順は、エージェントが使うものも `guides/` に定義する。conventions の手順（文書を書く、パターンを当てはめる、
  レビューする）は `docs/guides/` に移す。
- スキルは、その手順への案内（「（全体を読む）」を付ける）と要約、そのプラグインの道具の使い方だけを持つ。

## Alternatives

- **スキルを手順の定義の置き場所にし、`guides/` には置かない（今のまま）**：スキルを届け方とする決まりと食い違い、
  人も同じ手順を読むときにスキルの中を探すことになる。
- **スキルに手順の全体を要約で持たせる**：同じ手順が二か所に書かれ、ずれる。「（全体を読む）」で全体を読ませられるので、
  要約は破られやすい数項目に絞る。

## Consequences

- スキルが手順への案内だけになるので、読み手がその先を読まないと手順が抜ける。「（全体を読む）」で全体が読まれるかは
  確かめていない（ADR 0015 と同じく、記録で確かめる）。
- スキルの description（いつ使うか）は変えていない。手順とスキルをどの場面で使うか、その範囲と階層は #123 で整理する。
- github、harness、slack のスキルは、そのプラグインの道具の使い方が中心なので、スキルに残す。
