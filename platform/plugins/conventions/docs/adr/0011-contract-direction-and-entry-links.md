# 0011. ハーネスの契約がターゲットの契約を前提にし、入口は索引と全体の解説の両方へつなぎ、届け方は決まりを持たない

## Context

文書全体を見直したところ、次のずれがあった。

- ターゲットの契約がハーネスの契約を前提にしていた。ハーネスの契約は、ターゲットのイメージ（ユーザー、ホーム）や
  ホストでの配置を言い換えて持っており、同じ事実が二か所にあった。
- README と CLAUDE.md の参照先は索引だけを指し、全体の解説（`docs/overview.md`）への道が決まっていなかった。
- レビューの答え方、CI の失敗の扱い、PR のタイトルの直し方などの決まりが、スキルや `prctl` のメッセージにだけあり、
  定義の文書になかった。
- リポジトリの CLAUDE.md と conventions の定義が食い違ったときにどちらに従うかが決まっていなかった。

## Decision

- 契約の中の向きを、ハーネスの契約 → ターゲットの契約 にする。ハーネスはターゲットのイメージで動くので、イメージと
  ホストでの配置はターゲットの契約が持ち、ハーネスの契約はそれを指す。ターゲットの契約からハーネスの契約へのリンクは
  案内にする。
- README と CLAUDE.md の参照先は、索引（`docs/README.md`）と全体の解説（`docs/overview.md`、あれば）の両方へつなぐ。
- 変更の進め方の決まり（変更とパターン、レビュー、検査と履歴）は conventions の `changes.md` が持ち、スキルと
  `prctl` はそれを指す。
- 届け方の例外として、役割ごとの指示は役割に固有の振る舞いを、スキルはそのプラグインの道具の使い方を、自分で持って
  よい（ADR 0010 の道具の扱いを、役割ごとの指示にも広げる）。
- リポジトリの決まり（CLAUDE.md）が conventions の定義と食い違うときは、リポジトリの決まりに従う。

## Alternatives

- **ターゲットの契約がハーネスの契約を前提にしたままにする**：イメージの事実がハーネスの契約にも要り、二か所に
  書くか、ターゲットの契約がハーネスの言葉に頼ることになる。ターゲットはハーネスより先に用意されるものなので、
  向きが逆になる。
- **入口からは索引だけを指す**：索引は在りかの一覧で、狙いや全体の構成はわからない。初めて読む人とエージェントが
  overview にたどり着くかが、索引の書き方しだいになる。
- **conventions の定義を優先する**：リポジトリごとの事情（公開の有無、互換）を CLAUDE.md で表せなくなる。

## Consequences

- 各ターゲットの README と CLAUDE.md の参照先に、全体の解説（あれば）へのリンクを足す。
- 決まりを足すときは、まず定義の文書に書き、スキルや要約には出典を示して写す。
