# 0042. パターンを当てはめる手順と design スキルをやめ、変更とパターンの表に使い方を置く

## Context

ADR 0017 で、パターンを当てはめる手順（`guides/design.md`）を共通の手順として置き、design スキルで届けることにした。
手順は 3 段で、中身は変更の扱い方の「変更とパターン」の表を引き、パターンの形を確かめ、設計とレビューに当てはめる
ことだった。変更を届けるとレビューするの 4 段は、その表を直に指していた。ADR 0020 の Consequences は、design の手順の
置き場所を見直していないとしていた。

全体のレビュー #283 の判断 9 で、依頼者はおすすめの (a) で進めると決めた（#284）。

## Decision

- 共通の手順のパターンを当てはめる（`guides/design.md`）と design スキルをやめる。
- 表の使い方（設計とレビューで、変更の種類から行を選び、パターンの形とよくある失敗を確かめて当てはめ、レビューでは
  名前と具体的な組み合わせで指摘する）を、変更とパターンの表の上に置く。
- 変更を届けるとレビューするの段、役割ごとの指示は、表を直に指す。

## Alternatives

- **今のまま（判断 9 の (b)）**：3 段の手順と一つのスキルが、一つの表への案内だけを持つ。読み手は手順とスキルを一段
  たどってから表に着き、表と手順の二か所に使い方がある。

## Consequences

- 設計するときに表を引くかは、変更を届けるの 4 段と、役割ごとの指示の要約に頼る。スキルの description からは届かなくなる。
