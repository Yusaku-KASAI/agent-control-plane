# 0030. 締めでは今の焦点から閉じた Issue だけを外し、ほかの課題のずれは直さず締めのまとめに書く

## Context

ADR 0025 は、締めでは今の焦点から閉じた Issue を外すことに限り、順番のずれは直さずに締めのまとめに書くと決めた。
そのあと ADR 0029 が、今の焦点には開いている Issue だけを `#<番号>` で並べると決め、PR やこのリポジトリにない番号も
今の焦点のずれになった。Issue のずれを機械で挙げる道具（GitHub を扱う区切りにある）は、開いている Issue 全体の
ずれを出すので、締める人が締めの範囲（このセッションが扱った Issue と今の焦点）の外のずれまで直しにいきうる（#234）。

## Decision

- 締めで直すのは、ADR 0025 のとおり、このセッションが扱った Issue と、今の焦点に残る閉じた Issue だけにする。
- 今の焦点のほかのずれ（順番、PR、このリポジトリにない番号）と、締めの範囲の外で整っている状態とのずれ（ほかの
  Issue のラベルなど）は、直さず締めのまとめの「人がすること」に書く。PR を外すと、それが閉じる開いている Issue まで
  今の焦点から消えうり、今の焦点の中身を変えることになる。直すのは課題を整える手順で、人が決めるものの扱いもそこに
  ある。

## Alternatives

- **締めで、今の焦点の PR をそれが閉じる Issue に書き換える**：PR と Issue の対応を締めのたびに判断することになり、
  締めの範囲が広がる。
- **締めで、気づいたずれをすべて直す**：締めが課題を整える手順を抱え込み、終わりが読めなくなる（ADR 0024 と同じ理由）。

## Consequences

- 締めのまとめの「人がすること」に、直さなかった課題のずれが並ぶ。続けて課題を整える手順を頼めば、そこで直る。
