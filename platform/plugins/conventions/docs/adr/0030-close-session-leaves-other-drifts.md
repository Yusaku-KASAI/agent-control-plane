# 0030. 締めでは今の焦点から閉じた Issue だけを外し、ほかの課題のずれは直さず締めのまとめに書く。今の焦点の PR は課題を整えるときに閉じる Issue に書き換える

## Context

ADR 0025 は、締めでは今の焦点から閉じた Issue を外すことに限り、順番のずれは直さずに締めのまとめに書くと決めた。
そのあと ADR 0029 が、今の焦点には開いている Issue だけを `#<番号>` で並べると決め、PR やこのリポジトリにない番号も
今の焦点のずれになった。Issue のずれを機械で挙げる道具（GitHub を扱う区切りにある）は、開いている Issue 全体の
ずれを出すので、締める人が、締めで直すと決めたもののほかのずれまで直しにいきうる（#234）。

## Decision

- 締めで直すのは、ADR 0024 と 0025 のとおり、このセッションが扱った Issue を閉じることと本文を書き直すこと、今の焦点に
  残る閉じた Issue を外すことだけにする。
- 今の焦点のほかのずれ（順番、PR、このリポジトリにない番号）と、ほかの整っている状態とのずれ（ラベル、blocked by
  など。このセッションが扱った Issue のものも含む）は、直さず締めのまとめの「人がすること」に書く。どのずれを直すか、
  どう直すかの判断は課題を整える手順に、人が決めるものの一覧は課題の扱い方の整っている状態の節に保ち（ADR 0025）、
  締めでどこまで直せば終わるかがその時の Issue の状態で変わらないようにするため。今の焦点の PR は、外すと、それが
  閉じる開いている Issue まで今の焦点から消えうるので、今の焦点の中身を変えることにもなる。
- 課題を整えるときは、今の焦点の PR をそれが閉じる開いている Issue に書き換え、このリポジトリにない番号は直すか外す。
  PR が開いている Issue を閉じないときは、閉じた PR なら外し、開いている PR は人が決めるもの（課題の扱い方の一覧）に
  する。外すと取りかかり中の作業が今の焦点から消え、どの Issue に書き換えるかは PR からは決まらないため。

## Alternatives

- **締めで、今の焦点の PR をそれが閉じる Issue に書き換える**：PR と Issue の対応を締めのたびに判断することになり、
  締めの範囲が広がる。
- **締めで、このセッションが扱った Issue のずれ（ラベル、blocked by）だけは直す**：扱った Issue に限れば範囲は
  読めるが、ずれの直し方と人が決めるものの判断が締めと課題を整えるの二か所に分かれる。
- **締めで、気づいたずれをすべて直す**：締めが課題を整える手順を抱え込み、どこまで直せば締め終わるかが、その時の Issue の
  状態で変わる。締めは、セッションの持ち越すものを残して片付けられる状態にする手順で、課題全体を整えるのは別の
  目的の手順（課題を整える）にある。

## Consequences

- 締めのまとめの「人がすること」に、直さなかった課題のずれが並ぶ。続けて課題を整える手順を頼めば、そこで直る。
