# 0024. push は、ほかの書き手のコミットを消さない形に決め、すべての push に当てる

## Context

一つのブランチに、ほかの書き手（人、ほかのセッション）が push することがある。control-plane 経由では既存の PR を
その PR の head ブランチで続ける（platform の ADR 0020）ので、スレッドの違うセッションが同じブランチに push する。
人が GitHub で提案を取り込んだときも同じ。

ほかの書き手が push したあとの push は断られるが、そのときの合わせ方は決まっていなかった。`--force` で押し切ると、
ほかの書き手のコミットが消える（#49）。一方で、レビューの指摘に答えて履歴を直すときなど、force push は要るので
止めない（#61）。

## Decision

- 変更の扱い方の「検査と履歴」に、push の決まりを場面ごとの表で置く。場面は、書き換えたか（push したコミットを
  別のコミットに置き換えたか）と、どの文面で断られたかで分ける。
- 書き換えていないのに `fetch first` か `non-fast-forward` で断られたら、`git pull --rebase` で取り込んでから push し
  直す。まだ push していないコミットに merge があれば `--rebase=merges` にする。
- 直しはできるだけコミットを足して行い、push したコミットを書き換えない。書き換えるのは自分のコミットだけにし、
  `--force-with-lease --force-if-includes` で push する。
- 書き換えた push が lease か includes で断られたら、書き換えた先頭を別の名前のブランチに残し、依頼者に返す。
- ほかの書き手がいるかによらず、すべての push に当てる。

## Alternatives

- **ほかの書き手がいるときだけに当てる**：push する側は、前もってブランチが共有されているかを知れない。自分だけの
  ブランチと思って `--force` すると、#49 と同じ形になる。共有されていなければ、lease は何も邪魔しない。
- **`--force-with-lease` だけにする**：取ってきたが取り込んでいないとき（バックグラウンドの fetch など）に、上書きが
  通る。`--force-if-includes` を添えると断られる。
- **まだ push していない merge があるときは `--no-rebase`（merge）で取り込む**：merge で解いた衝突をもう一度解かずに
  済むが、リモートが rebase と force push で書き換えられていると、書き換える前に push したコミットが merge で戻る。
  `--rebase` は remote-tracking ブランチの reflog から分かれた所を求めて、それを除く。
- **書き換えた push が断られたら、ほかの書き手のコミットを書き換えた履歴の上に載せる（cherry-pick、`rebase --onto`）**：
  戻して書き換え直すより手数が少ないが、リモートの先頭が手元の履歴に一度も入らないので、`--force-if-includes` に
  断られる。`--force-with-lease` だけにすれば通るが、上の守りを失う。
- **書き換えた手元のブランチにそのまま `pull --rebase` する**：書き換えで中身が変わらなければ、書き換えたコミットが
  捨てられる。変わっても元と重ならなければ、元のコミットの上に足される。重なれば衝突で止まる。前の二つは、黙って
  書き換えを失う。
- **書き換えた push が断られたら、書き換える前の先頭に戻して取り込み直し、書き換え直す**：自分で片付けられるが、
  別のブランチに残す、`reset --hard` で戻す、足したコミットを載せ直すと手数が多く、どこかを誤ると失う。取り込んだ
  あとに書き換え直すと、ほかの書き手のコミットを置き換えうる（先頭がほかの書き手のコミットのときの amend など）。
  lease も includes もそれを止めない。この場面は、書き換えている間にほかの書き手が push したときだけで、まれなので、
  書き換えたものを残して依頼者に返す。
- **ハーネスの契約に置く**：人が同じブランチに push するときも同じ場面になり、動き方によらない。
- **作業領域の pre-push フックで、ほかの書き手のコミットを消す push を断る**：読むことに頼らずに守れるかもしれないが、
  決まりを置くこととは別に確かめる（#200）。

## Consequences

- 取り込むときに、まだ push していない merge があると、その merge で解いた衝突をもう一度解く。
- 書き換えた push が断られると、依頼者に返る。書き換えたものは別のブランチに残る。
- `--force-if-includes` は git 2.30 から。
