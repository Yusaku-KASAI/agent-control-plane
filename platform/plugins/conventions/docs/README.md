# conventions

このプロジェクト群のリポジトリが共通で従う決まり：文書をどう分けて書くか、変更と課題をどう扱うか、設計で何を
当てはめるか。拠り所は principles プラグインの原則とパターンで、それ以外は前提にしない。

| 文書 | 種類 | 何があるか |
| --- | --- | --- |
| [overview.md](overview.md) | 解説 | このプラグインの構成と、エージェントへの届け方 |
| [architecture/documentation.md](architecture/documentation.md) | 解説 | 文書の体系：設計を記述する 3 層、区切りと依存の向き、各リポジトリの器、体系を作る部品 |
| [reference/formats.md](reference/formats.md) | 参照 | 文書の形式：構成要素の説明、ADR、リンク |
| [reference/writing.md](reference/writing.md) | 参照 | 書き方：コメント、コミット、PR |
| [reference/changes.md](reference/changes.md) | 参照 | 変更の扱い方：PR の流れと、変更の進め方 |
| [reference/issues.md](reference/issues.md) | 参照 | 課題の扱い方：Issue の分類、ロードマップ |
| [reference/glossary.md](reference/glossary.md) | 参照 | 文書と作業の言葉 |
| [adr/](adr/) | 判断 | 文書、変更と課題の決まりの判断 |

手順はスキルにある：文書を書く（[skills/write-docs](../skills/write-docs/SKILL.md)）、設計とレビューの観点（[skills/design](../skills/design/SKILL.md)）。
