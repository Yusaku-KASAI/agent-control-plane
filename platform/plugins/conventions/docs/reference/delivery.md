# 届け方の決まり

決まり（定義）を、共通のルール、役割ごとの指示、スキルに載せてエージェントと人に届けるときの決まりと、それらが案内する
手順の層の決まり。定義と届け方の仕組みは[文書の体系](../architecture/documentation.md#delivery "在りか")に、各文書の形は
[形式](formats.md "在りか")に、
判断の理由は ADR [0010](../adr/0010-always-read-selection-and-size.md)、[0015](../adr/0015-starting-points-and-reading-scope.md)、[0016](../adr/0016-summaries-guides-and-common-rules.md)、[0017](../adr/0017-procedures-in-guides-and-skills-deliver-them.md)、[0020](../adr/0020-scene-procedures-start-by-reading.md)、[0021](../adr/0021-purpose-procedures-and-triage.md)、[0022](../adr/0022-forms-of-procedures-and-role-instructions.md)、[0040](../adr/0040-no-read-whole-mark.md) にある。

<a id="summaries-and-guides"></a>

## 要約と案内

文書がほかの文書の中身に触れるときは、次のどちらかで書く。

| 書き方 | 書くもの |
| --- | --- |
| 要約 | リンク先の中身を短く言い直したもの。開かなくても分かり、守れるようにする |
| 案内 | 中身を言い直さず、どの場面で、どこを読むかだけ |

- リンクの種類（前提のリンクか在りかのリンクか）は、これとは別に[形式：リンク](formats.md#links "在りか")の決め方で
  決める。要約には、項目ごとに、要約が拠る文書（出典）へのリンクを付ける。出典が変わると要約の見直しが要るので、この
  リンクは前提のリンクになる。案内のリンクは、ふつう在りかのリンクになる。
- 全体（`overview.md`、索引）から子へは案内で書き、子の細部を要約しない。全体が自分の事実として持つ子の責務や一行の
  説明（構成要素の説明、索引の説明の列）は、子の要約ではない。
- 一般的な原則と、それをこのプロジェクト群で具体化した決まりがあるときは、具体化した決まりを要約にし、原則はその
  理由として添える。

<a id="starting-points"></a>

## 起点

起点は、エージェントがリンクをたどって選ぶのではなく、丸ごと読み込む文書。エージェントの入口（CLAUDE.md）、共通の
ルール、役割ごとの指示は作業の始めに、スキルは使うと決めたときに読み込まれる。人の入口（`README.md`）、索引、
全体は、読み手が選んでたどる文書で、起点ではない。

- 共通のルールに載せるのは、ほぼすべての作業に関わり、破られやすく、検査で守れない決まりだけ。特定の作業（文書を
  書く、変更を届ける）にだけ要る決まりは、その作業の手順（目的の手順か、共通の手順のスキル）や役割ごとの指示で届ける。
- 役割ごとの指示とスキルが principles と conventions の定義を載せるときは、同じ基準を、その起点の範囲（その役割の
  作業、その作業）に当てはめて、要約にするか案内にするかを選ぶ。起点が自分で持つもの（CLAUDE.md のリポジトリの
  決まり、役割に固有の振る舞い、スキルの道具の使い方）は、この選び方に限らない。
- 起点が自分で持つものと、ほかの定義の要約と案内が一つの文書に混ざるときは、節で分け、どの行がその起点だけの
  定義で、どの行が定義を変えたら直すものかを見分けられるようにする（役割ごとの指示の節の形は[形式](formats.md#role "在りか")）。
- 判断の軸になる決まりを、細かい作法より先に載せる。大事さは、起点に要約として書くことで表し、「大事」の印は付けない。
- 項目を作業の場面や関心ごと（始めに読む、決めるとき、書くときなど）の節に分け、一続きの段落や長い一つのリストに
  しない。読み込ませる起点（共通のルール）は、読み込ませるときに自分の在りかも示す。
- 作業の始めに読み込まれる起点は、[量の上限](formats.md#size "在りか")の中に収める
  （[必要十分](../../../principles/docs/reference/principles.md#sufficiency)）。

全体まで読ませる文書は、次のどれかで示す。ほかのリンクは、要るときにリンク先の節を読む。

| 読ませる場面 | 示し方 |
| --- | --- |
| どの作業でも（文書の体系） | 共通のルールの「始めに読む」の節に、条件を付けずに直に並べる。「変更するときは」のような前置きを付けると、読み手が自分の作業は当てはまらないと読み、飛ばしうる |
| 目的の手順に入ったとき | その手順の「始めに読む」の段に並べ、起点にはその段の文書を直に並べる（[目的の手順と共通の手順](#procedures)） |
| スキルを使うとき | スキルに、届ける手順を全体まで読んで沿うと書く |

<a id="procedures"></a>

## 目的の手順と共通の手順

手順（`guides/`）は、最大 2 層の階層にし、3 層目は作らない（[階層的分解](../../../principles/docs/reference/principles.md#hierarchy)）。
プラグインの `docs/guides/`（エージェントに届ける手順）に置く
手順は、どれもどちらかの層に入る。人が読む運用や準備の手順（リポジトリの `docs/guides/` など）は、この層の外に置いてよい。
それぞれの形は[形式：手順](formats.md#procedure "在りか")にある。

| 層 | 何の手順か | 例 |
| --- | --- | --- |
| 目的の手順 | 依頼者が何をしてほしいかの単位。依頼を受けてから終えるまでの全体で、いくつものターンやセッションにわたることがある | 変更を届ける、レビューするなど |
| 共通の手順 | 目的の手順の段の中で使う、作業の一部分。いくつもの目的の手順から使いうる | 文書を書くなど |

- 手順は依頼の目的で切り、ロール（役割）では切らない。ロールは、権限と隔離の境界（書けるもの、残せる所）で、使うモデルも
  持つ。手順とロールは多対多になり、どの目的の手順を受け持つかは役割ごとの指示の「受け持つ手順」の節に書く
  （[形式：役割ごとの指示](formats.md#role "在りか")）。振り分けとロールの指示が食い違うときは、ロールの指示に従う。
- 目的の手順は、段の中で、その段で使う共通の手順を案内する。共通の手順は、目的の手順を前提にせず、ほかの手順を案内しない。
- 決まりとして守る順序も手順に置く。参照の文書は、手順の段が使う決まり（条件、表、形）を持ち、順序は持たない。
- 依頼を受けたら、まずどの目的の手順に当たるかを決める（振り分け）。目的の手順のない依頼（事実を聞く質問など）は、
  依頼に沿って進める。作業の途中で目的が変わったら（相談から変更へなど）、その目的の手順に入り直す。
- 目的の手順は一つのターンで終わるとは限らない（追加の依頼、レビューの指摘への答え、CI の失敗）。
  どこからを新しい依頼として振り分けから入るかは、各目的の手順に書く。
  続きのターンでは、今どの段にいるかを確かめてそこから進める。会話の記録がない新しいセッションで続きから入るときと、
  ほかの作業の途中からその目的の手順に入るときは、「始めに読む」から始める。
- 目的の手順の最初の段は「始めに読む」にし、その手順で全体まで読む文書を並べる。並べるのは、その手順の多くの段で
  判断の軸になる文書だけにし、一つの段でだけ使う文書は、その段で案内する。

起点への並べ方：

- 起点（共通のルール、役割ごとの指示）は、目的の手順と、その「始めに読む」の段の文書を、最初に全体まで読むものとして、
  出典（その段）付きの要約で直に並べる。手順を指すだけにすると、読む文書が一段たどった先になり、読まれにくい。
- 共通のルールの振り分けの節には、すべての目的の手順を並べる。そのうち「始めに読む」の段の文書まで直に並べるのは、
  ロールの指示を通らずに入ることが多い手順（変更を届ける）だけにする。ほかは、主に使うロールの指示に直に並べ、振り分け
  からはスキルへの案内で届ける。どのロールも主に使わない手順は、ロールの指示からもスキルへの案内で届ける。
- スキルは、共通の手順への入口として、使うと決めたときに読み込まれる。そのロールで動いていない人が目的の手順に入るとき
  （たとえば役割を持たないセッションがレビューを頼まれたとき）の入口にもなる。

目的の手順を足したり、ロールの受け持ちや「始めに読む」の段を変えたりしたら、それを並べた所を直す：共通のルールの
振り分け、各ロールの「受け持つ手順」と description、conventions の索引と、スキルを足すか消すときは全体像のスキルの表。
ほかの文書（ロールの全体像、用語集の例など）は、手順の一覧や受け持ちを書き写さず、指示の節や索引への案内にする。
どの文書も索引から届くことは検査が確かめる。ほかは特定の節に何を並べるかで中身なので、検査にせず（[形式：検査の範囲](formats.md#check-scope)）、
変える人とレビューする人がここから直す所を挙げる。
