# 用語集（文書と作業）

文書、変更、課題、レビューの決まりで使う言葉。ほかの言葉は、それを使う区切りの用語集にある。

| 言葉 | 意味 |
| --- | --- |
| 区切り | 知識を、使う人（誰が読めるか）と持ち主で分けた最上位の項目。Bounded Context に当たる |
| 文書の根 | 区切りごとの文書の置き場所。`README.md` を持つ `docs/` ディレクトリ |
| 共有の核 | ほかのすべての区切りが前提にしてよい区切り。principles と conventions |
| 契約 | 区切りの間で受け渡すものの約束。使う側から読める場所に置く |
| 文書の種類 | 解説（今の姿）、手順（目的を果たす手順）、参照（引くための事実と決まり）、判断（ADR）の 4 つ（[文書の体系](../architecture/documentation.md#types "在りか")） |
| 入口 | 最初に読まれる文書。人には README.md、エージェントには CLAUDE.md |
| 索引 | 文書の根の唯一の一覧（`docs/README.md`） |
| 原則 / パターン | 原則は何を大事にするか、パターンはそれを特定の問題への形にした解き方 |
| 構成要素の説明 | アーキテクチャの文書で、構成要素ごとに責務、置くもの / 置かないもの、関係、当てはめた原則・パターンを書いたもの |
| 項目 | 地図に載る単位。区切り、契約、その中の部品（プラグイン、話題の文書など）。入れ子になる |
| 前提にする | 相手の中身が変わったら、こちらも見直しが要る関係。依存の向きの決まりはこの関係に当てる |
| 在りかを示す | 相手の在りかを示すだけの関係（索引から各文書へのリンク、タイトル「在りか」のリンクなど）。相手の中身が変わっても、在りかが変わらなければ直さなくてよい。依存ではない |
| 地図 | ある階層の項目と、その間の前提の向き。階層ごとに書く |
| 全体 | 子を持つ項目が直接持つ文書（overview、索引、全体の解説）。子と並ぶ項目として扱い、子から前提にされ、子を前提にしない |
| 定義 | 決まりそのもの。原則とパターン（principles）、このプロジェクト群の決まり（conventions の `docs/`）、区切りの間の契約。一つの決まりは一か所でだけ定義する（[定義と届け方](../architecture/documentation.md#delivery "在りか")） |
| 届け方 | 定義を、効く形でエージェントや人に届けるもの。検査、共通のルール、役割ごとの指示、スキル。新しい決まりを足さない。文書の届け方（共通のルール、役割ごとの指示、スキル）は定義を要約か案内で載せる（例外は[定義と届け方](../architecture/documentation.md#delivery "在りか")にある） |
| 出典 | 要約が拠る文書。要約の項目ごとに、その文書への前提のリンクを付ける（[要約と案内](../architecture/documentation.md#summaries-and-guides "在りか")） |
| 共通のルール | 毎回の作業の前に読み込ませる届け方。定義を要約か案内で載せる。プラグインの `rules/` の文書で、hook が読み込ませる。載せるのは、ほぼすべての作業に関わり、破られやすく、検査で守れない決まりだけ |
| 起点 | エージェントがリンクをたどって選ぶのではなく、丸ごと読み込む文書。エージェントの入口（CLAUDE.md）、共通のルール、役割ごとの指示、スキル（[起点](../architecture/documentation.md#starting-points "在りか")） |
| 要約 | ほかの文書の中身を短く言い直して書いたもの。出典への前提のリンクを付ける（[要約と案内](../architecture/documentation.md#summaries-and-guides "在りか")） |
| 案内 | ほかの文書の中身を言い直さず、どの場面で、どこを読むかだけを示すもの |
| 読む範囲 | リンクの直後の「（全体を読む）」で示す、その場面でリンク先をどこまで読むか。付けなければ、要るときにリンク先の節を読む（[読む範囲](../architecture/documentation.md#reading-scope "在りか")） |
| 役割 | エージェントの用語集の「ロール」と同じ意味（[エージェントの用語集](../../../../docs/reference/glossary.md "在りか")）。developer、guide、reviewer など |
| 役割ごとの指示 | 役割ごとに、その役割で動くエージェントに読み込ませる指示。プラグインの `agents/` の文書（Claude Code のカスタムエージェントの定義）で、役割に固有の振る舞い（「固有の振る舞い」の節）と、その役割で使う決まりとスキルの要約と案内（「使う決まり」の節）を持つ |
| 差分のレビュー | 一つの変更（PR の差分）を、取り込む前に別の目で確かめること（[レビューの扱い方](reviews.md#kinds "在りか")） |
| 全体のレビュー | 地図の項目を範囲にして、今の姿全体を見直すこと。監査とも呼ぶ（[レビューの扱い方](reviews.md#kinds "在りか")） |
| 観点 | レビューで何を探すかの切り口。関心で分ける（[観点](reviews.md#perspectives "在りか")） |
| 指摘 | レビューで見つけた問題。決まった形で書く（[指摘](reviews.md#findings "在りか")） |
| 量の上限 | いつも読み込まれる文書（ルートの `CLAUDE.md`、共通のルール、役割ごとの指示）の行数の上限（[形式](formats.md#size "在りか")） |
