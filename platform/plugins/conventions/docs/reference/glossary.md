# 用語集（文書と作業）

文書、変更、課題、レビューの決まりで使う言葉。ここは言葉の意味だけを持つ。決まりの在りかは、置き場所と関係、届け方、
手順と役割なら[文書の体系](../architecture/documentation.md "在りか")から、変更と課題とレビューなら[索引](../README.md "在りか")からたどる。
ほかの言葉は、それを使う区切りの用語集にある。

## 置き場所と関係

| 言葉 | 意味 |
| --- | --- |
| 区切り | 知識を、使う人（誰が読めるか）と持ち主で分けた最上位の項目。Bounded Context に当たる |
| 共有の核 | ほかのすべての区切りが前提にしてよい区切り。principles と conventions |
| 契約 | 区切りの間で受け渡すものの約束 |
| 項目 | 地図に載る単位。区切り、契約、その中の部品（プラグイン、話題の文書など）。入れ子になる |
| 全体 | 子を持つ項目が直接持つ文書（overview、索引、全体の解説）。地図では子と並ぶ項目として扱う |
| 地図 | ある階層の項目と、その間の前提の向き。階層ごとに書く |
| 前提にする | 相手の中身が変わったら、こちらも見直しが要る関係。依存の向きの決まりはこの関係に当てる |
| 在りかを示す | 相手の在りかを示すだけの関係（索引から各文書へのリンク、タイトル「在りか」のリンクなど）。相手の中身が変わっても、在りかが変わらなければ直さなくてよい。依存ではない |
| 文書の根 | 区切りごとの文書の置き場所。`README.md` を持つ `docs/` ディレクトリ |
| 文書の種類 | 文書を、読み手の目的で分けた種類。解説、手順、参照、判断 |
| 入口 | 最初に読まれる文書。人には README.md、エージェントには CLAUDE.md |
| 索引 | 文書の根の唯一の一覧（`docs/README.md`） |
| 原則 / パターン | 原則は何を大事にするか、パターンはそれを特定の問題への形にした解き方 |
| 構成要素の説明 | アーキテクチャの文書で、構成要素ごとに責務、置くもの / 置かないもの、関係、当てはめた原則・パターンを書いたもの |

## 届け方

| 言葉 | 意味 |
| --- | --- |
| 定義 | 決まりそのもの |
| 届け方 | 定義を、効く形（検査、共通のルール、役割ごとの指示、スキル）でエージェントや人に届けるもの |
| 共通のルール | 毎回の作業の前に読み込ませる届け方。プラグインの `rules/` の文書で、hook が読み込ませる |
| 起点 | エージェントがリンクをたどって選ぶのではなく、丸ごと読み込む文書 |
| 要約 | ほかの文書の中身を短く言い直して書いたもの |
| 案内 | ほかの文書の中身を言い直さず、どの場面で、どこを読むかだけを示すもの |
| 出典 | 要約が拠る文書 |
| 量の上限 | いつも読み込まれる文書と、どの作業でも始めに全体まで読む文書の行数と行の表示幅、役割とスキルの `description` の表示幅の上限 |

## 手順と役割

| 言葉 | 意味 |
| --- | --- |
| 目的の手順 / 共通の手順 | 目的の手順は、依頼者が何をしてほしいかの単位で、依頼を受けてから終えるまでの手順（変更を届けるなど）。共通の手順は、目的の手順の段の中で使う、作業の一部分の手順（文書を書くなど） |
| 振り分け | 依頼を受けたら、どの目的の手順に当たるかを決めること（トリアージ）。依頼を受け取ること自体ではなく、受け取った依頼の目的を決めること |
| 役割 | 権限と隔離の境界。書ける範囲（作業領域、PR、PR のレビュー、Issue のうち何を書けるか）と、受け持つ目的の手順と、使うモデルを持ち、役割ごとの指示で定める。手順とは多対多。エージェントの用語集では「ロール」と呼ぶ |
| 役割ごとの指示 | 役割ごとに、その役割で動くエージェントに読み込ませる指示。プラグインの `agents/` と、リポジトリの `.claude/agents/` のうちロールの定義（Claude Code のカスタムエージェントの定義） |

## 変更と課題

| 言葉 | 意味 |
| --- | --- |
| 依頼の範囲 | 変更の依頼（と、決める Issue、確かめる Issue）で、取りかかる前に決める、範囲の中（扱うもの）と範囲の外（扱わないもの）。差分の範囲（コミットからコミットまで）や全体のレビューの範囲（地図の項目）とは別 |
| キャンバス | 相談や壁打ちで、考えを会話の外に置いて積み上げる Issue |
| 締め | セッションで作業した人が、このセッションの開いている PR がなくなったうえで、持ち越すものを Issue に残し、残す理由のうち自分で解けるものを解いて、締めのまとめを答えること。セッションを消すこととは別で、締めたセッションも続けられる |
| 残す理由 | 締めるときに、セッションの作業を置いた所（作業領域）を消すのを止めているもの。消すと失われるものと、まだ依頼がありうる作業 |

## レビュー

| 言葉 | 意味 |
| --- | --- |
| 差分のレビュー | 一つの変更（PR の差分）を、取り込む前に別の目で確かめること |
| 全体のレビュー | 地図の項目を範囲にして、今の姿全体を見直すこと。監査とも呼ぶ |
| 回し方 | 変更した人が頼む差分のレビューを、どう回すか。通常（既定）と念入りがある |
| 観点 | レビューで何を探すかの切り口 |
| 指摘 | レビューで見つけた問題 |
