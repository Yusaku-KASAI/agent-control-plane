# 書き方

コード中のコメント、コミットメッセージ、PR に何を書くかと、理由の置き場所。文書の形は[形式](formats.md "在りか")に
ある。どの言語で書くかは、リポジトリの CLAUDE.md が決める。

<a id="reasons"></a>

## 理由の置き場所

理由は、種類ごとに次の所に書く（[今と経緯を分ける](../../../principles/docs/reference/principles.md#present-state)、[ADR 0041](../adr/0041-reasons-by-kind.md)）。

| 理由 | 置き場所 |
| --- | --- |
| 守らないと壊れる制約の理由（なぜその順か、なぜそれを避けるか） | 今の姿として、その制約のそばに一文で書く（コメント、文書。参照の文書も含む） |
| 選んだ理由と、選ばなかった案 | ADR |
| 変更の理由と経緯 | コミットメッセージと PR |

<a id="comments"></a>

## コード中のコメント

- コードは自己説明的に書き、コメントはできる限り削る。コードから読み取れることは書かない。
- コメントに残すのは、コードで表しきれない制約や、その理由だけ（[理由の置き場所](#reasons)）。
- 構成、方針、使い方はコメントではなく文書に書く。コメントが大きくなるようなら、文書か ADR に移す。
- 変更の履歴や以前の姿は書かない。

<a id="commits"></a>

## コミットメッセージ

- 1 行目に、何をしたかを一文で書く。
- 本文に、なぜそうしたか（変更の理由と経緯）を書く。コードと文書には今の姿だけを書くので、変更の理由と経緯はここに残す。

<a id="pull-requests"></a>

## PR

| | 答えること | 読み手 |
|---|---|---|
| タイトルと本文 | この PR は今何か：何をなぜ変えるか、検討した別の形、当てはめた決まり、どう確かめたか、確かめていないこと、残っていること | 初めて開く人 |
| コメント | 前回からの変更：この push で何をなぜ変えたか | 前回までを読んだ人 |

- 本文は、次の節をこの順に一度ずつ持ち、どれも空にしない。節の中は自由に書く。ほかの節（残っていることなど）は、
  どこに足してもよい。見出しのない `Closes #<番号>` などの行と署名の行は、節の中身に数えない。

  | 節 | 書くこと |
  | --- | --- |
  | `## 何を変えるか` | 何をなぜ変えるか |
  | `## 検討した別の形` | 選んだ形のほかに考えた形（目的に立ち返った別の手段、より単純な形、一つ上の枠組みでの解き方）と、選ばなかった理由。挙がらなければ、別の形がない理由。ADR があれば、その Alternatives へのリンクと一行の要約でよい |
  | `## 当てはめた決まり` | 判断の軸にした原則、パターン、決まりの名前と、それぞれをどこにどう当てはめたか |
  | `## どう確かめたか` | 検査、レビュー、手で試したこと |
  | `## 確かめていないこと` | 確かめていないこと。なければ「なし」と書く |

- 本文は、ブランチの今の中身を説明し続ける。追記せず、今のブランチの姿に合わせて書き換える。経緯はコメントと
  コミットメッセージに任せる。
- タイトルも本文と同じく今の PR 全体を表す。範囲が広がったり変わったりしたら直す。
- push で中身が変わったら、本文を書き換え、コメントを書く。コメントには理由を書く。
- PR が Issue を閉じるときは、本文に `Closes #<番号>` と書く。依頼の Issue を閉じないとき（[依頼の範囲](issues.md#scope)で、範囲の中の残りか積んだ指摘が残るとき）は、`Refs #<番号>` と書く。
- ほかの PR に重ねた PR（[変更](changes.md#changes)）は、本文に、どの PR の上かと、マージの順（下から）を書く。
