# レビュー

- 自分の変更のレビューを頼むときと、指摘に答えるときは、部品の手順の
  [レビューを頼んで答える](../../docs/guides/request-review.md "在りか")（全体を読む）に沿う。
- 頼まれて差分や全体をレビューするときは、場面の手順の[レビューする](../../docs/guides/review.md "在りか")（全体を読む）に
  沿う。その 1 段で、文書の体系とレビューの扱い方を全体まで読む。

要約すると：

- 自分が変更した差分は、自分では見ずにサブエージェント（reviewer ロールがあればそれ）に渡す。渡すのは、レビューする
  手順とその始めに読む文書の在りかと、結果を返し GitHub には残さないことのほか、依頼の内容、変更の意図、差分の三つだけ（[レビューを頼んで答える](../../docs/guides/request-review.md)の 2 段）。
- 選んだ観点を結果に書く（[観点](../../docs/reference/reviews.md#perspectives)）。
- PR のレビューの残し方と、指摘への答え方は github スキルにある（ほかの人の PR は「ほかの人の PR と既定のブランチを
  読む」）。
