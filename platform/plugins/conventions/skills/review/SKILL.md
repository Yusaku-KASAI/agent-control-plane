# レビュー

差分のレビューと全体のレビューの手順。決まりは[レビューの扱い方](../../docs/reference/reviews.md "案内")にある。

## 差分のレビュー

1. 依頼の内容、変更の意図、差分を集める。自分が変更した差分なら、自分では見ずにサブエージェントに渡す。
   渡すのはこの三つだけにする（[差分のレビュー](../../docs/reference/reviews.md#diff)）。
2. 差分と、それが前提にする所、それを前提にする所を読み、関わる観点を選ぶ（[観点](../../docs/reference/reviews.md#perspectives)）。
   正しさの観点では design スキルを、設計の観点では principles スキルを使う。
3. 指摘を決まった形で書く（[指摘](../../docs/reference/reviews.md#findings)）。

## 指摘に答える

指摘のあったところで、直したならどのコミットで直したかを、直さないなら理由を書く（[差分のレビュー](../../docs/reference/reviews.md#diff)）。
PR のレビューコメントへの返し方は github スキルにある。

## 全体のレビュー

[全体のレビュー](../../docs/reference/reviews.md#audit)の 7 段に沿って進める。このスキルが足すのは、各段の道具の使い方。

1. **範囲と観点を決める**：地図は `python3 tools/check-docs.py --map` で一覧できる。前回からの決まりの変更は、
   前回の直しの PR のマージより後の、principles と conventions の `git log` で見る。
2. **検査を回す**：`make check`。
3. **範囲ごとに読む**：範囲ごとにサブエージェントを分ける。各サブエージェントには、範囲、観点、指摘の形
   （[指摘](../../docs/reference/reviews.md#findings)）を渡し、ファイルを変えないよう頼む。
4. **指摘を確かめる**：戻ってきた指摘を、自分で元の文書とコードを開いて確かめる。
5. **まとめる**：分類ごとの直し方の案と、判断が要る点（選択肢とおすすめ）に分ける。
6. **報告して直す**：報告し、答えを受けてから、一つの目的ごとの PR で直す。
7. **仕組みに戻す**：検査を足せる指摘は、`tools/check-docs.py` などに検査を足す PR にする。
