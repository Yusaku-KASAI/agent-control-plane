# 共通のルール：コメントとドキュメント

どのリポジトリでも守るルール（conventions プラグインが常に読み込ませる）。リポジトリの CLAUDE.md と食い違う
ときは CLAUDE.md に従う。

コメント、コミット、PR についてはここが持ち主。文書についてはいつも守らせたいことの要約で、中身は conventions
プラグインの文書（文書の体系、形式、作業の進め方）と、principles プラグインの原則とパターンにある。

## コメント、コミット、PR

- コードは自己説明的に書き、コメントはできる限り削る。コメントに残すのは、コードで表しきれない制約や理由だけ。
- 構成、方針、使い方はコメントではなく文書に書く。コメントが大きくなるようなら、文書か ADR に移す。
- 変更の理由や経緯は、コミットメッセージと PR に書く。

## 文書（要約）

- 同じ事実は一か所にだけ書き、ほかはリンクする（原則：SSOT）。
- 今の姿だけを書く。変更履歴、以前の姿、試して捨てた案、日付付きの観測は書かない。直すときは追記せず書き換え、
  古くなった説明は消す（原則：今と経緯を分ける）。
- 一つの言葉は一つの意味で使う。複数の意味に取れる言葉は使う前に定め、その言葉を定める区切りの用語集に従う
  （原則：ユビキタス言語と用語集）。
- 書く前に、区切り、種類、持ち主を決める。判断と選ばなかった案は ADR に書く（手順：文書を書く）。
- これらを守るためなら、文書とコメントは破壊的に変えてよい。散らばった説明をまとめ直す、置き場所を移す、
  ディレクトリ構成を変えることも含む（文書の体系の「書き換え」）。
