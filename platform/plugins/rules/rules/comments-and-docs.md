# 共通のルール：コメントとドキュメント

どのターゲットでも守るルール（platform の rules プラグインが読み込ませる）。ターゲットの CLAUDE.md と
食い違うときは CLAUDE.md に従う。文書をどう分け、どこに置くかは platform の `docs/architecture/documentation.md` に、
原則は `docs/reference/principles.md` にある。

- コードは自己説明的に書き、コメントはできる限り削る。コードから読み取れることは書かない。
  コメントに残すのは、コードで表しきれない制約や理由だけ。
- メタ的な説明（構成、方針、使い方など）はコメントではなく通常のドキュメントに書く。コメントが大きく
  なるようなら、通常のドキュメントか ADR に移す。
- 一つの言葉は一つの意味で使う。複数の意味に取れる言葉（PR の「head」がブランチかコミットか、など）は、
  使う前に定める。区切りをまたぐ言葉は platform の用語集に従う。
- シングルソースにする。同じ事実を複数の場所に書かず、責務を持つ場所に一つだけ置いて他からは参照する。
- コメントと通常のドキュメントには現状だけを書く。変更履歴、以前の姿、試して捨てた案、日付付きの
  観測は書かない。
- 情報はそれぞれの責務を持つ場所に置く。そこにあるべきでないものは、ふさわしい場所に移すか、
  不要なら消す。
  - コードで表しきれない制約や理由：コード中のコメント
  - 現状の仕組みや方針：通常のドキュメント
  - 判断とその代替案・理由（また間違えそうなもの、現状を理解するのに必要なもの）：ADR
  - それ以外の変更理由や経緯：コミットメッセージや PR
- 編集するときは追記ではなく書き換える。古くなった説明は消す。
- これらのルールを守るためなら、ドキュメントとコメントは破壊的に変えてよい。散らばった同じ説明を一か所に
  まとめ直す、置き場所を移す、ディレクトリ構成を変える、といった大きな書き換えも含む。
