# 0025. 手順を受け持てるかは、その手順の目的を書ける範囲で果たせるかで決める（guide は相談に乗るを受け持ち、締めは受け持たない）

## Context

ADR 0019 は、ロールが手順を受け持つかを、そのロールの書ける範囲でその手順を終えられるか（結果を残せるか）で決めた。
guide は GitHub に何も書かない。guide の指示では、セッションを締めるは受け持たず（1〜3 段に沿い、残すのは pm に回す）、
相談に乗るは受け持つ（キャンバスは回答に書いて pm に回す）。どちらも Issue に書く段を持つのに扱いが違い、その理由が
conventions の ADR 0025 にも書かれていなかった（#213）。

三つの手順（相談に乗る、セッションを締める、課題を整える）は、どれも答えること（まとめ）で終わると冒頭に書き、
どれも書けないものを答えやまとめに書いて人に渡す扱いを持つ。終わり方や、書けないときの扱いがあるかでは、違いが
出ない。

## Decision

- 手順を受け持てるかは、その手順の目的（依頼者が求める結果）を、書ける範囲で果たせるかで決める。書く段の結果が
  目的そのものなら、書けないロールは受け持たない。書けないものを人に渡す扱いは、目的を果たせるロールが、一部を
  書けないときのためのもの。書く段が目的に添えるもので、書けないときの扱いを手順が持つなら、書けなくても受け持てる。
- 相談に乗るの目的は、考えを返すこと（6 段）。キャンバスに残す 5 段は、何回かにわたるときなどに考えを後に残すための
  条件付きの段で、書けないときは残す中身を答えに書いて書けるロールに回すと手順が決めている。guide は相談に乗るを
  受け持つ。
- セッションを締めるの目的は、持ち越すものを Issue に残して失わないこと（4 段）で、課題を整えるの目的は、Issue と
  ロードマップを整っている状態に合わせること（5 段）。どちらも書く段の結果が目的そのものなので、Issue に書けない
  guide は受け持たず、その手前の段に沿って回す。

## Alternatives

- **相談に乗るも締めと同じ形にそろえ、guide は受け持たない（1〜4 段と 6 段に沿い、pm に回す）**：相談の多くはキャンバスに
  残さずに答えで終わり、guide の責務（質問と相談に答える）そのものに当たる。受け持たないと書くと、答えることまで
  回す先に任せるように読める。
- **書く段に条件が付くか、書けないときの扱いを手順が持つかで決める**：締めの 4 段と課題を整えるの 5 段も、書けない
  ものをまとめに書いて人に渡す扱いを持つので、三つの手順のどれも受け持てることになり、相談と締めを分けられない。
- **相談に乗るの 5 段を、書けるロールでだけ行う段に分ける**：段の中に、書けないときの扱いがすでにある。段を分けると、
  手順がロールで切れることになる（conventions の ADR 0021）。

## Consequences

- この決め方は、書ける範囲の違いで受け持ちが分かれる手順（ここで比べた三つ）に当てる。レビューするの受け持ちは、差分を
  読む所を別の目のために分けたロールに頼む決め方（ADR 0019）のままで、guide は受け持たない。
- pm も同じ決め方で読める。pm は締めを受け持つ。目的の持ち越すものは Issue に残せ、作業領域に
  書く 6 段は、片付けを止めているもののうち自分で解けるものを解く段で、ほかは人が解くものとしてまとめに書く。
