# 0016. ファイルを変えないロールは自分の worktree で動かし、サブエージェントの間の作業領域の変化を知らせる

## Context

レビューのサブエージェントが試しに動かしたコマンドが、作業領域の一番上にファイルを作った。セッションの
エージェントの `git add -A` でそれがコミットに入り、依頼者が見つけた。レビューのサブエージェントが作業領域を
detached HEAD にしたことも 2 回あった（Issue #141 の A5、Issue #143）。reviewer ロールは「作業領域のファイルと HEAD を
変えない」と決めているが、頼むたびに依頼文で念を押していた。

作業領域でコミットし push するのはセッションのエージェントで、そのコミットは作業ツリーの中身から作る。サブエージェントが
残した変更は、エージェントが自分の変更と見分けないかぎりコミットに紛れる。

一方で、サブエージェントに作業を任せて作業領域を編集させるのは、ふつうの使い方である。レビューでも、試すための
編集や検査は要る。守りたいのは、作業領域を変えてはいけないサブエージェントが変えないことと、変わったときに
セッションのエージェントが気づくことである。

Claude Code のカスタムエージェントの定義（frontmatter）は、`isolation`、`hooks`、`tools`、`disallowedTools`、
`permissionMode` などを持てる。`isolation: worktree` のエージェントは、リポジトリの `.claude/worktrees/` の下の自分の
worktree で動く。hook の入力は、サブエージェントのツールの呼び出しにだけ `agent_id` を持つ（2.1.292 で確かめた）。

## Decision

- **ファイルを変えないロール（reviewer、guide）は、定義に `isolation: worktree` を持つ。** サブエージェントとして
  動くときは自分の worktree で動き、試すための編集や検査もそこで行う。作業領域には触れない形にする。どのロールが
  作業領域を変えてよいかはロールの性質なので、ロールの定義に置く。
- **harness プラグインの hook（`scripts/watch-tree`）は、control-plane 経由のとき、セッションのエージェントが動かす
  サブエージェントの前後で作業領域を比べ、変わっていれば何が変わったかを知らせる。** どのサブエージェントも止めない。
  比べるのは HEAD、ブランチ、index、stash、変更のあるファイルと追跡していないファイル（ignore されたものと、作業領域の
  中の linked worktree は除く）の中身。任せた変更でも、手段（リダイレクトやスクリプトの中など）によらず、何が
  変わったかがセッションのエージェントに届く。
- **control-plane は、作業領域の `.git/info/exclude` に `/.claude/worktrees/` を書く。** `isolation: worktree` の worktree が
  変更を持ったまま残ると、作業領域の追跡していないファイルに見え、push の前の検査のフック（control-plane の ADR
  0032）が push を断るため。ターゲットの `.gitignore` は変えない。
- review の手順に、範囲のファイルを `git diff --stat` で先に確かめることと、レビューするリポジトリを変えず、試すなら
  その外を使うことを書く。変更の進め方に、コミットの前に `git status` で入れるファイルを確かめることを書く。

## Alternatives

- **決まりと依頼文の念押しのままにする**：決まりはあって、破られた（仕組みで守る）。
- **harness の hook で、サブエージェントが作業領域を変える Edit、Write、git のコマンドをすべて断る**：作業を任せる
  サブエージェントまで止める。作業を任せるには `isolation: worktree` で取り込みの手間が増え、規模が大きくなるほど
  効く。どのサブエージェントが変えてよいかというロールの知識を、動き方の層（harness）に持ち込むことにもなる。
  Bash のコマンドを字面で読む断り方は、書き方によって通すものと誤って断るものが残る。
- **hook の入力の `agent_type` で、ファイルを変えないロールのときだけ断る**：ロールの知識を harness に持ち込む点は
  同じ。断っても、レビューに要る試すための編集の場所は、案内に頼ることになる。隔離すれば、断らずに済む。
- **ロールの定義の `hooks` で、そのロールのときだけ断る**：断る仕組みを持つ点で上と同じ。隔離で足りる。
- **ターゲットの `.gitignore` に `.claude/worktrees/` を足す**：target-template の `.gitignore` の共通の部分になり、
  すべてのターゲットを直すことになる。困るのは control-plane の作業領域の push だけなので、作業領域の中で除く。
- **devcontainer で直接動くときも比べて知らせる**：人が端末にいて、作業領域の変化を自分で見られる。

## Consequences

- reviewer と guide をサブエージェントとして頼むと、作業領域の HEAD から作った worktree で動く。自分の変更のレビューは
  コミットしてから頼むので、worktree に変更が入る。変更のない worktree は Claude Code が消し、変更のあるものは残る。
- 作業を任せたサブエージェントは、作業領域を編集できる。そのときも、セッションのエージェントには何が変わったかが
  届くので、コミットの前に確かめる材料になる。
- 比べるのは前後の状態なので、サブエージェントが変えてから戻したものは知らせない。並べて動かしたサブエージェントの
  どれが変えたかは分からない。比べるための写しを作業領域の `.git` に一時的に置き、1 日より古いものは次の Agent の
  前に消す。
- control-plane がセッションの主のエージェントとしてロールを起動するとき（`--agent reviewer`）に `isolation` が
  どう扱われるかは、確かめていない。
