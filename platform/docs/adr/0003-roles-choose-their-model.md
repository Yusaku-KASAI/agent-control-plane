# 0003. ロールが、自分の仕事に合うモデルと進め方を決める

- Status: Accepted
- Date: 2026-10-07

## Context

developer が、古いセッションを片付ける変更で、記録を消したあとに同じスレッドから依頼し直したときの問題を
見落とした。レビューした別のセッションは気づいた。違いは、前提をまとめて読める場所がなかったこと、作業の
進め方に影響の洗い出しや見直しの手順がなかったこと、モデル（developer は既定の Sonnet、レビューした側は Opus）
だった。`claude -p` の既定のモデルは、アカウントの既定に従う。Claude Code のカスタムエージェントは、frontmatter
の `model` でモデルを指定できる。

## Decision

- ロールの定義の frontmatter で、そのロールの仕事に合うモデルを指定する。developer は `opus` にする。
- developer の進め方に、変更が関わる前提の確認、壊れうる場面の洗い出し、PR を作る前のサブエージェントによる
  差分のレビューを入れる。

## Alternatives

- **control-plane の設定でエージェントごとにモデルを指定する**：同じロールのエージェントごとに書くことになり、
  ロールに求める仕事の重さという、ロールの性質と離れる。
- **ターゲットの `.claude/settings.json` でモデルを指定する**：そのターゲットで動くすべてのロールに同じモデルが
  使われる。
- **レビューを別のロール（reviewer）に任せる**：PR ごとに別のエージェントを動かす仕組みが要る。まず書く側の
  見直しで足りるかを見る。

## Consequences

- developer の1回の依頼にかかる時間と使用量が増える。
- ターゲットで別のモデルにしたいときは、`.claude/agents/developer.md` に同名のロールを置いて上書きする。
