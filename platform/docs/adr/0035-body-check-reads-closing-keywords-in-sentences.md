# 0035. prctl の本文の検査は、文の中の閉じるキーワードも読み、依頼の Issue でない Issue を閉じる本文を断る

## Context

conventions の書き方は、PR の本文の `Closes` と `Refs` の行に依頼の Issue だけを置き、ほかの Issue には文の中で触れると
決めている（書き方：PR）。`prctl` の本文の検査（`body_check`）は、閉じるキーワードか `Refs` と Issue で始まる行が挙げる
Issue を、依頼の Issue 一つに限ってきた。

GitHub は、閉じるキーワード（close、fix、resolve とその活用。大文字小文字を問わない）を本文のどこにあっても読み、後ろの
`#N`、`owner/repo#N`、Issue の URL が指す Issue を、PR のマージで閉じる。行の始まりだけを見る検査では、「これは fixes #7
の続き」のように文の中でほかの Issue に触れると、検査を通ったまま、その Issue がマージで閉じる。閉じたことはマージの
あとに初めて表に出て、範囲の中の項目が済まないまま Issue が閉じる（PR #331 のレビュー 81efbcd の提案 1 の案 2、#306）。

## Decision

- `body_check` は、コードブロックとインラインのコードの外の行から、文の中の閉じるキーワードと後ろの Issue も集める。
  `Refs` は含めない（GitHub は `Refs` で閉じない）。
- キーワードの前は行の始まりか、英数字と `_` でない文字にする（`prefix #2` は読まない）。キーワードの後ろには `:` と空白が
  あってよい。
- Issue の URL（`https://github.com/owner/repo/issues/N`）は `owner/repo#N` と同じに読み、このリポジトリのものかは見分けない。
  比べるときは大文字小文字を問わない。
- 集めた Issue が依頼の Issue（閉じるか触れる行が挙げる Issue。その行がなければ、ない）と違えば断る。断る文には、どの
  Issue をどの言い方で閉じるかと、文の中でほかの Issue に触れるときは閉じるキーワードを使わないことを書く。
- 行の始まりの形の確かめ（行が依頼の Issue 一つを挙げるか）は、そのまま残す。依頼の Issue を読むのは行の始まりの形で、
  `prctl worktree pr` と `prctl ready` もそれによる。

## Alternatives

- **行の始まりの形だけを見る今の形のまま**：書き方の決まりは行に置くことを決めていて、文の中のキーワードは決まりの
  外とも読める。ただ、GitHub が閉じるかは行に置いたかによらず、閉じてほしくない Issue がマージで閉じる失敗は、
  マージのあとまで気づけない。検査は書いたときに断れるので、決まりの狙い（依頼の Issue だけを閉じる）を仕組みで守る方を採る。
- **GitHub の `closingIssuesReferences` で読む**（PR を作ったあとに、GitHub が閉じると読んだ Issue を API で取り、依頼の
  Issue と比べる）：GitHub の読み方とずれない。ただ、PR を作る前と本文を書き換える前には読めず、`prctl create` と
  `prctl update` は書いてから断ることになる。本文を書き換えるたびに API を読み、検査が手元の文字列だけで閉じなくなる。
  正規表現でのずれ（GitHub が読まない形を断るなど）は安全側に止まるので、書く前に手元で読む形を採る。
- **URL の形をこのリポジトリかどうかで見分ける**（このリポジトリの URL を `#N` と同じに読む）：リポジトリの名前を
  `gh` か `git remote` から読む要が増える。依頼の Issue を URL で書いた文を断っても、`#N` で書けば通るので、見分けない。

## Consequences

- 依頼の Issue と同じ Issue を文の中で閉じるキーワードとともに書くのは通る。依頼の Issue を `#N` で書き、文の中で同じ
  Issue を `owner/repo#N` か URL で書くと、違う Issue と読んで断る。
- キーワードの直後に空白も `:` もない形（`fix#3`）も、文の中の閉じるキーワードと読んで断る。
- 依頼の Issue のない本文は、文の中で閉じるキーワードを Issue の前に書くと断る。
- インラインのコードは、バッククォートの数のそろう組を外して読む。コードの中に閉じるキーワードを書けば、断らない。
