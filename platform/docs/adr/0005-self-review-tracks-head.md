# 0005. 差分のレビューを PR のコメントに印付きで残し、hook で head に追いつかせる

## Context

エージェントは PR を作る前に、サブエージェントに差分をレビューさせることになっていた（ADR 0003、conventions の
レビューの扱い方）。守らせていたのは役割ごとの指示とスキルだけで、レビューしたかどうかは外から見えなかった。
レビューのあとの push で入った変更は、レビューされないままになりやすかった。

PR を見る人には、どの範囲を誰がレビューし、指摘にどう答えたかが要る。エージェントのコンテナはセッションの途中でも
作り直されるので、手元の記録は失われうる。本文の古さは、本文の印と hook で検出している（ADR 0002）。

## Decision

- 差分のレビューの結果を、見た範囲と、指摘とそれぞれへの答えとともに、PR のコメントに残す。コメントには、どの head
  までレビューしたかの印（`<!-- prctl: reviewed=<コミット> -->`）を隠して入れる。`prctl review` で書く。
- まだレビューしていない範囲は、最後の印の head から今の head まで。その head が履歴にないときは、ブランチが
  既定のブランチから分かれた所から。`prctl unreviewed` が示す。
- ADR 0002 の hook を広げ、本文が古いか、レビューが今の head に追いついていなければ促す。ターンの終わりには一度
  止める。どちらも済んだ head は覚えて、GitHub に聞き直さない。

## Alternatives

- **レビューの結果を PR の本文に書く**：本文は今の中身の説明で、push ごとに書き換える。レビューは範囲ごとの記録で、
  書き換えると経緯が消える。
- **別のエージェント（reviewer）が push を見てレビューする**：control-plane に外から届く口がなく、ポーリングの
  仕組みが要る。まず変更した側のレビューを機械的にする。reviewer の役割は人が頼んで使う（#28）。
- **レビューしたかをセッションの手元の記録で判断する**：コンテナを作り直すと失われ、人とも共有できない。
- **サブエージェントを動かしたかを hook で検出する**：何をレビューさせたかまでは分からず、結果も残らない。

## Consequences

- push のたびに、その範囲のレビューが要る。小さな直しなら、レビューも小さくなる。
- 印のあるコメントを書くのはエージェントとは限らない。人が対話で使うときも同じ hook が働く。
- 印は誰でも書けるので、レビューが本当に行われたかまでは保証しない。PR を人が確かめる最後の防衛線（app ADR 0025）は
  変わらない。
