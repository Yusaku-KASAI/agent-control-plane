# 0005. 差分のレビューを、見た最後のコミットに付けた PR のレビューとして残し、hook で head に追いつかせる

## Context

エージェントは PR を作る前に、サブエージェントに差分をレビューさせることになっていた（ADR 0003、conventions の
レビューの扱い方）。守らせていたのは役割ごとの指示とスキルだけで、レビューしたかどうかは外から見えなかった。
レビューのあとの push で入った変更は、レビューされないままになりやすかった。

PR を見る人には、どの範囲がレビューされ、指摘にどう答えたかが要る。エージェントのコンテナはセッションの途中でも
作り直されるので、手元の記録は失われうる。本文の古さは、本文の印と hook で検出している（ADR 0002）。

## Decision

- 差分のレビューは、コミットしたものに対して行う。結果は、見た範囲と指摘を、見た最後のコミットに付けた PR の
  レビュー（`event=COMMENT`、`commit_id`）として残す。`prctl review <コミット> <指摘>` で書く。
- まだレビューしていない範囲は、本文のある PR のレビュー（誰が付けたものでもよい。行へのコメントだけのものや返信、
  取り下げたものは数えない）が付いたコミットのうち、今の head の履歴に
  ある最後のものから、今の head まで。ないときは、ブランチが PR の向き先のブランチから分かれた所から。
  `prctl unreviewed` が示す。
- レビューのあとに直したコミットは、次のレビューの範囲になる。指摘への答えは、PR を作る前のレビューならそのレビューの
  中に、作ったあとなら push の変更点のコメント（ADR 0002）に書く。
- ADR 0002 の hook を広げ、本文が古いか、レビューが今の head に追いついていなければ促す。ターンの終わりには一度
  止める。どちらも済んだ head は覚えて、GitHub に聞き直さない。レビューを読めないときは何も言わない。

## Alternatives

- **PR のコメントに、レビューした head の隠した印を入れる**：GitHub がすでに持つレビューと `commit_id` を、
  自分の形で作り直すことになる。人やほかのエージェントのレビューを数えられない。
- **記録するときの head までをレビュー済みにする**：レビューのあとに直して push してから記録すると、誰も見ていない
  直しまでレビュー済みになる。
- **レビューの結果を PR の本文に書く**：本文は今の中身の説明で、push ごとに書き換える。レビューは範囲ごとの記録で、
  書き換えると経緯が消える。
- **別のエージェント（reviewer）が push を見てレビューする**：control-plane に外から届く口がなく、ポーリングの
  仕組みが要る。まず変更した側のレビューを機械的にする。reviewer の役割は人が頼んで使う（#28）。
- **サブエージェントを動かしたかを hook で検出する**：何をレビューさせたかまでは分からず、結果も残らない。

## Consequences

- push のたびに、その範囲のレビューが要る。直しが小さければ、レビューも小さくなる。
- 人が対話で PR のブランチを使うときも、同じ hook が働き、ターンの終わりごとに一度止まる（本文と同じ）。読むだけで
  PR のブランチを checkout したときも止まる。
- PR のレビューは誰でも付けられるので、レビューが本当に十分だったかまでは保証しない。PR を人が確かめる最後の防衛線
  （app ADR 0025）は変わらない。
