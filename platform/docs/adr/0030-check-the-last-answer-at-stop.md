# 0030. control-plane 経由の最後の回答は、slack プラグインの Stop hook で崩れる形を確かめる

## Context

ADR 0028 は、Slack で崩れる形を `slackctl check` と `post` で見つけると決め、control-plane が投稿する最後の回答は、
エージェントが答える前に `slackctl check` に通すよう slack スキルに書いた。ターンの終わりの hook（Stop）で最後の回答を
確かめる形は、最後の回答がまだ崩れ続けるか分からないとして見送り、崩れが続くなら足すとした。

その後のセッションの記録では、書式の多い最後の回答を書いたエージェントが、答える前に `slackctl check` を通して
いなかった（#266 の作り直したあとの確かめ）。崩れはそのとき出ていなかったが、通すかどうかがエージェントに任されて
いて、ネストしたリストやコードブロックのように崩れやすい形は残る。依頼者は、Stop hook で確かめるだけの形を
頼んだ（2026-10-26）。control-plane 経由のものだけでよく、標準の Markdown でありつつ Slack でも崩れない共通の形に
寄せるのがよい、という考えを添えた。

## Decision

- slack プラグインに Stop hook（`scripts/check-answer-at-stop`）を置く。ターンの終わりに、最後の回答（Stop hook の入力の
  `last_assistant_message`）を `check-markdown` にかけ、崩れる形があれば、見つけた行と形を理由にしてターンを止め
  （`decision: block`）、書き直して答え全体をもう一度書くよう促す。確かめるだけで、直しも投稿もしない。
- 動くのは control-plane 経由（`ACP_SESSION_BRANCH` がある）のときだけ。devcontainer で直接動くときの回答は端末に出る
  だけなので確かめない。control-plane 経由では、依頼が Slack からか CLI からかを分けない。それを知る値は渡されて
  おらず、崩れない形は標準の Markdown のうちどちらでも読める形なので、CLI の回答に当てても損はない。
- 同じ見つけた形では、セッションの中で一度だけ止める。見つけた形は、行ではなく形の種類と数で覚え、わざとその形を
  残すときは、前後を書き換えても止まらない。
  崩れる形のない回答で覚えを消し、あとのターンで同じ形が出ればまた止める。hook 自身の失敗では止めない。
- slack スキルは、最後の回答を答える前に `slackctl check` に通す手順をやめ、hook が止めたら書き直すことを書く。

## Alternatives

- **今のまま、エージェントが `slackctl check` を通すのに任せる**：手間は増えないが、通していない回答が見つかっていて、
  依頼者は仕組みで確かめる形を頼んだ。
- **control-plane が投稿の前に検知して、崩れる形を直すか知らせる**：直せる形（URL と表）はすでに直している。ほかの形は
  意味を変えずには直せず（control-plane の ADR 0050 と同じ理由）、投稿の前に知らせてもエージェントのターンは終わっている。書き直せる
  のはエージェントなので、ターンの中で止める方がよい。
- **Slack からの依頼のときだけ確かめる（control-plane が依頼の入口を環境変数で渡す）**：CLI の回答に当てないで済むが、
  ハーネスの契約に値を足すことになる。崩れない形は CLI の回答でも読めるので、分ける益が小さい。
- **見つかったら、毎回止める**：わざとその形にする回答（Markdown の書き方を説明する回答など）で終われなくなる。
  conventions の `check-docs-at-stop` と同じく、同じ失敗では一度だけにする。
- **会話の記録（`transcript_path`）から最後の回答を読む**：古い Claude Code でも動くが、記録の形に頼る。今の Claude Code
  は Stop hook の入力に最後の回答を渡すので、それを読み、なければ確かめない。

## Consequences

- control-plane 経由の最後の回答は、エージェントが忘れても検知を通る。崩れる形があれば、ターンが一度延び、そのぶん
  時間とトークンが増える。
- 回答の書き方は、slack スキルの「書く」（標準の Markdown のうち Slack でも崩れない形）にそろう。
- 確かめるのは `check-markdown` が見つける形だけ。見つけない形（ADR 0028）は、今までどおり書き方に任せる。
- Claude Code が Stop hook の入力に `last_assistant_message` を渡さない版では、確かめない。
