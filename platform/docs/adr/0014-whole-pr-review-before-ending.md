# 0014. 終える前に PR 全体の差分のレビューを求め、終えてよいかを hook で確かめる

## Context

ADR 0005 で、差分のレビューは push のたびに前回からの差分を見ることになった。最後に PR 全体を見直す決まりは
なかった。#132 で最後に PR 全体をすべての観点で見るレビューを試すと、前回からの差分のレビューが見落とした提案と
細部が出た（Issue #110）。依頼者は、終えるときには PR 全体がすべての観点で見直されていてほしいと考えている。
指摘が出続けてレビューが増えることには、上限を設けて人に返したい（Issue #134）。

ADR 0011 で、レビューの結果と答えに決まった形と、機械で読む写しを持たせた。終えてよいかを、その写しから判定できる。

## Decision

- conventions の `reviews.md` に「終える前」を決める。終えたと報告する前に、PR 全体の差分のレビューをすべての観点で
  行う。そのあとに細部の直し（レビューしない直し）のほかの変更がなく、必須の指摘がなく、すべての指摘に答えて
  いれば終えてよい。提案は直さない理由か、範囲の外の直しなら Issue で、細部は直さないか細部の範囲の直しで終えて
  よい（範囲の中の直しを Issue に送らない）。提案や必須を直したら、もう一度 PR 全体の差分のレビューを行う。5 回
  （最初の 1 回と、直したあとの 4 回。依頼者と決めた）しても終えられなければ、依頼者に返し、続けるよう言われたら
  そこから数え直す。
- 強いる所は、下書き（draft）を外すときと、下書きを外したあとのターンの終わりにする（依頼者と決めた案 C）。
  - `prctl create` は PR を下書きで作る。途中のあいだは下書きで、終える前のレビューを求めない。
  - `prctl ready` は、終えてよいときだけ下書きを外す（GitHub の GraphQL の `markPullRequestReadyForReview`）。
    終えられなければ断り、足りないものを言う。
  - `prctl hook stop` は、下書きでない PR で、終えてよいかを確かめ、終えられなければ止めて足りないものを言う
    （下書きを外したあとの変更を捕まえる）。本文、レビューの追いつき、CI の失敗が足りないときも、いっしょに言う。
    hook は一つのターンで一度しか止めないので、それらを済ませたあと確かめずに終わらないようにする。5 回に達していれば、
    依頼者に返すよう言い、どこまで数えたかを作業ツリーの `.git` に覚える。下書きのあいだは確かめず、head を済んだ
    とも覚えない（下書きは push なしで外れるため）。`prctl status` は `end:` の行で同じことを言う。
- 判定の材料は、head の履歴にあるレビューの事実（コミット、レビューしない直しの記録か、写しの範囲の種類と指摘の
  重さ、写しと答えのコメントから分かる答えた番号）で、一度だけ読む。答えはレビューの id で突き合わせる（同じ
  コミットのほかのレビューへの答えを数えない）。最後の PR 全体の差分のレビューより後のコミットの記録（レビューしない
  直しの記録は除く）を変更とみなす（同じコミットへのほかのレビューは変更ではない）。判定は `lib/review.jq` の
  `final_errors` の一か所。まだ記録のない head（レビューしていない push）は、先に記録するよう言う（細部の直しかどうかは
  記録が決めるので、変更とも、上限の理由ともみなさない）。

## Alternatives

- **エージェントの判断で、終える前に PR 全体を見直すよう決まりに書くだけにする**：読ませるだけでは守られない
  ことがある（#96）。写しから判定できるので、仕組みで守る。
- **push のたびに PR 全体を見る**：レビューのたびに全体を読むことになり、細部の直しのたびのレビュー（#110 の 1）と
  同じく回数とコストが増える。節目（作る前と終える前）にだけ全体を見る。
- **上限を設けない**：指摘が出続けると、エージェントが止まらない。人に返して判断を仰ぐ。
- **ターンの終わりだけで強いる（案 A）**：途中経過を返すたびに全体のレビューが回らないよう、エージェントが下書きを
  使い分ける必要があり、下書きのときに確かめた head を覚えて、外したあとに確かめない穴もあった。
- **下書きを外すときだけで強いる（案 B）**：外したあとの push を捕まえられない。
- **上限に達したら hook が止めずに終えさせる**：何が残ったかが報告に出ない。一度止めて、残りを添えて返すよう言う
  （hook に促されて続けたターンでは、もう止めない）。

## Consequences

- 途中経過を報告するターンでは、PR は下書きなので、PR 全体の差分のレビューは求められない（下書きを外したあとの
  追加の依頼では、`prctl draft` で戻したとき）。
- 人が手で下書きを外すことは止められない。そのあとのターンの終わりで hook が確かめる。
- 写しのないレビュー（ADR 0011 より前のもの、手で付けたもの）は、PR 全体の差分のレビューに数えない。
- 判定は、ターンの終わりごとにレビューと PR のコメントを GitHub に聞く。終えてよいと確かめた head は、そのときの
  レビューの数といっしょに覚えて、同じあいだは聞き直さない（レビューの一覧は毎回読む）。
- 5 回の数えには、PR を作る前のものも含め、前に数え直したあとの PR 全体の差分のレビューが入る。数え直すのは、
  ターンの終わりの hook が「依頼者に返す」と言った時点（下書きのあいだも、止めずに覚える）と、終えてよいと確かめた
  時点（hook ではほかにターンを止めるものがないとき、と `prctl ready`）。`prctl ready` は「返す」と言っても数え直さない（呼び直しで上限を超えないため）。
  依頼者が続けるよう言ったかは見ない。返すかどうかは、判定の種類（`final_errors` の `kind`）で見分け、文面には
  頼らない。
- 下書きを外したあとに追加の依頼で続けるときは、`prctl draft` で下書きに戻す。戻さなければ、途中経過を返すターンも
  hook に止められる。
- コミットの前後は、head の履歴のトポロジカルな順で決める。数え直しの位置は、最後に数えた PR 全体の差分のレビューの
  コミットで覚え、履歴を書き換えてそのコミットが head の履歴になければ、すべてを数える（上限には早く達する）。
  数え直しの位置は作業ツリーに覚えるので、ほかのクローンからは見えない。
- 判定の材料（写しと答えの印）は、誰が書いたものでも読む。PR に書き込める人は信頼できる（依頼者一人の手元の
  運用）ことを前提にしていて、偽の印で判定を通せないようにはしていない。
- 答えの印に、答えたレビューの id を足した（ADR 0011 の写しの形を変える）。id のない前の形の答えは、PR 全体の差分の
  レビューの答えに数えない。
- 印を読めない（壊れた写しや、GitHub を読めない）ときは、hook は何も言わずに終わらせ、`prctl ready` は断る。
- 下書きのない、前に作った PR は、ターンの終わりごとに確かめられる。
