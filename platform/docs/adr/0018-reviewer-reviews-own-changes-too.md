# 0018. 変更した人が頼む差分のレビューも reviewer ロールが行い、結果は頼んだ人に返す

## Context

ADR 0007 は、reviewer を、PR を指す依頼なら PR 全体を見て GitHub に残し、指さない依頼なら全体のレビューをする役とした。
変更した人が頼む差分のレビュー（PR を作る前、push のあと）は、変更したエージェントが、役割を持たないサブエージェントに
頼んでいた。

conventions の ADR 0020 で、場面の手順（レビューする）は、その「始めに読む」の段の文書と合わせて、起点（役割ごとの
指示）に直に並べることにした。役割を持たないサブエージェントには、その起点がない。#130 で数えると、頼む文に在りかが
書かれていなければ、レビューのサブエージェントは手順を読んでいなかった。実際の依頼では、変更した人はすでに reviewer
ロールのサブエージェントに差分のレビューを頼み、頼む文で「GitHub に残さず結果を返す」と上書きしていた。

## Decision

- 変更した人が頼む差分のレビューも、reviewer ロール（サブエージェント）が行う。reviewer は、依頼を二つの軸で分ける。
  - 種類：コミットの範囲（PR を作る前の範囲、前回のレビューからの差分）か PR を指せば、差分のレビュー。地図の項目を
    指すか、何も指さなければ、ADR 0007 のとおり全体のレビュー。
  - 残し方：結果を返すよう頼まれたら、PR が書かれていても GitHub には残さず、頼んだ人に返す（残すのは頼んだ人）。
    そうでなく PR を指すなら、ADR 0007 のとおり、PR 全体を見て、見た head に付けた PR のレビューとして残す。
- 変更した人は、頼む文に、結果を返し GitHub には残さないことと、レビューする手順とその始めに読む文書の在りかも書く。reviewer ロールを使えないときにも、
  手順に届くようにするため。

## Alternatives

- **役割を持たないサブエージェントに戻し、頼む文に在りかを書くだけにする**：起点に直に並べる形（ADR 0020）が使えず、
  手順に届くかは頼む文の書き方しだいになる。
- **変更した人の差分のレビューも PR 全体で見て、reviewer が GitHub に残す**：push のたびの前回からの差分のレビューが
  なくなり、変更した人の記録（`prctl review`）と二重に付く。

## Consequences

- reviewer の固有の振る舞い、developer のレビューの要約、roles の全体像を、この分け方（種類と残し方の二つの軸）に合わせる。
- 変更した人の差分のレビューにも、reviewer のモデル（ロールの定義の frontmatter）が使われる。
