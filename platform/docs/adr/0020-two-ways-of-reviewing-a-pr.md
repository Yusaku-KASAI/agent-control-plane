# 0020. PR の差分のレビューを、通常と念入りの二つの回し方に分け、PR のラベルで見分ける

## Context

ADR 0005 で push のたびに前回からの差分を、ADR 0014 で終える前に PR 全体を、すべての観点でレビューすることにした。
ADR 0014 は、提案や必須を直したらもう一度 PR 全体をレビューし、5 回で終えられなければ依頼者に返すとした。

直近にマージした 11 件の PR（#172〜#189）では、レビューは 73 回で、すべて PR 全体だった（前回からの差分のレビューは
0 回）。1 件あたりは中央値 5 回、最多は 15 回（#183）で、上限は依頼者が続けるよう言って数え直していた。提案は 10 回目を
過ぎても 1 回に 1〜3 件出続け、必須は 73 回のうち 15 回で出た。必須が、必須のないレビューが何回か続いたあとに出た
PR もある（#187 の 7 回目、#189 の 9 回目と 10 回目）。

依頼者は、レビューで質を保ちつつ、ラリーの回数、時間、トークンを抑えたいと考えている。取り込める所まで来たら
マージして先に進み、残りは手の空いたときの全体のレビュー（監査）で拾う。そのうえで、次の二つの回し方を示した
（Slack）。

- PR のレビュー（明示的に頼まれたときを除く）：PR 全体のレビューだけ。必須なしが出ないまま 3 回続いたら止める。読む
  エージェントは一つ。
- 全体のレビュー：全体のレビュー、PR 全体、前回からのレビューのすべてを含む。終える条件は回数のほかは今までどおりで、
  上限は 10 回。読むエージェントは観点ごとに並べる。

Issue #170 は、直したあとを前回からの差分で見て PR 全体を終える前にだけ回す案を、#171 は、観点「別の形」の指摘が
出にくいことを扱っていた。

## Decision

- conventions の `reviews.md` に「回し方」の節を足し、変更した人が頼む PR の差分のレビューを、通常（既定）と念入りに
  分ける。念入りは、依頼者が念入りに頼んだ PR と、全体のレビューの報告から作る PR に当てる。
  - **通常**：PR を作ったあとのレビューも毎回 PR 全体にし、前回からの差分のレビューはしない。一人がすべての観点で読む。
    必須のなかった PR 全体のレビューを取り込める所とし、その指摘（提案、質問、細部）への直しは、もう一度見ない
    レビューしない直しにする。PR 全体のレビューで必須が 3 回続けて出たら、依頼者に返す。
  - **念入り**：今までの回し方。push ごとに前回からの差分、終える前に PR 全体をレビューし、レビューしない直しは細部の
    指摘への意味の変わらない直しだけ。観点ごとに読む人を分けて並べ、頼んだ人が一つの結果にまとめる。PR 全体の
    レビューを 10 回しても終えられなければ、依頼者に返す。
- 全体のレビュー（監査）は、回し方によらず、観点ごとに読む人を分けて並べる。
- 回し方は、PR のラベル `念入りのレビュー` で示す。`prctl mode` が付け外しし、`prctl` は、ラベルがあれば念入り、なければ
  通常と読む。通常の PR には、前回からの差分のレビュー（`"scope": "since"`）を残させず、必須のあった PR 全体のレビュー
  のあとの範囲を、レビューしない直しとして残させない。push のあとの hook の案内も、回し方に合わせて PR 全体のレビューか
  前回からの範囲のレビューを促す。
- 終えてよいかの判定（`lib/review.jq` の `final_errors`）は、回し方を受け取る。終える条件（最後の PR 全体のレビューの
  あとにレビューしない直しの記録のほかの変更がない、必須がない、すべてに答えた）は、どちらも同じ形のままにし、
  何をレビューしない直しにしてよいかは決まりで分ける。依頼者に返すときだけ、念入りは数え直したあとの PR 全体の
  レビューの数（`PRCTL_FINAL_CAP`、既定は 10）、通常は最後から続けて必須を出した PR 全体のレビューの数
  （`PRCTL_MUST_STREAK`、既定は 3）で見る。

依頼者の「必須なしが 3 回連続で出なければ ok」は、「必須なし」の結果が 3 回続けて出ないまま（必須が 3 回続いて）なら
止める、と読んだ。「必須なしが 3 回続けば終えてよい」とも読めるが、そうすると終える条件が今より重くなり、ラリーを
抑える狙いに合わない。

## Alternatives

- **#170 の案（直したら前回からの差分、PR 全体は終える前だけ）**：PR 全体のレビューの回数は減るが、前回からの差分の
  レビューと PR 全体のレビューを交互に回すので、ラリーの数は減らない。依頼者は、前回からの差分のレビューはラリーを
  増やすだけと見ている。念入りでは、今までの回し方のまま前回からの差分も使う。
- **通常でも提案を直したら PR 全体をもう一度見る**：直近の 73 回では、提案は回を重ねても出続け、これがラリーが
  終わらない元だった。取り込める所（必須なし）まで来たら、残りは監査で拾う。
- **必須なしが 3 回続いたら終える**：直近の 11 件に当てはめると 48 回（今は 73 回）で、遅れて出た必須のうち #173 と
  #178 の 3 回目は拾えるが、#187 と #189 のものは拾えない。どの回数でも遅れて出る必須は残るので、監査で拾う方に
  寄せ、ラリーを抑える方を選んだ（同じく当てはめると 19 回で、2 件は依頼者に返る）。
- **回し方を `prctl ready` の引数で渡す**：ターンの終わりの hook が回し方を知れない。PR に持たせれば、依頼者も
  GitHub で付け外しでき、セッションをまたいで残る。
- **回し方を PR の本文の隠した印に持たせる**：本文は `prctl update` で書き換えるたびに印を保つ必要があり、人からも
  見えない。

## Consequences

- 通常の PR では、終える前の PR 全体のレビューのあとの提案と質問への直しを、誰も見ないまま取り込みうる。それが
  壊したものは、あとの全体のレビューか、次の変更で見つける。
- 通常では上限の回数がなく、必須が出ては消えるのを繰り返すと、レビューが続きうる。必須が続けて出ないかぎり返さない。
- 念入りでは、レビューのたびに観点の数（7）だけサブエージェントが動き、トークンが増える。
- 観点「別の形」を一人が読むのは、念入りと全体のレビューだけになる。通常の PR でそれが出にくいこと（#171）は残る。
- ラベルは、`prctl mode thorough` が初めて付けるときにリポジトリに作る。developer の App が Issue に書けることを前提にする。
