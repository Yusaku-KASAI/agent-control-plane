# 0009. 細部の指摘への直しだけの範囲は、レビューせずにそう記録して、レビューを head に追いつかせる

## Context

ADR 0005 で、push のたびに、まだレビューしていない範囲をレビューさせることになった。hook は、レビューが今の head に
追いついていなければ促し、ターンの終わりに止める。

細部や任意の指摘を直して push するたびに、新しい範囲ができ、次のレビューが要った。一つの PR でレビューが 4〜6 回
続いたことがある。後の回は、言い回しの直しや、直しが生んだ細部の食い違いを見るためのものだった（Issue #110）。
レビューの決まりは、どの指摘の直しを次のレビューに回すかも、直しをいつ push するかも決めていなかった。

## Decision

- 決まり（conventions の[差分のレビュー](../../plugins/conventions/docs/reference/reviews.md#diff)）を足す。拠り所は、パターン
  [直しを任せて見直しを終える](../../plugins/principles/docs/reference/patterns.md#lgtm-with-comments)（Google の
  Engineering Practices の LGTM with comments）。
  - 一回のレビューの指摘への直しは、すべての指摘に答えを決めてから、まとめて push する。
  - もう一度見ないと決めるのは、レビューした人にする。細部の指摘は、レビューした人が意味の変わらない直しで済むと
    判断したもの（指摘の重さの定義）なので、その判断として使う。
  - 範囲が細部の指摘への直しだけで、直しがその指摘の中に収まるなら、次のレビューに回さず、その範囲をレビューしない
    直しとして PR のレビューに残す。必須、提案、質問への直しや、指摘への答えではない直しがあるか、直しで意味が
    変わったら、次のレビューに回す。PR の最初のレビューは省かない。
  - 提案と細部の指摘は、直さない理由を書いて終えてよい。
- `prctl review --minor <コミット> <メモ>` を足す。その範囲を「レビューしない直し」の見出しで、範囲の最後のコミットに
  付けた PR のレビューとして残す。PR にレビューが一つもないときと、範囲の始まりがレビューではなく、レビューしない
  直しの記録のとき（一つのレビューの直しを分けて push した）は断る。
- その記録も本文のある PR のレビューなので、まだレビューしていない範囲の数え方（ADR 0005）は変えない。hook の
  促す文に、細部の指摘への直しだけなら `--minor` で残す道を足す。

## Alternatives

- **細部の指摘への直しを、hook が数えないようにする**：どのコミットが細部の直しかを、hook は見分けられない。
  コミットメッセージの印などで見分けると、記録が PR に残らず、PR を見る人に何をレビューしなかったかが見えない。
- **変更した人が、直しで意味が変わったかで決める**：提案への小さな直しも省けるが、省くかを、見直される側が自分で
  決めることになる。パターンのよくある失敗（意味の変わる直しまで見直さずに取り込む）が起きやすい。
- **レビューする人が、指摘ごとに「直したら見直さなくてよい」と別の印を付ける**：細部の重さが、すでにその意味を
  持つ。印を足すと、指摘の重さと二つの決め方が並ぶ。
- **任意の指摘は直さずに理由を書いて終える、だけにする**：直したほうがよい細部も残る。直すかは変更した人が決め、
  直したときの扱いを決める方が、選べる幅が広い。
- **再レビューの回数に上限を設ける**：上限の手前の意味の変わる直しと、上限を越えた直しを区別できない。

## Consequences

- 細部の指摘への直しだけの push では、レビューを頼まずに hook を通れる。どの指摘を見直さなくてよいかを決めるのは
  レビューした人だが、範囲が細部への直しだけで、その中に収まっているか（指摘のない直しが混ざっていないかを
  含む）は、変更した人の判断に任され、仕組みでは確かめない。記録は PR に残り、人が PR を確かめる最後の
  防衛線（app ADR 0025）は変わらない。
- `--minor` の記録の後にほかの直しを push すると、次のレビューの範囲は `--minor` の記録の後から始まる。
  細部の指摘への直しの範囲は、変更した人が頼む前回からの差分のレビューでは見ない（PR 全体のレビューや、人の確認は
  見る）。
- 提案への直しは、小さくても次のレビューに回る。
