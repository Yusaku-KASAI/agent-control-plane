# 0001. ターゲットをまたぐ能力は platform/ に Claude Code のプラグインとしてまとめる

## Context

ロールや Slack の扱いなど、どのターゲットでも使うエージェントの能力がある。拡張は Claude Code の標準機能を
優先する（app ADR 0005）。将来は agent-platform として別のリポジトリにする構想があるが、今はまだ
インターフェースが固まっていない。control-plane から起動したエージェントでも、ターゲットの devcontainer で
人間が使う Claude Code でも、同じ能力を使えるようにしたい。

## Decision

- 共通の能力は、このリポジトリの `platform/` に Claude Code のプラグインのマーケットプレイスとして置く。
- `platform/` は将来そのまま別のリポジトリのルートになる形にし、このリポジトリの他の部分に依存させない。
- 認証情報など環境ごとに変わるものはプラグインに含めず、実行する環境から渡す。

## Alternatives

- **今すぐ別のリポジトリにする**：インターフェースが固まらないうちは、1 つの変更が複数のリポジトリに分かれる。
- **ターゲットごとに `.claude/` に置く**：ターゲットの間で同じ定義が重複する。
- **control-plane が能力を持ち、起動時に注入する**：devcontainer で人間が使うときに同じ能力を使えない。

## Consequences

- 2 つ目のターゲットができた時点で、`platform/` を切り出すかを見直す。切り出したあとは、ターゲットは
  GitHub などのマーケットプレイスとして宣言する。
- コンテナの起動など control-plane にしかできないことは、プラグインからは使えない。
