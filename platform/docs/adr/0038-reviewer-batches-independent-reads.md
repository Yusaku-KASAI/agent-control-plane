# 0038. reviewer は、互いに依らない読み取りを一つのメッセージでまとめて呼ぶ

## Context

#247：通常の回し方で、レビューのサブエージェント（reviewer）の 1 回あたりの費用を下げたい。[ADR 0025](0025-normal-review-cutoff-after-two.md)
では回数を抑える形だけを入れ、1 回あたりの費用は #280 の比べを待った。

#280 の比べ（会話の記録、2026-10-10〜11-03）で分かったこと：

- reviewer 1 回あたりの費用（入力に換算したトークン）は、#246 の前の 197k から、#330 のあとの 292k に増え、費用に
  占める割合は約 3 割のまま。
- 1 回の費用の内訳は、キャッシュの読み込みが 61%、書き込みが 36%、出力が 3%。読み込みの費用は、呼び出しの回数と、
  そのたびに読み直す文脈の大きさの積になる。呼び出しの回数（中央値）は 18 から 27 に増えた。
- reviewer は、道具をほとんど一つのメッセージで一つずつ呼んでいた（1,871 回のうち 1,692 回）。始めに読む 3 つの
  文書を、1 回のレビューで平均約 1.9 回ずつ読んでいた（`sed -n` で分けて読むことを含む）。

## Decision

- reviewer ロールの指示の「読み方」に、互いに依らない読み取り（始めに読む文書、差分、依頼の Issue、関わる文書や
  コード）を一つのメッセージでまとめて呼ぶこと、全体まで読んだファイルを分けて読み直さないことを足す。
- 読む力（モデル）と、読むもの（始めに読む文書）は変えない。

## Alternatives

- **通常の回し方では、reviewer のモデルを軽いものにする**（#247 の候補）：1 トークンあたりの費用がすべての部分で
  下がる。ただ、レビューは読む力に頼っており、軽いモデルで必須の指摘を見落とさないかの比べがない（会話の記録で
  軽いモデルの reviewer は 36 回の呼び出しだけ）。モデルの選び方はロールが持つ（[ADR 0003](0003-roles-choose-their-model.md)）ので、
  通常と念入りで変えるにはロールを分けるか、呼び出しのたびにモデルを指定することになる。費用の多くが呼び出しの
  回数から来ると分かったので、まず回数を減らし、足りなければ次に試す。
- **同じ PR の 2 回目からは、始めに読む文書を渡し方で絞る**（#247 の候補）：毎回新しいサブエージェントなので、前に
  読んだかを知らない。目的の手順の「始めに読む」を省かない決まり（conventions の ADR 0020）を、レビューにだけ
  変えることになる。始めに読む文書の読み直しは、まとめて呼ぶことでも減らせる。
- **同じ reviewer に `SendMessage` で次のレビューを頼み、読んだ文脈を使い回す**：control-plane 経由では断られる
  （[ADR 0008](0008-subagents-in-foreground-under-control-plane.md)）。使えても、直しを挟むあいだにキャッシュの期限
  （5 分）が切れて文脈を書き直すことになり、前のレビューの見方も引き継ぐ。
- **レビューに要るもの（差分、依頼の Issue、範囲）を一度に出す prctl のコマンドを作る**：呼び出しは減るが、道具を
  作る手間がかかり、始めに読む文書や関わるコードの読み取りには効かない。指示で減らせるかを先に確かめる。

## Consequences

- 指示なので、守られないことがある。効き目（reviewer 1 回あたりの呼び出しの回数と費用）は、入れたあとに会話の
  記録で確かめる（#247 の範囲の中）。
- 一つのメッセージでまとめて読むと、その時点の文脈が一度に大きくなる。読む量は変わらないので、費用は増えない。
