# 0031. ターゲットの契約を platform の文書の根に置き、契約には渡すもの、求めるもの、制約、責務だけを書く

## Context

conventions の ADR 0002 は、ターゲットの契約を target-template に置くと決めた。契約は使う側から読める場所に置く
決まり（使う側に届く契約）なのに、ほかのターゲットのコンテナにマウントされるのは platform のマーケットプレイス
（`/workspace/agent-platform`）だけなので、platform の文書、スキル、ロールからターゲットの契約へのリンクは、そこでは
行き止まりになっていた（全体のレビュー #283 の C）。

また、ハーネスの契約は、harness と slack のプラグインの hook が何を断り、何を知らせるかまで書いていた。同じことを
各プラグインの全体像も書いていて、プラグインを変えると契約まで直すことになり、契約の両側（control-plane と
エージェント）に関わらない変更でも契約が動いた。

ターゲットのイメージに求める道具は `claude`、`git`、`gh` だけだったが、platform のコマンドと hook は `bash`、`jq`、
`python3`、`curl` なども使う。target-template のイメージが入れているので動いていたが、契約からは読み取れなかった。

## Decision

- ターゲットの契約を `platform/docs/reference/target.md` に置き、エージェントの用語集とハーネスの契約と並べる。
  置き場所の親（platform の文書の根）と、関係の上での親（契約）は違ってよい。
- 契約には、渡すもの（ハーネスの契約）か求めるもの（ターゲットの契約）、その見分け方、制約、それに応じてエージェントが
  すること（責務）だけを書く。プラグインが hook やコマンドで守らせることと、その仕組みは、そのプラグインの文書に置く。
  契約は、守らせる側があることに触れなくてよい。
- 契約は、それを使う側が要る事実を持つ。ロールごとの GitHub App の権限はハーネスの契約の認証情報に、platform が
  使う道具はターゲットの契約のイメージに置く。

## Alternatives

- **platform が要る事実だけをハーネスの契約に移す**：ターゲットの契約が二か所に分かれ、どちらが正かが読み手に
  分からない。
- **target-template に残し、platform からは文で案内する**：行き止まりのリンクが、たどれない文の案内に変わるだけで、
  ほかのターゲットのエージェントは契約を読めない。
- **hook の振る舞いもハーネスの契約に書く（ハーネスはプラグインを含む）**：プラグインの変更が契約の変更になり、同じ
  振る舞いを契約とプラグインの全体像の二か所で持ち続ける。

## Consequences

- リポジトリを control-plane、platform、target-template に分けても、契約は platform と一緒にすべてのエージェントに届く。
- target-template の文書と control-plane の文書は、platform の文書の根の契約を指す。
- 契約からは、エージェントが hook に断られる理由をたどれない。断る文と各プラグインの全体像が、それを持つ。
