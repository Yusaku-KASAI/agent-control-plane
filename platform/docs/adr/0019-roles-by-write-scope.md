# 0019. ロールは書ける範囲と受け持つ手順で分け、developer もレビューするを受け持つ

## Context

ADR 0007 は、レビューは reviewer ロールが行うと決めた。ADR 0018 は、変更した人が頼む差分のレビューも reviewer が
行うとした。conventions の ADR 0021 で、手順を依頼の目的で切り、ロールは権限と隔離の境界にして、手順とは多対多に
した。ロールの定義には、書ける範囲と、振り分けの目的の手順ごとに受け持つか受け持たないかを並べる「受け持つ手順」の
節を置く。

依頼者は、ロールの権限を、エージェントのハーネスの外に残るもの（GitHub）への書き込みで分けると考えている。guide は
何にも書かない、pm は Issue だけ、reviewer は PR のレビューと Issue だけ、developer はすべてに書ける。

## Decision

- ロールは、書ける範囲（作業領域、PR、PR のレビュー、Issue のうち、どれを書けるか）と、受け持つ手順で分ける。手順を
  受け持つかは、そのロールの書ける範囲でその手順を終えられるか（結果を残せるか）で決める。別の目のように、その手順の
  一部のために分けたロールがあるときは、その部分をそのロールに頼んだうえで決める（レビューは、差分を読む所を reviewer
  に頼めば、結果を残せるロールが受け持てる）。
- guide は、GitHub に何も書かないので、PR を指すレビューも全体のレビューも結果を残せず、レビューするを受け持たない。
- developer は、すべてに書けるので、レビューする（ほかの人の PR の差分のレビュー、全体のレビュー）も受け持つ。ただし、
  差分を読むのは reviewer ロールのサブエージェントに頼み、developer は返った結果を COMMENT の PR のレビューと Issue に
  残す（承認も変更の要求もしない）。このリポジトリの PR はほとんど developer が作るので、developer が自分で読むと、作者と
  同じロール、指示、モデルで読むことになり、ADR 0007 が reviewer を分けた理由（別の目）が弱まるため。全体のレビューは、
  範囲ごとに読む人を分ける手順（レビューするの「全体のレビュー」）で、別の目を保つ。
- reviewer は、ADR 0007 と 0018 のとおりレビューするを受け持ち、変更を届けるは受け持たない。

## Alternatives

- **レビューは reviewer だけが行う（ADR 0007 のまま）**：Slack で developer に頼まれたレビューを、reviewer に頼み直して
  もらうことになる。developer はすでに PR のレビューと Issue に書けるので、権限の上で分ける理由がない。
- **質問だけの依頼には書き込みの権限を付けない（ADR 0007 の Alternatives の懸念）**：その懸念は、guide を書き込みの
  ない別のロールにすることで扱う。developer に相談の依頼が来たときは、振り分けで相談として扱い、書き込みは要る
  ときだけにする。

## Consequences

- 差分のレビューは、変更した人が頼むものも、developer が頼まれたほかの人の PR のものも、reviewer ロールが読む。
- developer がほかの人の PR をレビューしたときも、その head までがレビュー済みとして数えられる（ADR 0007 の
  Consequences と同じ）。
