# 0025. 通常の回し方の打ち切りを、必須のない PR 全体のレビューが 2 回続いたときにする

## Context

トークンの消費を調べたキャンバス（Issue #240）で、レビューのサブエージェントが費用の約 3 割を占め、1 回あたり
7〜8 万トークンかかると分かった。通常の回し方は、必須の指摘のない PR 全体の差分のレビューが 3 回続いたら打ち切って
終えてよい（ADR 0021）。依頼者とキャンバスで、レビューの回数を抑えること（F5）を、作業の範囲の決め方（F1、F2。
conventions ADR 0032）とともに Issue #244 で進めると決めた。#244 は、打ち切りを 2 回にすることを勧めていた。

## Decision

- conventions の `reviews.md` の回し方で、通常の打ち切りを、必須の指摘のない PR 全体の差分のレビューが 2 回続いたら、
  にする。そのレビューの提案を直さずに終えてよいこと、上限（10 回）、念入りの回し方は変えない。
- 打ち切りは、ADR 0021 のとおり `prctl` が数えない。github スキルと developer ロールの要約の回数を合わせる。

## Alternatives

- **打ち切りを 1 回（必須のない PR 全体のレビューが一度出たら終えてよい）にする**：ADR 0021 で、直しを誰も見ないまま
  取り込むとして採らなかった形に近い。2 回なら、提案への直しをもう一度見てから終えられる。
- **3 回のままにして、範囲の決め方（conventions ADR 0032）だけで減らす**：範囲を絞ると指摘への直しは減るが、
  1 回ごとの費用が大きいレビューの回数の上限には効かない。
- **1 回あたりの費用を下げる（通常では reviewer のモデルを軽くする、同じ PR の 2 回目から読ませる文書を絞る）**：
  回数とは別の手で、決まりの回数を変えずに効く。ただし、読む力と、毎回の始めに決まりを読む前提（目的の手順の
  「始めに読む」）を変えるので、#244 の範囲の外とし、回数の効き具合を見てから扱う（Issue #247）。
- **上限（10 回）を下げる**：上限に当たるのは必須が出続けるときだけで、そこで早く返しても必須は直さなければならない。
- **打ち切りを `prctl` で数える**：ADR 0021 のとおり、打ち切った提案に「直さない」と答えれば今の終える条件で終えられる
  ので、判定は変えない。

## Consequences

- 必須のない PR 全体のレビューの 2 回目のあとに出たはずの必須は、打ち切りで拾えなくなる。あとの全体のレビューか、次の
  変更で見つける。ADR 0021 の 11 件の PR に 2 回の打ち切りを当てはめて、減る回数と拾えなくなる必須を数えることは
  していない。効き具合は下の `usage_log` で確かめる。
- 効き具合は、この変更をマージした日の前と後で、`usage_log` のターンの使用量（control-plane の app ADR 0036）を
  比べる。締めを促す仕組み（Issue #245）の閾値を決める材料にする。
- 打ち切りを何回で数えたかを確かめる検査は、今までどおりない。
