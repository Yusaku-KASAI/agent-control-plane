# 用語集

エージェントとハーネスの言葉。エージェントとハーネスに関わる文書では、この意味で使う。文書の体系と作業の言葉は
[conventions の用語集](../../plugins/conventions/docs/reference/glossary.md)にある。

| 言葉 | 意味 |
| --- | --- |
| control-plane | エージェントのコンテナを起動し、依頼を届け、認証情報を渡して更新するアプリケーション（agent-control-plane） |
| platform | エージェントの能力（ロール、スキル、hook）を持つ区切り。Claude Code のプラグインのマーケットプレイス `acp-platform` に入れて配る |
| マーケットプレイス | プラグインをまとめて配る単位。`acp-platform` は、platform のプラグインに加えて principles と conventions も配る |
| ターゲット | エージェントが作業する環境と、その定義を持つリポジトリ。何を用意するかはターゲットの契約が定める |
| target-template | ターゲットに共通の環境のファイルと、その説明を持つひな形 |
| ハーネス | エージェントを動かす仕組みの全体：ターゲットのイメージ、プラグイン、それを起動する control-plane か devcontainer。何が渡されるかは[ハーネスの契約](harness.md "在りか")が定める |
| ロール | エージェントの役割（developer、guide、reviewer、pm など）。Claude Code のカスタムエージェントとして定義される。何で分け、手順とどう関わるかは conventions の[目的の手順と共通の手順](../../plugins/conventions/docs/architecture/documentation.md#procedures "在りか")にある |
| エージェント | ターゲットとロールの組。Slack では Bot 一つに当たる（例：control-plane-dev） |
| 依頼者 | エージェントに依頼を出した人 |
| スレッド | 依頼を受けた Slack のスレッド。同じスレッドへの依頼は同じセッションに届く |
| セッション | 一つのエージェントとの一続きの会話の履歴と、その作業領域。Slack ではスレッドごとに一つ |
| 作業領域 | セッションごとに clone したターゲットのリポジトリ |
| セッションのブランチ | 作業領域を作るときに切られ、`ACP_SESSION_BRANCH` で渡されるブランチ `acp/<セッション ID の先頭8文字>`。エージェントがふだん作業するブランチ |
| ターン | Claude Code が依頼（いくつかの依頼をまとめて受けることもある）か自分から始めた作業を進め、最後の回答を出すまで |
| バックグラウンドの処理 | ターンが終わったあとも続く、エージェントが裏で動かしている処理。終わると、エージェントが自分からターンを始めることがある |
| 片付け | 使われないまま保持期間を過ぎたセッションを、作業領域や会話の履歴ごと消すこと。コンテナを止めて消すことは「片付け」と呼ばない |
| head ブランチ / base ブランチ | PR のマージ元 / マージ先のブランチ |
| head コミット | head ブランチの先頭のコミット。あるコミットが「head コミットに入っている」とは、head コミットから履歴をたどってそのコミットに行き着くこと |
