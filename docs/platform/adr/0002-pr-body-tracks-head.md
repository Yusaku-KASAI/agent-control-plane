# 0002. PR の本文に説明済みの head を記録し、hook で古い本文を検出する

- Status: Accepted
- Date: 2026-10-05

## Context

エージェントは PR を作るときには本文を書くが、後から push したときに本文を直し忘れる。PR の本文は
「このブランチに何が入っているか」の説明なので、直さなければ誤りになり、見た目では気づけない。
エージェントのコンテナはセッションの途中でも作り直され、手元に残した状態は失われうる。

## Decision

- 本文の末尾に、どの head まで説明したかを HTML コメントの印として入れる。本文が今の head を説明しているかは、
  GitHub の PR の head と印を比べて判断する。
- 本文の作成と更新は `prctl` で行い、更新で head が進んでいれば、変更点のコメントを必須にする。
- hook で検出する。
  - PostToolUse（Bash）：`origin/<ブランチ>` が HEAD と一致し、前回知らせた head と違えば PR を確かめ、本文が
    古ければ促す。
  - Stop：本文が古ければターンを終わらせずに書き換えさせる。一度止めたあとは止めない。

## Alternatives

- **Bash のコマンドの文字列から `git push` を探す**：文中に書いただけでも反応し、スクリプト経由の push を見逃す。
- **説明済みの head を手元のファイルに残す**：コンテナを作り直すと失われ、人間とエージェントで共有もできない。
- **スキルで指示するだけ**：プロンプトなしでも本文は書けるので、弱いのは指示ではなく、更新の忘れ。

## Consequences

- `gh pr create` や `gh pr edit` で直接本文を書くと印が無くなり、古いと判断される。`prctl` で書き直せば直る。
- Stop の hook は、ブランチが origin にあるターンの終わりごとに GitHub の API を1回呼ぶ。
- 人間が対話で使うときも、同じ hook が働く。
