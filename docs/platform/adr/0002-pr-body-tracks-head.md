# 0002. PR の本文に説明済みの head を記録し、hook で古い本文を検出する

- Status: Accepted
- Date: 2026-10-05

## Context

エージェントは PR を作るときには本文を書くが、後から push したときに本文を直し忘れる。PR の本文は
「このブランチに何が入っているか」の説明なので、直さなければ誤りになり、見た目では気づけない。
エージェントのコンテナはセッションの途中でも作り直され、手元に残した状態は失われうる。

## Decision

- 本文の末尾に、どの head まで説明したかを HTML コメントの印として入れる。本文が今の head を説明しているかは、
  GitHub の PR の head と印を比べて判断する。
- 本文の作成と更新は `prctl` で行い、更新で head が進んでいれば、変更点のコメントを必須にする。
- hook で検出する。
  - PostToolUse（Bash）：`origin/<ブランチ>` が HEAD と一致し、前回知らせた head と違えば PR を確かめ、本文が
    古ければ促す。
  - Stop：この作業ツリーから push した head について本文が古ければ、ターンを終わらせずに書き換えさせる。
    一度止めたあとは止めない。本文が説明済みと確かめた head は、次からは GitHub に問い合わせない。
  - どちらの hook も PR が無いときや `gh` が使えないときは何もしない。止めるのは1回だけで、書き換えるかは
    エージェントが判断する。

## Alternatives

- **Bash のコマンドの文字列から `git push` を探す、または hook の matcher で絞る**：文中に書いただけでも反応し、
  スクリプトや make 経由の push を見逃す。
- **説明済みかを手元のファイルだけで判断する**（手元のファイルは問い合わせを減らす控えにだけ使う）：コンテナを作り直すと失われ、人間とエージェントで共有もできない。
- **スキルで指示するだけ**：プロンプトなしでも本文は書けるので、弱いのは指示ではなく、更新の忘れ。

## Consequences

- `gh pr create` や `gh pr edit` で直接本文を書くと印が無くなり、古いと判断される。`prctl` で書き直せば直る。
- PostToolUse の hook はすべての Bash の呼び出しで動くが、push がなければ手元の git だけで終わる。
- サブエージェントの終わりでは Stop は動かない。サブエージェントが push したときは、そのサブエージェントが
  PostToolUse で促され、見落としても呼び出し元のターンの終わりに Stop で検出される。
- 人間が対話で使うときも、同じ hook が働く。
