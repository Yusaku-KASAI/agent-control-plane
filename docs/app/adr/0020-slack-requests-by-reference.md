# 0020. Slack からの依頼は本文ではなく場所を渡し、エージェントが Bot トークンで Slack を読み書きする

- Status: Accepted
- Date: 2026-10-03

## Context

Slack からの依頼には、スレッドの前の発言や、貼られた別のメッセージへのリンクといった文脈がある。これらを
control-plane がすべて読んでプロンプトに入れると大きくなり、受信箱で待つ間に依頼が編集されても反映されない。
Slack の読み書きの手段は環境によって違う（ADR 0006）。

## Decision

- Slack から受けた依頼は、本文を入れず、依頼者・依頼のメッセージ・スレッドの場所だけをプロンプトとして渡す。
  本文やスレッドの他の発言、リンク先は、エージェントが必要に応じて読む。
- エージェントには、そのエージェントの Slack アプリの Bot トークンを渡し、Slack の読み書きを許す。
  トークンはファイルで渡し、エージェントは platform の slack プラグイン（`slackctl`）で読み書きする。
- ターンの最後の回答は control-plane がスレッドに投稿し、エージェントは自分では投稿しない。

## Alternatives

- **スレッドの発言をプロンプトに入れる**：大きくなりやすく、他の Bot の発言など不要なものも入る。
- **読み取り専用の Slack アプリを別に用意する**：エージェントが途中経過などを投稿できず、アプリの管理も増える。
- **Slack の MCP を使う**：公式の MCP はユーザー本人の OAuth で動き、Bot としてのエージェントには合わない。
  非公式の実装には頼らない。

## Consequences

- エージェントが読めるのは、Bot が招待されたチャンネルだけになる。
- 依頼が受信箱で待つ間に編集されても、エージェントは処理する時点の本文を読む。
- Bot トークンを短命にする（Slack のトークンローテーション）場合も、ファイルの書き換えで済む。
