# 0018. 認証情報はセッションごとのディレクトリのファイルで渡し、control-plane が失効前に更新する

- Status: Accepted
- Date: 2026-10-03

## Context

ADR 0011 では GitHub のトークンを環境変数でコンテナに渡していた。セッションのプロセスを動かし続けると
（ADR 0017）、コンテナは 1 時間で失効するトークンより長く動く。環境変数は起動後に変えられない。
`gh` は `GH_CONFIG_DIR` の `hosts.yml` を呼び出しのたびに読み、ディレクトリが読み取り専用でも動く。
`sessions.root` は devcontainer から読み取れる場所にある。

## Decision

- 認証情報はセッションごとのディレクトリにファイルで置き、エージェントのコンテナに読み取り専用で
  マウントする。GitHub のトークンは `gh` の `hosts.yml` として置き、git は `gh` を認証に使う。
- control-plane はセッションのプロセスが動いている間、失効より前に認証情報を発行し直してファイルを書き換える。
- 置き場所は control-plane だけが書ける Docker ボリュームとし、エージェントのコンテナにはそのセッションの
  サブパスだけをマウントする。

## Alternatives

- **環境変数で渡す**：起動後に更新できない。
- **`sessions.root` の下に置く**：devcontainer から読めてしまう。
- **コンテナからトークンを取りに来させる**：コンテナから control-plane への経路と、その認証が要る。

## Consequences

- エージェントは、ファイルの更新を意識せずに `gh` と git を使い続けられる。
- 有効期間の短い認証情報だけをコンテナに置くので、漏れたときの影響が小さい。
