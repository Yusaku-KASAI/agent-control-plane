# 0025. 保護された既定のブランチに入る前の PR を、人が確かめる最後の防衛線にする

## Context

エージェントには承認の手順を設けず、コンテナの中では何をしてもよく、認証情報があれば push や PR の作成も
行う（ADR 0003）。それでも、エージェントの変更が人の目を通らずに本番の扱いになるのは避けたい。GitHub の
ルールセットで、既定のブランチへの変更を PR 経由に限れる。

## Decision

- ターゲットの既定のブランチは保護し、変更は PR 経由に限る。PR は人が確かめてからマージする。
- エージェントの作業は、既定のブランチに入る前までなら任せてよい形にする。ブランチを作る、push する、PR を
  作り直すといった操作は取り返しがつくので、エージェントに任せる。
- PR を通らない影響（認証情報やコードの持ち出し、Slack への投稿などの外部への書き込み、ホストへの影響）は
  PR では止められないので、隔離と、絞った短命の認証情報で抑える。

## Alternatives

- **エージェントの操作ごとに人が承認する**：承認が多いほど人が見なくなり、任せる意味も薄れる。
- **CI が通れば自動でマージする**：検査で分かることしか守れず、設計や意図の誤りは残る。
- **PR の確認だけに頼る**：PR に現れない持ち出しや外部への書き込みを防げない。

## Consequences

- 人が確かめやすい PR にすることがエージェントの仕事の一部になる。本文を今のブランチに合わせ続ける仕組み
  （platform ADR 0002）や CI はそのためにある。
- 既定のブランチを保護できないターゲットでは、この防衛線がない。
