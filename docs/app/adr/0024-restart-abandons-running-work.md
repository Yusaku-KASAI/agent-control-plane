# 0024. 再起動では動いている処理を中断して知らせ、続きは次の依頼で会話から再開する

## Context

エージェントのプロセスは control-plane がコンテナに attach して動かしており、control-plane が止まると
やり取りできなくなる。このリポジトリはエージェント自身が開発するので、変更を反映するたびに control-plane が
再起動する。これまでは、止まるときにエージェントの終了を待つ間に compose の猶予（既定 10 秒）が切れて強制終了され、
コンテナが残り、Slack のスレッドには何も知らされなかった。会話の履歴は Claude Code の設定ディレクトリに残るので、
同じセッションは `--resume` で続けられる。

## Decision

- 止まるとき：実行中のターンを interrupt してから各プロセスを閉じる。待っている依頼には、再起動で中断したことと、
  続けるにはもう一度依頼することを返す。待っている依頼がないのにエージェントが進めていた処理（自分で始めたターン、
  バックグラウンドの処理）があれば、スレッドに同じことを知らせる。知らせ終えてから終了し、compose の猶予は 1 分にする。
- 起動するとき：依頼を受け付ける前に、ラベル（`acp.session`）の付いたエージェントのコンテナを、動いているものも
  止まっているものもすべて削除し、そのセッションのスレッドに、再起動で止めたことを知らせる。そのために Docker の
  プロキシでコンテナの一覧（`GET /containers/json`）を許可する。
- 中断した処理は自動では再開しない。次の依頼で、同じセッションの会話を引き継いで新しいプロセスを起動する。

## Alternatives

- **再起動後に残ったコンテナへ attach し直す**：出力の途中から読み直すことになり、ターンやバックグラウンドの
  処理の状態を復元できない。新しい control-plane とエージェントの間の取り決めが変わっていることもある。
- **待っている依頼を保存し、再起動後に流し直す**：再起動の間に状況が変わった依頼を勝手に実行することになる。
  人がもう一度依頼すれば足りる。
- **セッションが処理中かを保存し、強制終了の後は処理中だったスレッドにだけ知らせる**：ターンのたびに書き込みが
  増える。強制終了はまれで、待ち状態のスレッドに知らせが届いても害は小さい。

## Consequences

- 強制終了の後は、待ち状態だっただけのスレッドにも知らせが届き、状態メッセージは「実行中」のまま残る
  （状態メッセージの位置は control-plane のメモリにしかない）。
- 同じ Docker ホストで `acp serve` を複数動かすと、後から起動したものが他のエージェントのコンテナを削除する。
- バックグラウンドの処理は再起動で失われる。
- control-plane はすべてのコンテナの一覧を読める。名前、イメージ、ラベルなどが見えるが、中身は操作できない。
