# 0017. アクティブなセッションは 1 つの Claude Code のプロセスを動かし続け、受信箱で依頼の順番を決める

- Status: Accepted
- Date: 2026-10-03

## Context

ADR 0009 ではターンごとにコンテナを作り、`claude -p` を 1 回実行していた。エージェントは 1 つのターンの中で
CI を待つなど長く動くことがあり、待つ処理と再開する処理は本来ひとまとまりである。実行中に届いた依頼の扱い、
割り込み、停止も決める必要がある。

`claude -p --input-format stream-json --output-format stream-json` では、標準入力を閉じるまでプロセスが
依頼を待ち続け、ターンの始めに `system/init`、終わりに `result` を出力する。実行中に依頼を送ると、
そのターンの途中に取り込まれる。`control_request` の `interrupt` を送るとターンが中断され、プロセスと会話は
そのまま残る。エージェントはバックグラウンドで処理を走らせてターンを終え、その処理が終わると依頼なしに
自分で次のターンを始めることがある。

## Decision

- アクティブなセッションごとに 1 つのコンテナで Claude Code を `stream-json` の入出力で動かし続け、
  依頼はその標準入力に送る。ターンの始まりと終わりはエージェントの出力（`system/init` と `result`）で判断する。
- 実行中に届いた依頼は、エージェントが自分で始めたターンの間も含めて、既定では受信箱に積み、`result` の
  後に送る。流し込むよう指定された依頼はすぐに送り、実行中のターンに取り込ませる。
- エージェントが自分で始めたターンの結果は、セッションが始まった会話（Slack のスレッドなど）に届ける。
  セッションには始まった会話を記録する。
- 停止は `interrupt` で行う。応答しないときだけコンテナを止める。
- ターンも待っている依頼もバックグラウンドの処理もない状態が一定時間続いたら、標準入力を閉じてコンテナを
  片付ける。次の依頼では新しいコンテナで `--resume` する。
- セッションごとのプロセスの管理は control-plane のプロセス内で行う。control-plane は 1 つだけ動かす。

## Alternatives

- **ターンごとにコンテナを作る（ADR 0009）**：待って再開する処理をターンの外に出す必要があり、
  待機中の割り込みの意味も曖昧になる。
- **実行中に届いた依頼もすぐに送る**：別の依頼が今のターンに混ざる。
- **停止でいきなりコンテナを止める**：実行中のコマンドの後始末やエージェントの報告の機会がない。

## Consequences

- コンテナが 1 時間を超えて動くことがあるため、認証情報を更新できる形で渡す必要がある（ADR 0018）。
- control-plane を再起動すると、動いていたセッションのプロセスと受信箱の依頼は失われる。
- CLI から始めたセッションには届け先の会話がないため、エージェントが自分で始めたターンの結果はログにだけ残る。
- Docker のプロキシで、コンテナの標準入出力への接続と停止の API を許可する。
