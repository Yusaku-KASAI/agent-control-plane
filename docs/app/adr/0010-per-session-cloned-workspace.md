# 0010. エージェントはセッションごとに複製した作業領域で動く

## Context

エージェントにはコンテナ内で何でもさせる（ADR 0003）。ターゲットのリポジトリをそのままマウントすると、
人間が作業している作業ツリーをエージェントが直接書き換えてしまう。複数のセッションが同時に同じ作業ツリーを
触ることもありうる。

## Decision

- セッションを始めるとき、ターゲットのリポジトリを `<sessions.root>/<セッションID>/workspace/<リポジトリ名>` に
  `git clone` し、そのセッションのターンではこの複製だけをマウントする。
- 複製はセッションが終わっても残し、そのパスを利用者に示す。

## Alternatives

- **git worktree を使う**：worktree は元のリポジトリの `.git` をホストの絶対パスで参照するため、
  コンテナ内から参照できない。ブランチなども人間の作業ツリーと共有される。
- **コンテナ内で Docker ボリュームに clone する**：ホスト側から結果を直接見られず、ターゲットの
  イメージに求めることも増える。
- **リモート（GitHub など）から clone する**：リポジトリごとに認証情報が要る。

## Consequences

- 複製に含まれるのはコミット済みの内容だけで、元の作業ツリーの未コミットの変更は入らない。
- 複製の `origin` はホスト上の元のリポジトリのパスで、コンテナ内からは使えない。エージェントが
  リモートへ push するには、別途リモートと認証情報の設定が要る。
- control-plane を動かす環境に git が要る。control-plane をコンテナで動かすときは、`sessions.root` を
  ホストと同じパスでマウントする。
