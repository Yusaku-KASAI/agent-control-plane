# 0065. 依頼の入らなかったターンの回答を投稿できなかったら、スレッドでは知らせず、文面ごとログに残す

## Context

依頼の入らなかったターンの回答と、`AgentAnswers` が決めたほかの知らせ（中断、再起動で止めたことなど）は、
`slackbot.Bot` が依頼を待たずに投稿する。Web API の呼び出しは再試行する（ADR 0063）が、それでも投稿できなかったときは、
セッション ID とエラーだけが警告としてログに残り、スレッドでは分からなかった（#354）。依頼のターンの回答と違い、
`:warning:` を付ける依頼のメッセージがない。

投稿できないのは、ネットワークの切断や Slack の不調のときがほとんどで、そのあいだは別の知らせも同じく届きにくい。
依頼者一人が自分の手元で control-plane を動かしており、依頼者がそのまま管理者になる。

## Decision

- 依頼を待たない知らせを投稿できなかったら、スレッドには何も足さず、エラーのログに、セッション ID、チャンネル、
  スレッド、知らせの文面、エラーを残す。管理者はログから、どのスレッドに何が届かなかったかを知り、文面を渡せる。

## Alternatives

- **スレッドに短い知らせを投稿する**：投稿できなかった原因が続いていれば、知らせも届かない。届くのは不調が収まった
  あとで、そのときに送り直す仕組み（いつ送るか、何を持っておくか）が要る。
- **状態メッセージに投稿できなかったことを出す**：状態メッセージの書き換えも同じ Web API で、同じく届きにくい。
- **届かなかった知らせを持っておき、つながったら送り直す**：持つ場所と送る時機を足すことになる（ADR 0063 で
  依頼のターンの回答にも採らなかった）。回答はセッションの会話にも残る。

## Consequences

- 投稿できなかったことは、スレッドでは分からない。依頼者は、答えが来ないときに control-plane のログを見る。
- ログに知らせの文面がそのまま残る。ログは control-plane を動かす手元にだけある。
- コンテナのログは、control-plane のコンテナを作り直すと消える（ADR 0036）。そのあとは、セッションを片付けるまで
  会話の履歴に回答が残る。
- 止めるときに投稿する知らせ（中断の知らせ、持っておいた回答）は、Slack とつながらなければ、再試行の途中で止まり
  （ADR 0063）、ログにも残らない。
