# 0048. Claude Code の `--session-id` と `--resume` は、会話の履歴があるかで切り替える

## Context

ADR 0009 は、最初のターンを `--session-id`、以降を `--resume` で起動すると決め、記録の `turns`（終えたターンの数）で
切り替えてきた。Claude Code は、会話の履歴（設定ディレクトリの `projects/<dir>/<ID>.jsonl`）がある ID を
`--session-id` で始めようとすると `Session ID <ID> is already in use.` で、履歴がない ID を `--resume` しようとすると
`No conversation found` で断る。履歴と `turns` は、次の場面で食い違う。

- 履歴は最初の依頼が届いた時点で書かれ、`turns` はターンを終えたときにしか増えない。最初のターンの途中で
  プロセスが落ちる（コンテナが落ちる、control-plane が再起動する）と、`turns` が 0 のまま履歴が残り、次の依頼は毎回
  `--session-id` で断られる。
- Claude Code は、`cleanupPeriodDays`（既定 30 日）を過ぎた履歴を起動のときに消す。設定ディレクトリはエージェントの
  すべてのセッションで共有なので、ほかのセッションの起動で消える。残す理由があって保持期間（既定 30 日）を過ぎて
  残ったセッションに次の依頼が来ると、`turns` が 1 以上のまま履歴がなく、毎回 `--resume` で断られる。

Slack ではスレッドから ID が決まるので、どちらもそのスレッドでは続けられなくなる。

## Decision

- エージェントの設定ディレクトリに、その ID の会話の履歴（`projects/*/<ID>.jsonl`）があれば `--resume`、なければ
  `--session-id` で起動する。`turns` は見ない。ID は UUID なので、Claude Code が作業ディレクトリから決める `<dir>` の
  名前の付け方は知らなくてよい。
- 判断は、Claude Code の起動の仕方を持つ runner（`internal/adapter/docker`）が `Start` で行う。

## Alternatives

- **`turns` が 1 以上なら `--resume` にし、0 のときだけ履歴を見る**：control-plane が設定ディレクトリを一覧できなくても、
  続いていたセッションを `--resume` で起動できる。ただ、履歴が消えたセッションは続けられないまま残る。一覧できない
  のは control-plane とエージェントのユーザーが食い違うときで、片付け（`SessionFiles.Remove`）も同じ一覧に頼るので、
  そろえる前提はすでにある。
- **`--session-id` が断られたら `--resume` で起動し直す（とその逆）**：Claude Code のエラーの文面に頼り、起動を二度
  試す処理がプロセスの扱いに入る。履歴を見れば、起動の前に決まる。
- **最初の依頼を送る前に、記録に「始めた」と書く**：プロセスが依頼を受け取る前に落ちると、履歴がないのに
  `--resume` で起動し、断られる。履歴が消える場面も解けない。正は Claude Code が持つ履歴で、記録はその写しになる。

## Consequences

- 最初のターンの途中で落ちたセッションも、次の依頼で会話を引き継いで続けられる。
- 履歴が消えたセッションは、断られずに新しい会話で始まる。作業領域とブランチは残るが、それまでの会話の文脈は
  引き継がない。
- 記録だけが消えて会話の履歴が残ると、同じ ID の新しいセッションは、古い会話を `--resume` で引き継ぐ。片付けは
  履歴を記録より先に消すので、ふだんはこの状態にならない。
- runner は、Claude Code が会話の履歴を設定ディレクトリの `projects/*/<ID>.jsonl` に置くことを前提にする。Claude Code が
  この置き場所を変えると、履歴のあるセッションを `--session-id` で起動して断られる。control-plane が設定ディレクトリを
  一覧できないときも同じになる。
- 最初のターンの途中で落ちたセッションでは、`reported_usage` がなく `turns` が 0 なので、次のターンの使用量は、
  最初のターンの前と同じく 0 と比べて出す。Claude Code が再開で前のプロセスの合計を引き継ぐなら、落ちたターンの分も
  次のターンに含まれる。引き継ぐかは確かめていない。
