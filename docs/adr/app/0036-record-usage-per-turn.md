# 0036. ターンごとの使用量を、セッションの合計の差として一つのファイルに残す

## Context

エージェントやターゲットを増やすかを決めるのに、誰の依頼で、どのエージェントの、どのセッションのターンが、どれだけ
使ったかを知りたい（Issue #8）。

Claude Code は、ターンを終えるたびに `result` イベントを出す。Claude Code の文書（Agent SDK の「Track cost and usage」、
2026-10-18 に読んだ）によると、control-plane のように一つのプロセスに続けて依頼する形（stream-json の入力）では、
`result` の値の範囲が次のように違う。

- `total_cost_usd` と `modelUsage`（モデルごとのトークン数と費用）は、プロセスが始まってからの合計で、サブエージェントの分も
  含む。`--resume` で続けたセッションでは、前のプロセスが正常に終わったときに保存した合計から数え始める（v2.1.277 から。
  それより前は 0 から）。`/clear` で数え直す。このリポジトリのイメージは 2.1.292。
- `usage` は、そのターンのメインのループの分だけで、サブエージェントの分を含まない。
- Claude Code が落ちたときの最後の `result` は、値がすべて 0 のことがある。
- 費用は、Claude Code が手元の価格表で見積もった値で、請求の値ではない。

control-plane は、セッションごとに Claude Code を一つのプロセスで動かし続け、休ませたあとは `--resume` で続ける
（ADR 0017）。プロセスは、休ませるときは入力を閉じて終わらせる。control-plane が止まらずに消えたときは、次の起動で
残ったコンテナを消す（ADR 0024）。セッションの記録は、保持期間を過ぎると片付けで消える（ADR 0026）。

## Decision

- ターンの使用量は、`result` の `total_cost_usd` と `modelUsage`（セッションの合計）から、前のターンのあとの合計を
  引いて出す。合計のどれかが前より小さければ数え直したものとみなし、報告された合計をそのターンの分とする。
  0 だけの報告は合計を表さないものとして、前の合計を持ち越す。
- 前のターンのあとの合計は、セッションの記録（`session.json` の `reported_usage`）に持つ。プロセスをまたいでも、
  Claude Code が保存した合計と比べられる。最初のターンの前は 0 とする。
- 合計が分からないときは、そのターンの使用量を「分からない」として残し、報告された合計を次のターンと比べる値にする。
  分からないのは、記録に合計がない（この変更より前からある）セッションと、前のプロセスが正常に終わらなかった（自分で
  終わった、閉じても時間内に終わらず止めた、残ったコンテナとして消した）セッション。Claude Code が合計を保存して
  いないかもしれないため。
- 残す先は、設定 `usage_log`（必須）のファイル一つ。ターンを終えるたびに、終えた時刻、エージェント、セッション、
  スレッド、依頼者、エージェントが自分で始めたか、終わり方、ターンの使用量、報告された合計を、JSON の 1 行として
  足す。エージェントが自分で始めたターンの依頼者は、そのエージェントが続けている依頼の依頼者（共著者と同じ）とし、
  新しいプロセスが依頼を取り込む前に自分で始めたターンでは、その依頼の依頼者とする。
  ターンの出力は残さない。
- 書けなかったときは、ログに残してターンは続ける。

## Alternatives

- **`usage` をターンごとに足す**：プロセスをまたいでも差を取らずに済むが、サブエージェントの分が入らない。
  レビューをサブエージェントにさせるので、使用量の多くが抜ける。
- **assistant のメッセージのトークン数を足す**：出力のトークン数は仮の値で、サブエージェントの分とも分けにくい。
- **セッションの記録に合計だけを持つ**：記録は片付けで消え、誰の依頼かも分からない。
- **セッションのディレクトリに置く**：同じく片付けで消える。
- **control-plane のログ（slog）に出す**：コンテナのログは作り直すと消え、集計しにくい。
- **ローテーションや DB**：一人が手元で使う量なら、1 行ずつ足すファイルで足りる（ADR 0008）。

## Consequences

- `jq` などで、エージェント、依頼者、セッション、日ごとに足し合わせられる。費用は見積もりなので、請求の確認には
  使わない。
- 今の `acp.yaml` には `usage_log` を足す必要がある。ないと `acp serve` が起動しない。
- 今あるセッションの、この変更のあとの最初のターンは使用量が分からない。2 つ目のターンからは数えられる。
- プロセスが落ちた、または control-plane が強制終了したあとの最初のターンも、使用量が分からない。
- ターンの途中でプロセスを閉じた（`result` が出なかった）ターンは行にならない。Claude Code が正常に終わって合計を
  保存していれば、その分は同じセッションの次のターンに含まれる。そのターンの依頼者が別の人なら、別の人の分になる。
- v2.1.277 より前の Claude Code のターゲットでは、休ませたあとの最初のターンの使用量が少なく出ることがある。
- `result` の値の範囲は文書で確かめたもので、実物の出力では確かめていない。
