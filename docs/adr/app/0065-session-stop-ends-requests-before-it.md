# 0065. セッションの停止は、止める前に届いた依頼をすべて止め、あとに届いた依頼は止めない

## Context

セッションの停止（`Dispatcher.Stop`、HTTP API と `acp stop`）は、ワーカーに停止を渡し、ワーカーが待ち行列と送った
依頼を取り消してエージェントの作業を止める。受け取り待ちの依頼（ADR 0059）には触れないので、ワーカーがエージェントを
起動している間などに届いた依頼は、停止のあとにワーカーが受け取って送り、動いていた（Issue #288）。ADR 0059 は、この
振る舞いを変えずに残していた。

試験で確かめると、ワーカーが起動中に止めた場合、止める前に届いた受け取り待ちの依頼は停止で答えを受け取らず、停止の
あとに送られた。逆向きのずれもあった。停止を渡してからワーカーがそれを扱うまでに届いた依頼は、ワーカーが停止より
先に受け取り待ちの依頼を選ぶと（select の選び方）、受け取って送ったあとに停止で取り消された。

## Decision

- 境目は `Stop` を呼んだ時点にする。止める前に届いた依頼はすべて止め、あとに届いた依頼は止めない。
- `Stop` は、受け取り待ちの依頼をすべて取り消し、同じロック（`Dispatcher` の `mu`）の下でワーカーに停止を渡す。
  依頼ごとの停止が受け取り待ちの依頼を取り消すのと同じ所で扱う。
- ワーカーは、受け取り待ちの依頼を受け取るとき（`takeArrival`、同じロックの下）に渡された停止が残っていれば、
  先に停止を扱ってから受け取る。ロックの下では、`Stop` が取り消したあとに残っている依頼は、停止のあとに届いたもの
  だけになる。
- 受け取り待ちの依頼をすべて取る処理は、control-plane が止まるときと一つにする（`worker.takeArrivals`）。

## Alternatives

- **ワーカーが停止を扱うときに受け取り待ちの依頼を取り消す**：停止を渡してからワーカーが扱うまでに届いた依頼も
  取り消す。ワーカーが起動中だと、取り消した依頼に答えるのも起動が終わるまで待つ。
- **今の振る舞いを意図どおりとして残す**：止めたのに、止める前の依頼が動く。止めた人は、何が止まったかを
  依頼の段階から推しはかれない。
- **停止を受け取り待ちの一覧に印として入れ、ワーカーが順に扱う**：一覧が依頼と停止の二種類を持ち、依頼ごとの停止の
  探し方と control-plane が止まるときの扱いも変わる。ロックの下で取り消して、停止の印を受け取るときに確かめる方が
  小さい。

## Consequences

- `acp stop` のあとに、止める前に届いた依頼が動くことはない。取り消された依頼には、停止で取り消されたと返る。
- 止めたあとに届いた依頼は、停止を扱ったあとに受け取るので、その停止では取り消されない。
- 境目は、停止が依頼を取り消すかについてのもの。止めたあとに届いた流し込む依頼は、中断を送ったターンが終わる前なら
  そのターンに送られる。エージェントが中断の前にそれを取り込めば、中断されたターンの結果を受け取る。これは中断を
  待つターンへの流し込みの振る舞いで、停止の前から同じ。
- ワーカーが一つの停止を扱う前に `Stop` が続けて呼ばれると、停止はまとめて一度扱う（停止の受け渡しは 1 件）。
  受け取り待ちの依頼はそれぞれの `Stop` が取り消すので、止める範囲は変わらない。
