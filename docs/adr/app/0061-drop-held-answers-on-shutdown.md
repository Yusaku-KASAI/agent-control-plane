# 0061. control-plane が止まるときに処理を止めたら、待っている依頼があっても、持っておいた回答を捨てる

## Context

依頼の入らなかったターンが、バックグラウンドの処理を残して回答（「待ちます」など）を出すと、`AgentAnswers` は
その回答を持っておく（ADR 0028）。control-plane が止まるときに処理を止めると、`Dispatcher` は `SessionAbandoned` を
伝え、`AgentAnswers` は持っておいた回答を捨てて中断の知らせを出していた（ADR 0055）。

ただし `SessionAbandoned` は、待っている依頼（取り込まれた、送った、待ち行列、受け取り待ち）がないときだけ伝えていた。
待っている依頼には、その返事が中断を伝えるので、スレッドに同じ知らせを重ねないためだった。そのため、待っている
依頼があると、持っておいた回答は捨てられず、止まるときの `Flush` で投稿されていた。スレッドには、止められた処理に
ついて書いた「待ちます」と、待っていた依頼への中断の返事が並んだ（Issue #336）。ADR 0028 は、止まる直前に依頼が
届いたときだけに起き、投稿されるのはエージェントが実際に言ったことだとして、これを受け入れていた。

## Decision

- `Dispatcher` は、止まるときにターンかバックグラウンドの処理を止めたら、待っている依頼があってもなくても
  `SessionAbandoned` を伝える。待っている依頼があれば `RequestsTold` を付ける。
- `AgentAnswers` は、`SessionAbandoned` で持っておいた回答をいつも捨て、`RequestsTold` がなければ中断の知らせを
  投稿する。

## Alternatives

- **今の振る舞いを意図どおりとして、規則の表に書く**：持っておいた回答は、止めた処理の途中の様子で、そのあとに
  止めたので、もう正しくない。待っている依頼があるかどうかは、その回答が正しいかに関わらない。
- **待っている依頼があっても中断の知らせを出す**：待っている依頼への返事と同じ中断を、スレッドに二度出す。
- **止めるのとは別の出来事の種類（回答を捨てるだけ）を足す**：止めたという一つの事実を二つの種類に分け、
  `AgentAnswers` と Bot がどちらも見ることになる。止めた事実に、知らせが要るかの事実を添える方が小さい。
- **中断されたターンの終わり（`SessionTurnFinished` の `Interrupted`）で捨てる**：ターンがなくバックグラウンドの
  処理だけを止めたときには、その出来事がない。依頼ごとの停止で中断されたターンの回答は投稿するので、区別もつかない。

## Consequences

- 止まるときに処理を止めたら、待っている依頼があってもなくても、スレッドに持っておいた回答は出ない。
- 持っておいた回答が 15 秒の待ちの間（処理が尽きたあと）なら、止める処理がないので `SessionAbandoned` は出ず、
  今までどおり `Flush` で投稿する。
