# 0013. セッションのブランチはリモートのデフォルトブランチから切る

## Context

ADR 0012 では、セッションのブランチは元のリポジトリでその時点にチェックアウトしているコミットから始まった。
手元で別のブランチをチェックアウトしていたり、手元の main がリモートとずれていたりすると、その状態が
PR に入り込む。ターンごとに GitHub App のトークンを発行できるようになった（ADR 0011）。

control-plane は将来コンテナとして動く（ADR 0004）。ホストのユーザーの git 設定や認証情報に頼る作りだと、
コンテナに移したときに振る舞いが変わる。

## Decision

- 作業領域を作るとき、エージェントのトークンで `origin` を fetch し、リモートのデフォルトブランチから
  セッションのブランチを切る。トークンが無いエージェントは、元のリポジトリの HEAD から切る。
- 作業領域を作る git の操作では、ホストのユーザーの git 設定、認証ヘルパー、SSH 鍵を使わない。認証には
  control-plane が発行したトークンだけを使う。

## Alternatives

- **リモートから直接 clone する**：毎回すべてのオブジェクトを取得することになる。手元の clone を土台にすれば
  差分の fetch で済む。
- **ホストのユーザーの git の認証を使って fetch する**：誰のマシンで動かすかで結果が変わり、コンテナに
  移すと動かない。
- **起点の調整をエージェントに任せる**：指示に従うかがモデル次第になる。

## Consequences

- 手元の作業ツリーの状態は PR に入らない。手元にしかないコミットを起点にしたい場合は、起点を指定する
  仕組みが別に要る。
- 作業領域の作成にもネットワークとトークンの発行が要る。
