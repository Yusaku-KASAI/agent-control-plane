# 0037. 終わった状態メッセージに、依頼とセッションの費用の見積もりを出す

## Context

ターンごとの使用量は `usage_log` に残る（ADR 0036）。ただし、見るにはファイルを集計する必要がある。人がスレッドを
見るだけで、1 回の依頼とセッション全体にどれだけかかったかを知りたい（Issue #175）。

状態メッセージは、依頼に答えるターンごとに出す（ADR 0019）。エージェントが自分で始めたターンは、最後の状態
メッセージを書き換えて使う（ADR 0028）。再開したセッションが依頼を取り込む前に自分で走らせたターンは、依頼の
ターンが隠す（ADR 0031）。1 つの状態メッセージは、一つの依頼から始まる仕事を追い、そこに複数のターンが入る。

ターンを終えたとき、worker はそのターンの使用量（分からないことがある）と、Claude Code が報告したセッションの
合計を知っている（ADR 0036）。費用は Claude Code の見積もりで、請求の値ではない。

## Decision

- 状態メッセージが終わった状態（完了、中断、失敗、使用上限で停止）のとき、
  「費用の見積もり：この依頼 $0.42・セッションの合計 $3.10」の行を出す。実行中は出さない。
- 「この依頼」は、その状態メッセージが追ったターン（隠したターンと、引き継いだ自分で始めたターンを含む）の費用の
  和。どれか一つでも分からなければ「不明」とする。`result` の出なかったターンは分からないものとする。
- 「セッションの合計」は、最後に終わったターンのあとのセッションの合計（Claude Code の報告。0 だけの報告のときは
  前の合計）。
- 費用だけを、ドルで小数 2 桁まで出す（0.005 ドル未満は「$0.01 未満」）。トークン数は出さない。
- `result` のあるターンが一つもなければ、行を出さない。
- worker はターンを終えた知らせ（`SessionEvent.Spent`）でこの値を渡し、どう見せるかは slackbot が決める。
- CLI（`acp run`）の出力には出さない。

## Alternatives

- **ターンごとの費用を出す**：状態メッセージは引き継がれるので、最後のターンの分だけでは依頼の分にならない。
- **トークン数も出す**：モデルとキャッシュで単価が違い、人が読んで判断に使いにくい。`usage_log` にある。
- **セッションの合計を締めくくりのときだけ出す**：締めくくりは決まっていない（Issue #62）。毎回出せば待たずに分かる。
- **分からないターンを除いて和を出す**：少なく見えて、気づけない。

## Consequences

- 依頼のたびに、費用の見積もりがスレッドに残る。請求の確認には使わない。
- この変更より前からあるセッションの、変更のあとの最初のターンは「この依頼 不明」になる（ADR 0036）。
- 終わった状態メッセージを、自分で始めたターンが引き継ぐと、実行中は行が消え、終わるとまた出る。
