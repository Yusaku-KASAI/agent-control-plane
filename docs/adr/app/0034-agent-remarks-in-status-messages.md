# 0034. 状態メッセージに、エージェントの直近の発言を並べる

## Context

状態メッセージの「今の作業」（ADR 0019）は、エージェントの最新のメッセージの、最後のツール呼び出しかテキストの
1 行目を、1 行だけ上書きして示していた。エージェントが節目で書いた発見や方針の変更は、次のツール呼び出しで消えた。
エージェントが自分で始めたターンは状態メッセージを引き継ぐ（ADR 0028）ので、一つの状態メッセージが見せる期間は
長く、何を経てきたか、全体のどこにいるかは見えなかった。

control-plane で動いたセッションの記録（Claude Code 2.1.292、12 本）では、次のことが分かった。
- 計画を表すツール（TodoWrite など）は使われていない。発言の階層や粒度を表す印もない。分かるのは、エージェント
  本体の発言か、サブエージェントの発言かだけ。
- `assistant` のメッセージは、テキストとツール呼び出しのブロックが一つずつ別の出来事として出る。
- エージェント本体のテキストのうち 7〜9 割は、ツール呼び出しの直前の前置き（「〜を読みます」）。
- エージェント本体のテキストを 1 行にした長さは、中央値が 59 文字、4 分の 3 が 82 文字以下。長いものは
  ほとんどが回答。

## Decision

- エージェント本体（サブエージェントではない）の `assistant` のメッセージのテキストを、エージェントの発言とする。
  状態メッセージでは、発言を 1 行にし、100 文字で切る。
- 「今の作業」は、最後のツール呼び出しか、サブエージェントのテキストにする。エージェント本体のテキストでは
  上書きしない。
- 状態メッセージは、実行中の間、直近の 10 件の発言を古い順のリストとして「今の作業」の上に示す。発言は状態
  メッセージが持ち、エージェントが自分で始めたターンが引き継いでも残る。依頼に答えるターンの新しい状態
  メッセージは、空から始める。
- ターンが終わったあとの状態メッセージには、発言を示さない。ターンが終わったとき、末尾の発言のうち回答の一部である
  ものを、発言から除く。回答は回答として扱われる（スレッドに投稿されるか、ADR 0028 のとおり持っておいて捨て
  られる）ので、引き継いだターンで発言として示し直さない。発言が回答の一部かは、`result` の文面に含まれるかで
  見る。

## Alternatives

- **発言の階層や粒度で選んで見せる**（節目の発言だけを残す、など）：出力に階層や粒度の印がなく、前置きと節目の
  一言を見分ける確かな手掛かりもない。件数を多くして、前置きごと流れを見せる。
- **直近の 2 件だけを見せる**：前置きが多いので、節目の一言はツール呼び出し 2 回で押し出される。
- **直近の作業（ツール呼び出し）を数件並べる**：何をしたかは分かるが、エージェントが何を見つけ、どう方針を
  変えたかは分からない。
- **発言をスレッドに投稿する**：通知が増え、スレッドが途中の報告で埋まる。状態メッセージの書き換えは通知しない。
- **終わったあとも発言を示す**：終わったら回答を読めばよく、途中の流れは要らなくなる。最後の発言はたいてい回答
  そのもので、回答の投稿とも重なる。

## Consequences

- 実行中の状態メッセージは、発言の分だけ最大でおよそ 1,000 文字長くなる。終わると発言を示さない小さな形に戻る。
  書き換えの回数は変わらない（5 秒ごとと、変化から 1 秒まとめたあと）ので、Slack の API の回数制限への影響はない。
- 発言の多くは前置きなので、10 件はおよそツール呼び出し 10 回分の流れになる。節目の一言も、その間は残る。
- テキストだけのメッセージのあとも、「今の作業」は直前のツール呼び出しのまま残る。
- 回答の最初の部分は、ターンが終わるまでの短い間、発言として示される。
- 回答の一部かは文面に含まれるかだけで見るので、回答の本文にたまたま含まれる短い発言（「確認します。」など）が
  末尾に続いていれば、それも除かれる。除かれても、実行中ではない状態メッセージから消えるだけで、失うものは小さい。
- `result` の文面に、回答の最後のメッセージのすべてのテキストのブロックが入ることを前提にしている。最後の
  ブロックだけなら、前のブロックは発言に残り、引き継いだターンで示される。どちらかは実物では確かめていない。
- 送った依頼より先にエージェントが自分で走らせたターン（ADR 0031）は、終わったことを伝えないので、その回答は
  発言に残る。その回答はどこにも投稿されずに捨てられるので、発言として見える方がよい。
- 発言は Markdown のままリストに入れる。コードの囲みを含む発言や、強調やリンクの途中で切った発言は、表示を
  崩しうる。崩れるのは見え方だけで、「今の作業」も同じ形で出している。
- 発言はメモリにだけ持つので、control-plane を再起動すると消える。
- Slack での実際の見え方は、実物では確かめていない。
