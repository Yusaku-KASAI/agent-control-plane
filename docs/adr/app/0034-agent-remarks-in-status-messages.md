# 0034. 状態メッセージに、エージェントの直近の発言を残す

## Context

状態メッセージの「今の作業」（ADR 0019）は、エージェントの最新のメッセージの、最後のツール呼び出しかテキストの
1 行目を、1 行だけ上書きして示していた。エージェントが節目で書いた発見や方針の変更は、次のツール呼び出しで消えた。
エージェントが自分で始めたターンは状態メッセージを引き継ぐ（ADR 0028）ので、一つの状態メッセージが見せる期間は
長く、何を経てきたかはなおさら見えなかった。

Claude Code は、文を出さずに作業が続くと、エージェントに一言書くよう促す。その一言は、ツール呼び出しとは別の
テキストのブロックとして、`assistant` のメッセージに入る。

## Decision

- エージェント本体（サブエージェントではない）の `assistant` のメッセージのテキストを、エージェントの発言とする。
  一つのメッセージのテキストを空白でつないで 1 行にし、200 文字で切る。
- 「今の作業」は、最後のツール呼び出しか、サブエージェントのテキストにする。エージェント本体のテキストでは
  上書きしない。
- 状態メッセージは、実行中の間、直近の 2 件の発言を引用として「今の作業」の上に示す。発言は状態メッセージが
  持ち、エージェントが自分で始めたターンが引き継いでも残る。依頼に答えるターンの新しい状態メッセージは、空から
  始める。
- ターンが終わったあとの状態メッセージには、発言を示さない。ターンが終わったとき、最後の発言が回答の始まりなら、
  それを発言から除く。回答はスレッドに投稿されるので、引き継いだターンで発言として示し直さない。

## Alternatives

- **直近の作業（ツール呼び出し）を数件並べる**：何をしたかは分かるが、エージェントが何を見つけ、どう方針を
  変えたかは分からない。数件のツール呼び出しは、長い作業では数秒で流れる。
- **発言をスレッドに投稿する**：通知が増え、スレッドが途中の報告で埋まる。状態メッセージの書き換えは通知しない。
- **終わったあとも発言を示す**：最後の発言はたいてい回答そのもので、回答の投稿と重なる。

## Consequences

- 状態メッセージは、発言の分だけ最大でおよそ 400 文字長くなる。書き換えの回数は変わらない（5 秒ごとと、変化から
  1 秒まとめたあと）ので、Slack の API の回数制限への影響はない。
- テキストだけのメッセージのあとも、「今の作業」は直前のツール呼び出しのまま残る。
- 回答の最初の部分は、ターンが終わるまでの短い間、発言として示される。
- ツール呼び出しの前の短い前置き（「〜を読みます」）も発言に数える。節目の一言が残る時間は、そのあとの前置きの
  多さで決まり、前置きが 2 回続けば押し出される。前置きを見分ける確かな手掛かりはないので、見分けない。
- 発言はメモリにだけ持つので、control-plane を再起動すると消える。
- Slack での実際の見え方は、実物では確かめていない。
