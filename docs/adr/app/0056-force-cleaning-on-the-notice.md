# 0056. 強制の片付けは、残す理由を返した知らせのメッセージへの `:fire:` で受け、時刻から推し量る条件を持たない

## Context

ADR 0046 は、強制の片付け（`:fire:`）をスレッドの最初のメッセージへのリアクションにした。そのため、`:fire:` が
理由の知らせのあとに、知らせを見て付けられたことを、時刻から推し量る条件を重ねていた：Slack の時計で知らせから
10 秒より後、control-plane の時計でも知らせから 10 秒より後（切断のあとに続けて届いたとき）、知らせの Slack の時刻は
`:wastebasket:` の時刻に判定にかかった時間を足して見積もる。条件は本人、`last_used_at`、1 時間、理由の包含と合わせて
6 つになり、依頼の仕方と知らせの文面にまで出ていた（#283 の H、#285）。ADR 0046 は、条件が増えて重くなれば
見直すと書いていた。

## Decision

- 強制は、`:wastebasket:` に残す理由を返した知らせのメッセージへの `:fire:` で受ける。知らせが出る前は付ける所が
  ないので、知らせのあとに付けたことは形で決まり、時刻から推し量る条件（読む時間と、二つの時計の比べ）を持たない。
- 知らせ（`SessionNotifier.Notify`）は、投稿したメッセージの ID を返す。`SessionCleaner` は、本人への知らせに、
  どのエージェントの、どの会話のチャンネルの、どのメッセージかを持ち、`:fire:` が付いたメッセージと照らす
  （`ForceClean`）。チャンネルにいるどのエージェントの Bot もリアクションを受けるので、自分の知らせだけを取る。
- 強制として受ける条件は、知らせを受けた本人が付けた、知らせてから 1 時間のうち（control-plane の時計）、
  知らせのために読んだ `last_used_at` が変わっていない、今の理由がどれも知らせた理由にある（ロックの下でも）、の 4 つ。
- 知らせのメッセージでないもの、ほかの人、1 時間を過ぎたもの、再起動で忘れたもの、新しく知らせ直したあとの古い
  知らせへの `:fire:` は、何もせず、何も返さない。`:fire:` はどのメッセージにも称賛で付きうるので、返事をすると
  スレッドを荒らす。スレッドの最初のメッセージへの `:fire:` も同じく何もしない。
- 本人の `:fire:` が、そのあとの使用か、知らせていない理由（ロックの下で見つけたものも）で止まったときは、今の理由を
  新しい知らせとして返し、その知らせへの `:fire:` を受ける。`:wastebasket:` からのやり直しは求めない。新しい知らせの
  あとに付けるので、知らせを見て付けたことは同じく形で決まる。
- 本人の `:fire:` のときに残す理由がなくなっていれば、そのまま消す。
- 開いている PR は、ADR 0046 と同じく強制でも残す。

## Alternatives

- **今のまま（最初のメッセージへの `:fire:` と 6 つの条件）**：条件の多くは時刻から推し量るためのもので、依頼の
  仕方と文面を重くし、二つの時計を比べることになる。
- **残した知らせに付けるボタン（Slack の Block Kit）**：知らせの上にしか押す所がないので、時刻の条件が要らなくなるのは
  同じ。ただ、Slack アプリのインタラクティビティの設定、ボタンの操作を受けるアダプタ、blocks の知らせが増える。
  押したことは画面に残らず、押したあとと片付けたあとの状態を見せるには、アプリが `chat.update` で知らせを書き換え
  続けることになる。リアクションは、誰が何を付けたかが見える状態として残り、停止（ADR 0039）と `:wastebasket:` とも
  操作がそろう。
- **リアクションの場所はそのままで、時刻の条件を外す**：コードと文書を削るだけで済むが、理由を読む前の `:fire:`
  （`:wastebasket:` とほぼ同時に付けたもの、切断のあとに続けて届いたもの）が通り、代わりの守りがない。
- **確認する代わりに、取り消せる片付けにする**（消さずに置き場所に移し、期間のあとに消す）：確認そのものが要らなく
  なるが、戻す手順と置き場所が新しく要る。
- **知らせの ts をセッションの記録に持つ**：再起動のあとも強制が効く。ADR 0046 と同じく、休んでいるワーカーが記録の
  ロックを持つあいだは書けない。窓が 1 時間なので、再起動で忘れても `:wastebasket:` から付け直せば足りる。
- **ADR 0046 が知らせへのリアクションを選ばなかった理由（ポートを変え、長いスレッドで知らせを探す）**：ポートの
  変更は、投稿の ID を返すだけで、Slack 以外の知らせ先は空を返せばよい。人は理由を読んだすぐあとに付けるので、
  探す手間は小さい。

## Consequences

- 依頼の仕方と知らせの文面から、時刻と時計の条件が消える。
- 知らせのメッセージでない所に付けた `:fire:` には返事がない。1 時間を過ぎたときや再起動のあとに付けても何も
  返らないので、人は文面の「1 時間のうちに」と、`:wastebasket:` からの付け直しに頼る。
- `SessionNotifier` を実装するものは、投稿したメッセージの ID を返す。
- Slack アプリのスコープとイベントは変わらない。
