# 0045. エージェントは、control-plane のバイナリをコンテナに置いた `acp cleanup-check` で、片付けと同じ判定を作業領域の中から見る

## Context

片付けで残す理由（ADR 0026 の判定）は、control-plane の usecase（`reasons`）の 1 か所にある。エージェントはそれを
見られず、ハーネスの契約のコンテナの寿命に文で写した条件を読んで自分で判断していた。写しは判定とずれうる
（#62 の PR のレビューで抜けが見つかった）。片付けの役割の分け方（#220）で、判定は control-plane だけが持ち、
エージェントは判定を見て理由を解く、と決めた。判定を見る道具は、control-plane への依存がない（少ない）形にし、
ネットワーク越しに control-plane を呼ぶ形はとらない（依頼者）。

ADR 0043 で、control-plane は起動のたびに自分のバイナリを `tools.dir`（`acp-tools` ボリューム）に置き、作業領域を
読むコンテナに渡すようになった。

## Decision

- エージェントのコンテナにも、`tools` の置き場を `/run/acp/bin` に読み取り専用でマウントする。
- `acp cleanup-check` は、作業ディレクトリの作業領域について、片付けと同じ事実の集め方と判定（usecase の
  `CheckCleanup`、中は `readFacts` と `reasons`）で、保持期間によらず残す理由を出す。セッションのブランチは
  `ACP_SESSION_BRANCH`、GitHub のトークンは `GH_CONFIG_DIR` の gh の設定から読む。作業領域はその場で読む（エージェント
  自身のコンテナなので、ADR 0043 の読むコンテナは要らない）。
- 出力は、理由ごとに種類（`open-pull` など）とタブと文面を 1 行。種類の一覧と意味は、ハーネスの契約のコンテナの寿命に
  書く。契約は、片付けを止める条件を文で並べるのをやめ、コマンドと種類の表にする。
- 判定の文面（スレッドへの知らせとコマンドの出力）は、理由ごとに一か所（`reason.text`）で決める。

## Alternatives

- **判定をプラグインのスクリプトなどで作り直す**：判定の写しが増え、ずれる。プラグインが control-plane の中身を
  前提にすることにもなる。
- **control-plane の HTTP API で判定を返す**：エージェントのコンテナから control-plane にネットワークで届かせることに
  なる（今は届かない）。依頼者が避けたい形。
- **control-plane が判定を書いたファイルを、認証情報のように置いておく**：判定はエージェントが片付けるたびに変わるので、
  置いた時点のものは古くなる。
- **エージェントのイメージに `acp` を入れる**：イメージはターゲットのもので、ターゲットに control-plane の版を追わせる
  ことになる。

## Consequences

- エージェントのコンテナは、control-plane と同じアーキテクチャで、静的にビルドした `acp` を実行できることを前提にする
  （ADR 0043 と同じ）。
- `acp cleanup-check` は GitHub の API を、片付けと同じくブランチごとに何度か呼ぶ。
- 判定や理由の種類を変えたら、ハーネスの契約の種類の表も直す。締めの手順（#225）は、この種類ごとの解き方を引く。
- devcontainer で直接動くときは、片付けもこのコマンドもない。
