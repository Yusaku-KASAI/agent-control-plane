# 0009. 会話の単位をセッション、1 回の依頼をターンとして扱う

## Context

Slack のスレッドのように、同じエージェントに続けて依頼し、前の会話と作業を引き継ぎたい。エージェントの
コンテナは依頼ごとに使い捨てにする。Claude Code は `--session-id <UUID>` で始めた会話を `--resume <UUID>` で
続けられ、会話履歴を作業ディレクトリごとに保存する。

## Decision

- 会話が続く単位をセッション、セッション内の 1 回の依頼をターンとする。ターンごとにコンテナを作り、
  `claude -p` を 1 回実行する。
- セッションは 1 つのエージェントに属し、作業領域（ADR 0010）と Claude Code の会話を 1 つずつ持つ。
  別のエージェントでは続けられない。
- セッション ID は UUID とし、そのまま Claude Code のセッション ID に使う。最初のターンは `--session-id`、
  以降は `--resume` で起動する。コンテナ内の作業ディレクトリはセッションの間変えない。
- セッションの記録は `<sessions.root>/<セッションID>/session.json` に置く。同じセッションのターンは同時に
  1 つだけ実行し、ファイルロックで守る。
- 会話履歴は当面、`claude.config_volume` の Claude Code 設定ディレクトリにまとめて保存する。

## Alternatives

- **依頼ごとに独立させ、会話を引き継がない**：スレッドで続けて依頼できない。
- **セッションの対応表を別に持ち、Claude Code のセッション ID と分ける**：対応を管理する手間が増えるだけで、
  分ける理由が今はない。
- **セッションごとに Claude Code の設定ディレクトリを分ける**：履歴は分かれるが、ログイン情報を
  セッションごとに渡す仕組みが要る。認証方式の差し替え（ADR 0007）と合わせて扱う。
- **DB に記録する**：1 台で動かすうちはファイルで足りる（ADR 0008）。

## Consequences

- Slack など外部の会話単位からは、決まった規則で UUID を導けば同じセッションを続けられる。
- 会話履歴は、設定ディレクトリを共有する他のセッションや開発用の対話と同じ場所に溜まる。
- 古いセッションは `<sessions.root>/<セッションID>/` ごと消せば片付く。
