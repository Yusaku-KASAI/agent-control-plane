# 0030. バックグラウンドの処理を止めたあとにエージェントが自分で始めるターンは、ほかの自分で始めたターンと同じに扱う

## Context

ADR 0019 は、`stop_task` で止めた処理による再開は起きないとした。ADR 0028 は、エージェントが自分で始めたターンの
回答をバックグラウンドの処理が残る間は持っておくとし、次の 2 つを確かめていないとした。

- サブエージェント（Agent）の処理での、処理の終わりと次のターンの始まりの順。
- 依頼者がセッションを止めたとき（`stop_task`）に、処理の数が空になった知らせが来るか。

依頼者が Claude Code 2.1.292 を control-plane と同じ引数（stream-json の入出力、`--replay-user-messages`、
`--verbose`）で動かし、`stop_task` を control-plane と同じ `control_request` で送って確かめた（Issue #98）。どれも、
ターンが終わってエージェントの手が空いているときの出来事。

| 場面 | 出来事の順 | 次のターン |
| --- | --- | --- |
| バックグラウンドの Bash を `stop_task` で止める | `task_updated`、`task_notification`（stopped）、`background_tasks_changed`（空）、`control_response`。同じ時刻 | 始まらない（50 秒以上見た） |
| バックグラウンドのサブエージェントを `stop_task` で止める | 同上 | 約 0.03 秒後に始まる。回答は止まったことを伝える一言 |
| サブエージェントが自分で終わる | `task_notification`（completed）、`background_tasks_changed`（空）、約 0.04 秒後に次のターンの `system/init` | 始まる |

ADR 0019 の「再開は起きない」は、Bash の処理では正しいが、サブエージェントの処理では外れる。

## Decision

- サブエージェントの処理を止めたあとに Claude Code が自分で始めるターンも、ほかの自分で始めたターンと同じに
  扱う（ADR 0028）。持っておいた回答は、このターンが始まった時点で捨てられ、このターンの回答（止まったことを
  伝える一言）が投稿される。
- ADR 0028 の判断（処理が尽きてから 15 秒待つことを含む）は変えない。

## Alternatives

- **止めた直後に始まるターンの回答を投稿しない**：止めた人には止まったことが伝わればよく、持っておいた回答を
  代わりに出す方が中身はある。ただ、どのターンが止めたことで始まったかを見分ける知らせはなく、時刻で推し量る
  ことになる。増えるのは止めたときの一言だけで、止めた人への返事として害がないので、仕組みを足さない。

## Consequences

- 止めたときも処理の数が空になった知らせは来るので、ワーカーが古い処理の数を持ち続けることはない。
- Bash の処理を止めたときは次のターンが来ないので、持っておいた回答は 15 秒待ってから投稿される（ADR 0028 の
  想定どおり）。
- サブエージェントの処理を止めたときは、`:no_entry_sign:` のあとにエージェントの回答が一つ増え、持っておいた
  回答は投稿されない。
- サブエージェントの処理でも、処理の終わりと次のターンの始まりの順は Bash と同じなので、15 秒の待ちで足りる。
- ターンの実行中に止めた（`interrupt` と `stop_task` が重なる）場合の順と、実際の Slack での見え方は確かめていない。
