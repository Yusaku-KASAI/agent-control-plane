# 0039. チャットでの停止は、依頼のメッセージへの `:no_entry_sign:` で、その依頼の段階に合わせて行う

## Context

チャットでは、状態メッセージに `:no_entry_sign:` を付けるとセッションを停止する（ADR 0019）。止まるのは、実行中の
ターン、バックグラウンドの処理、受信箱の依頼の全部で、依頼を一つだけ取り消す手段はない。依頼のメッセージに
付けても何も起きず、止まらないとき（再起動の前の状態メッセージ、依頼できない人、何も動いていない）も何も返らない。

依頼のメッセージには、受け付けた、取りかかった、終わったがリアクションで付く（ADR 0038）。依頼した人が見て、
触るのは、自分の依頼のメッセージである（Issue #185）。

## Decision

- 状態メッセージへの `:no_entry_sign:` で止める形をやめ、依頼のメッセージへの `:no_entry_sign:` で止める。ワーカーは
  依頼の段階に合わせて、次のように動く。
  - 受信箱で待っている（エージェントにまだ送っていない）：その依頼だけを取り消す。
  - エージェントに渡した（送ったがまだ取り込まれていない、または実行中のターンに取り込まれた）：エージェントの作業を
    止める。実行中のターンの中断、バックグラウンドの処理の停止、送ったがまだ取り込まれていない依頼の取り消しを
    行う。受信箱で待っているほかの依頼は残し、そのあと順に送る。
  - 終わっている：何もしない。ただし、それがエージェントに最後に渡した依頼で、答えたあともエージェントが自分で
    動いている（自分で始めたターン、バックグラウンドの処理）ときは、エージェントの作業を止める。受信箱で待っている
    依頼や取り消した依頼は、まだエージェントに渡していないので「最後に渡した依頼」にならない。
- 依頼のメッセージがどのスレッドのものかは、Bot がメモリに 24 時間覚える。覚えていないメッセージ（再起動の前の
  依頼、依頼でないメッセージ）への `:no_entry_sign:` は何もしない。
- 止められるのは、そのエージェントに依頼できる人だけにする（ADR 0019 のとおり）。
- 取り消した依頼と中断した依頼には、今までどおり知らせを返し、`:no_entry_sign:` を付ける（ADR 0038）。それ以外に
  返事は足さない。
- HTTP API と CLI の停止（`acp stop`）は、今までどおりセッション全体を止める。

## Alternatives

- **状態メッセージへの停止を残し、依頼のメッセージへの停止を足す**：止め方が二つになり、どちらで何が止まるかを
  覚える必要がある。依頼した人は、状態メッセージより自分の依頼のメッセージを見ている。
- **処理中の依頼を止めるときに、待っているほかの依頼も取り消す**：今の状態メッセージでの停止と同じになるが、
  ほかの依頼まで消える。待っている依頼は、それぞれのメッセージで取り消せる。
- **終わった依頼には、いつも何もしない**：答えたあとにエージェントが自分で動き続ける間（CI を待つなど）、Slack から
  止める手段がなくなる。
- **止まったか、止めるものがなかったかを返事で返す**：何も起きない場合のほとんどは、すでに終わった依頼で、リアク
  ション（`:white_check_mark:` など）で分かる。返事は投稿を増やす。

## Consequences

- 依頼を一つだけ取り消せる。処理中の依頼を止めても、待っているほかの依頼は進む。
- 状態メッセージに `:no_entry_sign:` を付けても止まらない。状態メッセージには、依頼のメッセージに付けるよう書く。
- 送ったがまだ取り込まれていない依頼は、Claude Code の入力に残る。今までの停止と同じく、Claude Code があとで
  取り込むと、エージェントが自分で始めたターンとして動きうる。
- 新しいスレッドの最初の依頼は、セッションを作る間（作業領域の clone など）、ワーカーにまだ届いていないので、
  `:inbox_tray:` が付いていても取り消せない。
- Slack アプリのスコープとイベント（`reactions:read`、`reaction_added`）は変わらない。
