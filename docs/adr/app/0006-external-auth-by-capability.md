# 0006. 外部サービスの認証は、必要な機能ごとに提供方式を差し替えられるようにする

## Context

同じ外部サービスでも、使える認証方式は環境によって異なり、方式ごとにできることの組み合わせも異なる。
たとえば Slack では、トークンを払い出せる Bot なら読み取り・投稿・スレッドへの返信がすべてできる。
トークンを払い出せない場合は、読み取りを MCP、投稿を Incoming Webhook で行うことになり、投稿したメッセージを
あとから特定してスレッドで続けることはできない。

## Decision

- 拡張は外部サービスの機能（例：Slack の読み取り、投稿、スレッド返信）を、必須のものと、あれば使うものに
  分けて宣言する。
- どの方式（Bot トークン、MCP、Webhook など）で提供するかは、環境ごとに control-plane が割り当てる。
  必須の機能がそろわない環境では、その拡張を有効にしない。
- control-plane は、実際に使える機能を拡張に伝える。拡張はその組み合わせに応じて動作を切り替える。

## Alternatives

- **拡張が特定の認証方式を前提にする**：その方式が使えない環境では拡張ごと使えなくなる。
- **機能の組み合わせの違いを control-plane が吸収する**：方式ごとにできないことを control-plane が
  補うことはできず、無理に揃えると特定の方式に寄った作りになる。

## Consequences

- 同じ拡張が、認証方式の異なる環境でそのまま使える。
- 拡張は、使える機能の組み合わせごとの動作を実装する必要がある。
- control-plane に、機能と提供方式の対応を管理する仕組みが要る。
