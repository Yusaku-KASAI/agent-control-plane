# 0057. 片付けで消したセッションのスレッドの最初のメッセージに、Bot が `:broom:` を付け、同じスレッドで新しいセッションを作ったら外す

## Context

片付けの結果（ADR 0026、0046）は、スレッドへの投稿でだけ知らせていた。人は、スレッドを開いて投稿を読まないと、
そのスレッドのセッションが片付いたかを知れない。依頼のメッセージには、進み具合をリアクションで付けている
（ADR 0038）。人は、チャンネルの一覧で、最初のメッセージのリアクションから済んだかを読み取りたい（#318）。

## Decision

- 片付けで消したら（`:wastebasket:`、`:fire:`、保持期間のどれでも）、`SessionCleaner` は知らせの投稿のあとに、
  `SessionNotifier.MarkCleaned` でセッションの始まった所に印を付ける。Slack では、Bot がスレッドの最初のメッセージに
  `:broom:` を付ける。残したときは付けない。
- 絵文字は `:broom:` にする。最初のメッセージはたいてい最初の依頼でもあるので、依頼の進み具合のリアクション
  （`:white_check_mark:` など）と分ける。人の `:wastebasket:`（頼み）と同じ絵文字だと、数を見るか誰が付けたかを
  見ないと「頼んだ」と「済んだ」を見分けられない。
- 同じスレッドでセッションを作ったら、`Dispatcher` が `SessionCreated` を知らせ、Bot は最初のメッセージの `:broom:` を
  外す。片付けたあとに続けて依頼すると新しいセッションになり、印が残ると、動いているのに済んだと読める。
- 付けるときの `already_reacted`、外すときの `no_reaction` は失敗にしない。ほかの失敗は、付けるときは片付けの
  失敗として返す（スレッドへの「判定できませんでした」は出さない。消したことは知らせてある）。外すときはログに書く。
- Bot は自分のリアクションを頼みとして受けないので、`:broom:` が片付けや停止を動かすことはない。

## Alternatives

- **Bot が `:wastebasket:` を付ける**：人の `:wastebasket:` と一つにまとまり、数が 2 になるだけで、済んだかが読み
  取りにくい。保持期間で消したときは 1 つだけになり、人が頼んだのと見分けられない。
- **依頼の進み具合と同じ `:white_check_mark:`**：最初のメッセージが依頼のときは、答えたことと区別できない。
- **メッセージを書き換える**（最初のメッセージは人の投稿で、Bot は書き換えられない）か、**スレッドの知らせだけにする**：
  スレッドを開かないと分からない。
- **外さない**：新しいセッションが動いているあいだも済んだと読める。
- **外すのを依頼を受けたとき（メンションのたび）にする**：セッションを作らない依頼のたびに Slack を呼ぶ。印が付いて
  いるのは、片付けたあとに初めてセッションを作るときだけ。

## Consequences

- 人は、チャンネルの一覧で、最初のメッセージの `:broom:` から、そのスレッドのセッションが片付いたことを読み取れる。
- 一つのスレッドで複数のエージェントを使うと、Bot ごとに `:broom:` が付き、一つにまとまる。どのエージェントの分が
  済んだかは、誰が付けたかを見る。一つのエージェントで新しいセッションを作ると、そのエージェントの Bot の分だけが外れる。
- `SessionNotifier` を実装するものは、`MarkCleaned` を持つ。Slack 以外の知らせ先は何もしない。
- Slack アプリのスコープ（`reactions:write`）は今も使っていて、変わらない。
