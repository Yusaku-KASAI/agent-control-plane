# 0028. エージェントが自分で始めたターンは、依頼の状態メッセージを引き継ぎ、バックグラウンドの処理が残る間は回答を投稿しない

## Context

ADR 0019 は、ターンが始まるたびにスレッドへ状態メッセージを投稿するとした。エージェントが自分で始めたターンの
回答は、中身があれば必ずスレッドに投稿していた。

エージェントは、セルフレビューのサブエージェントや CI の待ち合わせをバックグラウンドで回す。処理が一つ終わる
たびにエージェントが自分でターンを始め、その多くは「結果を待ちます」とだけ答えて終わる。1 回の依頼で、状態
メッセージと待つだけの回答が十数件スレッドに並び、依頼者が要る回答が埋もれた。

エージェントへの指示で待つだけのターンを黙らせることもできるが、指示は守られないことがある。

control-plane は、ターンの終わり（`result`）、バックグラウンドの処理の数の変化（`background_tasks_changed`）、
ターンの始まり（`system/init`）を、Claude Code が出した順に受ける。Claude Code 2.1.292 を control-plane と同じ
引数で動かし、Bash と Monitor の処理をバックグラウンドで回して確かめた順は次のとおり。

- ターンのない間に最後の処理が終わると、`task_notification`、`background_tasks_changed`（空）、次のターンの
  `system/init` の順に出る。空になってから次のターンの始まりまでは、約 0.1 秒だった。
- ターンの途中で終わった処理は、新しいターンを始めず、動いているターンに取り込まれる。処理の数はそのターンの
  中で減る。
- サブエージェント（Agent）の処理での順は、確かめていない。

## Decision

- エージェントが自分で始めたターンは、そのセッションで最後に出した状態メッセージを書き換えて使い、新しく
  投稿しない。経過時間は、その状態メッセージを出した依頼のターンの始まりから数える。最後に出した状態メッセージを
  control-plane が知らないときだけ、新しく投稿する。
- エージェントが自分で始めたターンの回答は、ターンが終わった時点でバックグラウンドの処理が残っていなければ
  投稿する。残っていれば、すぐには投稿せずに持っておく。
  - 次のターン（自分で始めたターンでも、依頼に答えるターンでも）が始まれば捨てる。
  - ターンのないまま処理が尽きたら、15 秒待ち、その間に次のターンが始まらなければ投稿する。待っている間に
    control-plane が止まるときは、待たずに投稿する。
  - control-plane が止まって中断の知らせを出すときは捨てる。
- 中断されたターンの回答は、処理が残っていても投稿する。
- 依頼に答えるターンの状態メッセージと回答は、これまでどおりにする。

## Alternatives

- **エージェントへの指示で、待つだけのターンに何も答えさせない**：指示は守られないことがあり、仕組みで守る
  （[仕組みで守る](../../../platform/plugins/principles/docs/reference/principles.md#mechanisms)）方を選ぶ。
- **回答の中身を見て、待つだけかを判定する**：文面の判定は言い回しで外れる。バックグラウンドの処理の数という
  事実で決める方が確か。

## Consequences

- 持っておく理由：処理が尽きると、次のターンより先に処理の数が空になったと知らせが来る。すぐ投稿すると、待つ
  だけの回答が処理の尽きるたびに出る。処理がターンを始めずに止められても（依頼者がセッションを止めたとき、
  プロセスが異常で止まったとき）、持っておいた回答は投稿される。
- 15 秒待つ理由：確かめた間隔（約 0.1 秒）より十分に長くし、ホストが混んでいるときや、確かめていない
  サブエージェントの処理でも、次のターンの始まりを待てるようにする。待つ長さが効くのは、次のターンが来ずに
  投稿するとき（セッションを止めたとき、プロセスが異常で止まったとき）の遅れだけなので、長めに取る。
- 中断されたターンをすぐ投稿する理由：止められたターンの後には、エージェントが自分で始めるターンが続かないため。
- 中断の知らせで捨てる理由：持っておいた回答は、中断された処理の途中の話なので、知らせと食い違う。
- 止まるときに待たずに投稿する理由：処理が尽きた後なので中断の知らせは出ず、この回答が最後の結果になる。

- 自分で動いている間にスレッドに増えるのは、書き換わる状態メッセージ一つと、バックグラウンドの処理が尽きた
  ときの回答だけになる。
- 処理が残っている間に依頼が届くと、その依頼のターンが新しい状態メッセージを出し、以後の自分で始めたターンは
  そちらを引き継ぐ。前の状態メッセージは、最後の表示（バックグラウンドの処理の数を含む）のまま残る。
- 終わらないバックグラウンドの処理（開発用サーバーなど）が残っている間は、ほかの処理が終わって始まったターンの
  回答も投稿されない。そのときの結果は、次の依頼への回答で伝わる。
- 回答を投稿しないターンでエージェントが伝えたかったことは、最後のターンの回答がまとめて伝える前提になる。
  エージェントにはハーネスの契約でそう伝える。
- 処理が残ったまま、依頼が届いたばかりで止まるときは、中断の知らせはその依頼への返事として出る。持っておいた
  回答は捨てられずに投稿され、知らせの後に途中の話が残る。止まる直前に依頼が届いたときだけに起き、投稿されるのは
  エージェントが実際に言ったことなので、受け入れる。
