# 0031. 依頼を取り込む前にエージェントが自分で終えたターンは伝えず、依頼のターンが続いているものとする

## Context

ワーカーは、ターンのない間に依頼を送ると、その時点で依頼のターンを始めたことにする（状態メッセージを出す）。
そして、次に来たターンの終わりを、そのターンの終わりとして扱っていた。

Claude Code は、送られた依頼を取り込む前に、自分のターンを先に走らせることがある。再開したセッションでは、
前のプロセスで終わらなかったバックグラウンドの処理を知らせるターン（`__orphan_summary__` の `task-notification`）を
走らせる。依頼を送ったのとほぼ同時にバックグラウンドの処理が終わったときも、その知らせのターンが先に走りうる。

このとき、先に走ったターンの終わりが依頼のターンの終わりとして扱われていた。依頼の状態メッセージは「完了」になり、
取り込んだ依頼のために新しい状態メッセージが出た。先に走ったターンは、取り込んだ依頼がないので、エージェントが
自分で始めたターンとして伝わった。その回答やエラーの知らせは、ADR 0028 と 0029 に従って投稿された（Issue #113）。

## Decision

- 依頼のターンとして始めたのに、取り込んだ依頼がなく、送った依頼が残っているときにターンが終わったら、
  そのターンの終わりを伝えず、依頼のターンが続いているものとする。
  - 状態メッセージは、依頼を送ったときに出した一つが「実行中」のまま続く。
  - そのターンの回答は投稿しない。エラーや使用上限の知らせも出さない（ADR 0028 と 0029 のこの場面の例外）。
    依頼のターンの回答が置き換える。
- エージェントが自分で始めたターンの途中に流し込んだ依頼（`:zap:`）が、そのターンに取り込まれないまま
  ターンが終わったときは、これまでどおりそのターンを伝える。依頼のターンは、そのあと新しく始まる。

## Alternatives

- **先に走ったターンも、エージェントが自分で始めたターンとして伝え、状態メッセージを分ける**：依頼の状態
  メッセージがすでに出ているので、どちらかが一瞬で終わる状態メッセージになる。依頼者が見たいのは依頼の進み具合。
- **先に走ったターンのエラーだけは知らせる**：使用上限なら、続く依頼のターンも同じ理由で終わり、そちらが知らせる。
  そうでないエラーも、依頼のターンが答えられれば要らない。
- **流し込んだ依頼の前のターンも伝えない**：そのターンは、エージェントが自分で始めたターンとして状態メッセージを
  引き継いで見せている。依頼を送った時点で依頼のターンを始めたことにしていないので、ここで隠すと見せ方が食い違う。

## Consequences

- 再開したセッションへの依頼でも、状態メッセージは一つで、回答は依頼への回答だけになる。
- 先に走ったターンでエージェントが伝えたかったことは、依頼のターンの回答がまとめて伝える前提になる。依頼に
  答えるターンが前の回答を置き換えるのと同じで、ハーネスの契約にそう書く。
- 状態メッセージの経過時間は、依頼を送った時から数える。先に走ったターンの時間も含む。
- 先に走ったターンも、セッションのターンの数には数える。
- 先に走ったターンの途中で止めると、送った依頼は取り消されるので、そのターンはエージェントが自分で始めたターンの
  中断として伝わる（これまでどおり）。
- 先に走ったターンで使用上限に当たり、続く依頼のターンが上限を外れて答えた場合、上限に当たったことは伝わらない。
  答えられたので、受け入れる。
