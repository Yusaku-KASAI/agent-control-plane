# 0049. コンテキストが閾値を超えたら、終わった状態メッセージで締めを促す

## Context

一つのスレッド（セッション）で別々の作業を何日も続けると、コンテキストが 85 万〜97 万トークンまで増え、費用の多くが
そうしたセッションに集まっていた。API の呼び出しのたびにコンテキスト全体を読み、間がキャッシュの寿命を超えると全体を
書き直すので、1 回の費用はコンテキストの大きさに比例する（Issue #240）。締め（close-session）は人が頼んだときだけで、
作業の区切りで締めて新しいスレッドに移るきっかけがない（Issue #245）。

Claude Code は、stream-json の assistant のメッセージごとに、それを出した API の呼び出しの使用量（`message.usage` の
`input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`）を付ける。その和が、その呼び出しが読んだ
コンテキストの大きさになる。サブエージェントのメッセージ（`parent_tool_use_id` がある）の値は、サブエージェント自身の
コンテキストのもの。`result` の `usage` はターンのメインのループの呼び出しの分を足したもので、コンテキストの大きさでは
ない（ADR 0036）。

状態メッセージは、終わった状態のときに費用の見積もりを出している（ADR 0037）。

## Decision

- runner は、ターンの中でメインのエージェントの最後の API の呼び出しが読んだトークン数（上の 3 つの和）を、
  コンテキストの大きさとしてターンの結果（`TurnResult.ContextTokens`）に渡す。そのターンに使用量の付いた呼び出しが
  なければ 0（分からない）とする。
- 状態メッセージが終わった状態のとき、その状態メッセージが追ったターンのうち最後に分かったコンテキストの大きさが
  閾値以上なら、費用の見積もりの次に、締めを促す 1 行を出す。「💡 コンテキストが約 45 万トークンです。次の作業は
  新しいスレッドで依頼すると、費用を抑えられます（締めるには「締めて」と頼んでください）」。締めそのものは
  close-session の手順に任せる。control-plane は締めのターンを見分けられず、締めた回答の状態メッセージにもこの行が
  出るので、締めたあとに読んでも食い違わない文面にする。
- 閾値は設定 `sessions.suggest_closing_at`（トークン数）。既定は 40 万、0 で出さない。Issue #240 で自動 compact が
  走った 97 万より十分小さく、一つの作業を続けるセッションより大きい値として仮に決めた。`usage_log` の値で見直す。
- 超えているあいだは、終わった状態メッセージのたびに出す。compact でコンテキストが閾値を下回れば出なくなる。
- ADR 0036 を補う：`usage_log` の行に `context_tokens`（分からなければ `null`）を足す。閾値を見直す材料にする。
- CLI（`acp run`）には出さない（ADR 0037 と同じ）。

## Alternatives

- **PR のマージをきっかけにする**：作業の区切りに合うが、マージを知るには GitHub の webhook かポーリングが要り、
  エージェントの GitHub App は webhook をオフにしている（`acp.example.yaml`）。依頼者がコンテキストの量で知らせる形を
  選んだ。
- **超えたときに 1 回だけ別のメッセージを投稿する**：目に留まりやすいが、知らせたかをセッションの記録に持つ要があり、
  再起動や compact のあとの扱いが増える。状態メッセージの 1 行なら状態を持たずに済み、通知も増えない。
- **エージェントに伝えて、回答の中で促させる**：プロンプトにトークンを足し、エージェントの判断に任せることになる。
  control-plane が事実から決められることは control-plane が出す。
- **セッションの費用の合計で判断する**：合計はコンテキストを compact で縮めても減らず、締めても今の費用は下がらない
  のと区別できない。次の呼び出しの費用に効くのはコンテキストの大きさ。
- **モデルのコンテキストの上限に対する割合で決める**：`modelUsage` の `contextWindow` はモデルごとで、メインの
  エージェントのモデルと結び付けにくい。費用はトークン数そのものに比例するので、数で決める。
- **自動 compact を早める**（Issue #240 の F4）：要約で失うものがあるので保留にしている。

## Consequences

- 長いスレッドで、終わった状態メッセージに締めを促す行が出る。依頼者が「締めて」と頼み、新しいスレッドで続ければ、
  次の作業はコンテキストが小さい所から始まる。
- 閾値より小さいモデル（20 万トークンなど）のセッションでは、Claude Code の自動 compact が先に走り、行は出ない。
- 既定の 40 万は仮の値で、`usage_log` の `context_tokens` で見直す（Issue #245）。
- stream-json の assistant のメッセージに `message.usage`（3 つの項目）と `parent_tool_use_id` が付く形は、会話の
  記録（jsonl）と、認証のない Claude Code が出した stream-json の行で確かめた。実際の API の呼び出しで値が入ることは
  確かめていない。入らなければ行は出ず、`context_tokens` は `null` になる。
