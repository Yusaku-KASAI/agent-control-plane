# 0012. エージェントはセッションのブランチで作業し、PR として届ける

## Context

セッションごとの作業領域（ADR 0010）でエージェントが加えた変更を、人間が確認して取り込める形で届けたい。
作業領域はホスト上の元のリポジトリから clone するため、そのままでは `origin` がコンテナ内から使えない。

## Decision

- 作業領域を作るとき、`origin` を元のリポジトリの `origin` の URL に付け替え、`acp/<セッションIDの先頭8文字>`
  ブランチを作ってチェックアウトする。このブランチ名は `ACP_SESSION_BRANCH` でエージェントに渡す。
- developer ロールは、変更したらコミットして push し、PR を作る（既にあれば更新する）。同じセッションで
  別の PR に分けるときは `<セッションのブランチ>-<内容>` を切る。
- コミットの作者は、エージェントごとに設定した名前とメールアドレスにする。
- main への直接の push などは GitHub のブランチ保護で防ぐ（ADR 0003）。

## Alternatives

- **ブランチ名をエージェントに任せる**：名前は分かりやすくなるが、セッションとの対応が崩れやすい。
- **追加のブランチを `<セッションのブランチ>/<内容>` にする**：git では同名のブランチがあると、それを
  階層に使うブランチを作れない。
- **push せず、人間が作業領域から取り込む**：Slack など手元にいない依頼者が結果を確認できない。

## Consequences

- セッションと PR がおおむね 1 対 1 になり、同じスレッドで続けて依頼すると同じ PR が更新される。
- セッションのブランチは、元のリポジトリでその時点にチェックアウトしていたコミットから始まる。
- Slack などから依頼した人を、作者情報や PR に残す仕組みは別に要る。
