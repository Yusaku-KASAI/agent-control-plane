# 0038. チャットの依頼が受信箱で待つか流し込まれたかをリアクションで示し、送り直されたメンションには何も返さない

## Context

チャットからの依頼には、受け付けた合図としてリアクション（`:eyes:`）を付ける（ADR 0016）。ターンの実行中に
届いた依頼は受信箱に積んでターンのあとに送り、本文が `:zap:` で始まる依頼は実行中のターンに流し込む（ADR 0017、
0019）。どちらになったかは、依頼した人からは見えない。状態メッセージには待っている依頼の数が出るが、自分の依頼が
そのどれかは分からない。流し込んだつもりの依頼が、実行中のターンがなかったために普通の依頼として扱われても
分からない（Issue #179）。

ADR 0016 は、Slack が同じイベントを送り直すと同じセッションのターンが重なり、後の方は「処理中」と返す、とした。
今の Bot は、同じチャンネルと ts のメンションを 1 時間のあいだ一度だけ依頼にし、送り直されたものには何も返さない
（Issue #75）。

## Decision

- 受け付けたときの `:eyes:` に加えて、実行中のターンがあるために受信箱で待たせた依頼には `:inbox_tray:` を、
  実行中のターンに流し込んだ依頼には `:zap:` を付ける。すぐに送れた依頼には足さない。
- 待たせたか流し込んだかはワーカーが決め、依頼の実行（`RunAgentInput.Placed`）を通して入口に知らせる。どう見せるかは
  入口（`ChatResponder`）が決める。
- 待っていた依頼が送られて始まったことは、その依頼のターンの状態メッセージで分かるので、リアクションは足さない。
  付けたリアクションは外さない。
- 送り直されたメンションには、スレッドに何も書かない。依頼者が書いたのは一度だけで、受け付けたことは最初の
  メンションのリアクションで分かる。

## Alternatives

- **扱われ方をスレッドへの短い返事にする**：依頼のたびに投稿が増え、スレッドが読みにくくなる。
- **状態メッセージに、待っている依頼の一覧を出す**：どの依頼が待っているかは分かるが、流し込んだかどうかは
  見えない。依頼のメッセージそのものに付く方が、どの依頼のことかが迷わずに分かる。
- **待っていた依頼が送られたら `:inbox_tray:` を外す**：今どこにあるかは正確になるが、リアクションを外す
  呼び出しが増える。始まったことは状態メッセージで分かる。
- **送り直されたものに「処理中」と返す**：依頼者が書いたのは一度だけなので、返事が増えるだけになる。

## Consequences

- 依頼のメッセージを見れば、待っているか、流し込まれたか、答えを兼ねたか、取り消されたかが分かる。
- 待っていた依頼には、送られたあとも `:inbox_tray:` が残る。今待っているかは、状態メッセージで見る。
- `:zap:` のリアクションは、送ったことを示す。エージェントがそのターンに取り込むか、次のターンに回すかは
  Claude Code が決める（ADR 0019）。
- 再起動の直前に受けたメンションが、再起動のあとに送り直されると、もう一度依頼になる（覚えるのはメモリの中だけ）。
