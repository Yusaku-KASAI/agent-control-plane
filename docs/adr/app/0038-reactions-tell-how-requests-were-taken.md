# 0038. チャットの依頼のメッセージに、受け付けた、取り込まれた、終わったをリアクションで示し、送り直されたメンションには何も返さない

## Context

チャットからの依頼には、受け付けた合図としてリアクション（`:eyes:`）を付けている（ADR 0016）。ターンの実行中に
届いた依頼は受信箱に積んでターンのあとに送り、本文が `:zap:` で始まる依頼は実行中のターンに流し込む（ADR 0017、
0019）。一つのターンに複数の依頼が入ったときは、最初の依頼に返信し、ほかの依頼には `:white_check_mark:` を付ける。

依頼した人からは、次のことが見えない（Issue #179）。

- 自分の依頼が受信箱で待っているのか、エージェントが取りかかっているのか。状態メッセージには待っている依頼の数が
  出るが、どの依頼かは分からない。
- 流し込んだつもりの依頼が、実行中のターンに入ったのか、実行中のターンがなかったか取り込まれずに残ったかで、
  普通の依頼として扱われたのか。
- 待っていた依頼が複数あるとき、どの答えがどの依頼への答えか。答えはスレッドに投稿されるだけで、依頼を指さない。

Claude Code は、送った依頼を取り込んだ時点でその依頼を出力し直すので、ワーカーは依頼がいつ、どのターンに
取り込まれたかを知っている（ADR 0019）。

ADR 0016 は、Slack が同じイベントを送り直すと同じセッションのターンが重なり、後の方は「処理中」と返す、とした。
今の Bot は、同じチャンネルと ts のメンションを 1 時間のあいだ一度だけ依頼にし、送り直されたものには何も返さない
（Issue #75）。

## Decision

- 依頼のメッセージに、依頼がどこまで進んだかをリアクションで足していく。付けたものは外さず、最後に付いたものが
  今の状態を表す。
  - 受け付けた（エージェントがまだ取り込んでいない）：`:inbox_tray:`
  - エージェントが取り込み、取りかかった：`:eyes:`。流し込んだ依頼が、流し込んだときに実行中だったターンに取り込まれた
    ときだけは `:zap:` にする。流し込みの指定があっても、実行中のターンがなかったか、エージェントが次のターンに
    回したときは `:eyes:` にする。
  - 終わった：答えた（自分への回答を返した、同じターンのほかの依頼への回答が答えを兼ねた）なら `:white_check_mark:`、
    エラー（使用上限を含む）や失敗で終わったなら `:warning:`、停止、中断、再起動で取り消したなら `:no_entry_sign:`。
    回答や知らせを返してから付ける。
- 取り込まれたことと、どのターンに取り込まれたかはワーカーが決め、依頼の実行（`RunAgentInput.Taken`）を通して入口に
  知らせる。どう見せるかは入口（`ChatResponder`）が決める。
- 送り直されたメンションには、スレッドに何も書かない。依頼者が書いたのは一度だけで、受け付けたことは最初の
  メンションのリアクションで分かる。

## Alternatives

- **扱われ方をスレッドへの短い返事にする**：依頼のたびに投稿が増え、スレッドが読みにくくなる。
- **状態メッセージに、待っている依頼の一覧を出す**：どの依頼が待っているかは分かるが、流し込まれたか、どの答えが
  どの依頼のものかは分からない。依頼のメッセージそのものに付く方が、どの依頼のことかを迷わない。
- **答えに依頼のメッセージへのリンクを添える**：答えとの対応は分かるが、待っているか取りかかっているかは分からない。
  終わったときに付くリアクションと答えの投稿は同じときに起きるので、対応はそれで追える。
- **進むたびに前のリアクションを外し、今の状態だけを残す**：今の状態は一目で分かるが、外す呼び出しが増え、どう
  進んだか（待ってから始まった、流し込まれた）が残らない。
- **受信箱で待たせたときだけ `:inbox_tray:` を付ける**：すぐ始まった依頼との違いは出るが、取りかかったことと終わった
  ことが分からず、どの答えがどの依頼のものかの問題が残る。
- **送り直されたものに「処理中」と返す**：依頼者が書いたのは一度だけなので、返事が増えるだけになる。

## Consequences

- 依頼のメッセージを見れば、待っているか（`:inbox_tray:` だけ）、取りかかっているか（`:eyes:` か `:zap:` まで）、
  どう終わったかが分かる。
- `:white_check_mark:` は、答えを兼ねたことだけでなく、答えたこと全般を表すようになる。
- すぐ取りかかれた依頼にも、取り込まれるまでの短い間 `:inbox_tray:` だけが付く。
- 取り込まれずに終わった依頼（取り込む前に失敗した、取り消した）には、`:eyes:` も `:zap:` も付かない。
- 再起動の直前に受けたメンションが、再起動のあとに送り直されると、もう一度依頼になる（覚えるのはメモリの中だけ）。
