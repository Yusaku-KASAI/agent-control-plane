# 0040. 作業領域の pre-push フックで、セッションの名前でない新しいブランチを作る push に注意を出す

## Context

control-plane が名前を決めるのは、作業領域を作るときに切るセッションのブランチ `acp/<ID の先頭8文字>` だけ
（ADR 0012）。別の PR に分けるときの `<セッションのブランチ>-<内容>` と、既存の PR を続けるときはその PR の head
ブランチで作業すること（platform の ADR 0020）は、ハーネスの契約の決まりで、守らせる仕組みはない。決まりと
違う名前のブランチを作っても、何も知らせない。

一方で、ほかのセッションの PR のブランチを扱うことと force push は、既存の PR を続けるのに要るので止めない
（Issue #61）。依頼者が名前を指定することもある。

## Decision

- 作業領域の `pre-push`（ADR 0032）で、リモートにまだないブランチ（`refs/heads/` の下で、リモート側のコミットが
  0 のもの。消す push は除く）を作る push を見る。その名前が、セッションが作ったブランチの名前（`SessionID.OwnsBranch`）でなければ、
  `acp pre-push: 注意` で始まる注意を出し、ハーネスの契約の「作業領域とブランチ」を指す。
- push は断らない。注意は、検査（`make check`）の前に、Makefile の有無によらず出す。注意には、合っていなければ
  正しいブランチで push し直し、作ったリモートのブランチを消すことを添える。片付けはセッションの名前のブランチ
  しか消さない（ADR 0026）ので、消さないと残り続ける。
- セッションのブランチの名前は、作業領域を作るときにフックに埋める。`-` で続ける決まりはシェルで写して持ち、
  フックの試験が `OwnsBranch` から期待を求めて、写しが食い違わないことを確かめる。
- ハーネスの契約の push の節に、注意が出ることと、出たときの扱いを書く。

## Alternatives

- **ブランチを作るとき（手元の `git switch -c` など）に見る**：git にはブランチを作る前のフックがない。
  post-checkout では、switch しない `git branch <名前>` を拾えず、既存の PR のブランチを取ってくる `git switch` も
  ブランチを作る操作なので、勧めている動きにまで注意が出る。
- **決まりと違う名前の push を断る**：依頼者が名前を指定したときや、決まりの外の正当な使い方まで止める。
- **既存のブランチへの push や force push にも注意を出す**：既存の PR を続けるときに毎回出て、注意が意味を失う。
- **`ACP_SESSION_BRANCH` をフックが環境から読む**：control-plane 経由でないプロセス（人がホストで作業領域を触る
  など）では空になり、決まりの外のすべての名前を見逃す。作るときに埋めれば、作業領域だけで決まる。
- **harness の PreToolUse の hook で、Bash のコマンドの字面からブランチの作成を見る**：作り方が多く、字面からは
  確かに拾えない（ADR 0032 の Alternatives と同じ）。

## Consequences

- 新しいブランチの名前が決まりと違えば、エージェントは push の出力で気づける。気づいたあとの扱いはエージェントに
  任せる。
- 注意は push ごとに出るのではなく、リモートにそのブランチを作る push でだけ出る。2 回目からの push では出ない。
- この版より前に作った作業領域のフックは置き換わらず、注意は出ない。
- `core.hooksPath` を設定しているターゲットや、`--no-verify` の push では出ない。
