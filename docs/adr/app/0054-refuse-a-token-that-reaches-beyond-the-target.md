# 0054. ターゲットのほかにも届くトークンは、発行しても渡さない

## Context

ADR 0053 は、GitHub App の届く範囲をインストールで絞り、トークンの発行では絞らないと決めた。届く範囲を守るのは
App を入れる人の操作だけで、「All repositories」で入れても control-plane は気づかない（Issue #315）。
選んで入れていても、ターゲットのほかのリポジトリを選んでいたり、あとで足したりすれば、同じように届く。

依頼者の考えとして、届く範囲と権限は GitHub の側（App の設定とインストール）で決め、トークンがそれと一致している方が
分かりやすく管理しやすい。

## Decision

- トークンを発行したら、そのトークンで `GET /installation/repositories`（2 件まで）を読む。発行の応答の
  `repository_selection` が `selected` で、届くリポジトリがターゲットの `origin` のリポジトリ（大文字と小文字は
  区別しない）の 1 件だけのときにだけ、トークンを渡す。
- ほかは発行のエラーにし、届いているリポジトリとターゲットのリポジトリと、直す所（インストールの Repository access）を
  文面に入れる。ターゲットに GitHub の `origin` がないときも、照らす相手がないので渡さず、`origin` を直すか
  エージェントの GitHub App の設定を外すよう案内する。
- 範囲は絞らない。ADR 0053 のとおり、届く範囲を決めるのはインストールのままにし、control-plane は食い違いを知らせる
  だけにする。

## Alternatives

- **発行時に `repositories` をターゲットに絞る**：インストールが広くても届く範囲はターゲットだけになる。ただ、GitHub の
  画面で見える範囲とトークンが実際に届く範囲が食い違い、何が許されているかを知るのに control-plane のコードまで
  読むことになる。広いインストールも気づかれないまま残る。
- **発行の応答の `repository_selection` だけを見る**：呼び出しは増えないが、選んだ中にターゲットのほかのリポジトリが
  あるときを捉えない。
- **`acp serve` の起動時に一度だけ確かめる**：呼び出しは少ないが、動いている間にインストールを変えたときを捉えない。
  トークンは 40 分ごとに発行し直すので、発行のたびに確かめれば、変えたあとの次の発行で捉えられる。

## Consequences

- 発行のたびに、GitHub の API の呼び出しが 1 回と、`git` の呼び出しが 2 回（`rev-parse` と `remote get-url`）増える。
- インストールが広いと、セッションを始められず、動いているセッションはトークンの更新で止まり、片付けもトークンを
  得られずに進まない。どれも、エラーの文面のとおりインストールを直せば戻る。
- 断ったトークンは使わずに捨て、失効させる呼び出しはしない。1 時間で失効し、control-plane の外には渡らない。
- 一つのエージェントが複数のリポジトリを扱う使い方を足すときは、照らす相手を決め直す。
- リポジトリの名前を変えたり移したりして、ターゲットの `origin` が古い名前のままだと、届くリポジトリと合わずに断る。
  文面に両方の名前が出るので、`origin` を直せば戻る。
- 発行の応答に `repository_selection` が入ることと、`GET /installation/repositories` の応答の形は、GitHub の API の
  文書で読んだだけで、本物の GitHub では試していない。
