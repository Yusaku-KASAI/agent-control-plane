# 0066. 動いている間の認証情報の発行し直しは、失敗しても今の認証情報が使える間はやり直す

## Context

ADR 0018 で、control-plane はセッションのプロセスが動いている間、失効より前に認証情報を発行し直す。発行し直しは
40 分ごとで、GitHub App のインストールトークンは 1 時間で失効する。発行か書き換えに一度でも失敗すると、プロセスを
止めて実行中のターンを失敗にしていた。今のトークンはまだ 20 分ほど使えるのに、数分のネットワークの不調が発行し直しの
時刻に重なるだけで依頼が失われた（Issue #393。control-plane の外への通信を 10 分ほど切った確かめで、
`api.github.com` の名前が引けずに失敗し、実行中のターンが止まった）。

Slack の Bot のトークンの更新（ADR 0022）は、失敗をログに出して次の回にやり直し、失効までは今のトークンを使い続ける。

GitHub App の宛先の確かめ（ADR 0054）で断るとき（インストールがターゲットの外まで届く、ターゲットに GitHub の
`origin` がない）は、設定を直すまでやり直しても通らない。

## Decision

- 発行か書き換えに失敗しても、今の認証情報が使える間は、プロセスを止めず、間を置いてやり直す。次のやり直しが
  使える間に収まらなければ、今と同じく止める。失効した認証情報でエージェントを動かし続けない。
- 使える間は、最後に発行し始めた時からの一定の長さ（`CredentialLifetime`）とし、`serve.go` で 55 分にする。
  インストールトークンの 1 時間から、最後のやり直し（発行と宛先の確かめの二つの呼び出しで、それぞれ 30 秒まで）が
  終わるまでの余りを引いた。やり直しの間は 1 分。比べるのは壁時計で、ホストのスリープのあいだも進む。
- 発行元が断ったこと（`domain.ErrCredentialsRefused`）は、やり直さずにすぐ止める。GitHub App の発行元は、宛先の
  確かめで断るときにこれを包む。通信の失敗や GitHub の API のエラーは包まず、やり直す。

## Alternatives

- **発行元が失効の時刻を返し、それまでやり直す**：GitHub は `expires_at` を返すので正確になるが、`domain.Credentials`
  と発行元、`credentialIssuers` のまとめ方が変わる。失効する認証情報は今は GitHub のトークンだけで、その長さは
  発行し直しの間隔（40 分）と同じく `serve.go` が前提にしている。一定の長さで足りる。
- **回数を決めてやり直す**：失効までの残りと結びつかず、ホストのスリープのあとに失効したトークンで動かしうる。
- **失敗しても止めず、次の 40 分の回を待つ**：次の回はトークンの失効の後になり、その間は失効したトークンで動く。
- **断るときもやり直す**：インストールがターゲットの外まで届くと分かったあとも、前に渡したトークンで動かし続ける。

## Consequences

- 発行し直しの時刻に重なる 15 分近くまでの通信の不調では、実行中のターンが止まらない。
- やり直しは control-plane のログに出ない。失効までに通らずに止まったときは、ターンの失敗に最後のエラーが残る。
- 使える間は GitHub App のないエージェントにも同じに当てる。Claude Code の認証は環境変数でコンテナの作成時に決まり、
  Slack の Bot のトークンの失効は発行元（`RotatingSource`）が見るので、それより長く動かせる場面はあっても短くはならない。
- ADR 0018 の「失効より前に発行し直す」は変わらない。変わるのは、発行し直しに失敗したときの扱いだけ。
