# 0062. 作業領域の pre-push フックで、認証情報の値かその形の値を含むコミットの push を止める

## Context

conventions の書き方は、認証情報（トークン、鍵、パスワード）の値を、コミットを含むどの書きものにも書かないと決めて
いる。今は読むことだけで守っていて、コミットに入ったものは push すると履歴に残って広がる（PR #297 のレビュー c19a787 の
指摘 12。#306）。エージェントのコンテナは、GitHub App のトークンと Slack の Bot のトークンをファイルで持ち
（ハーネスの契約の認証情報）、コマンドの出力やログをファイルに写すと、それがそのままコミットに入りうる。

#306 は、GitHub の push protection を既定のブランチの守りの決まりに入れて `check-protection` で確かめる形と、コミットの
前の hook に足す形のどちらかを決めるとしていた。

## Decision

- control-plane が作業領域に置く pre-push フックに、認証情報の確かめを足す。push するコミット（リモートの先頭から先か、
  新しいブランチならどのリモートのブランチにもないもの）のメッセージと、足した行を読み、次があれば値を出さずに止める。
  - コンテナが持つ認証情報の値：`GH_CONFIG_DIR` の `hosts.yml` の `oauth_token` と、`SLACK_BOT_TOKEN_FILE` の中身。
    20 文字に満たない値は、文の中の言葉と取り違えうるので数えない。
  - よく知られた形の値：GitHub のトークン（`gh?_` の 36 文字、`github_pat_`）、Slack のトークン、Anthropic と AWS の鍵、
    秘密鍵の始まりの行。
- 消した行は見ない（すでに push した値を消すコミットは通す）。止めずに通す変数（`ACP_PUSH_OVERWRITE` のようなもの）は
  持たない。認証情報でないものが当たったら、依頼者に伝え、依頼者が作業領域の外から push する。
- push の前に置くのは、上書きの確かめと同じく、push で外に出る前の最後の所で、コミットのあとに直す道（履歴から消す）が
  まだ手元にあるため。

## Alternatives

- **GitHub の push protection を既定のブランチの守りの決まりに入れ、`check-protection` で確かめる**：push protection の
  設定はリポジトリの管理者でないと読めない。エージェントの GitHub App にも CI の `GITHUB_TOKEN` にも Administration の
  権限はなく（ハーネスの契約の認証情報）、確かめられない。organization でない個人の非公開のリポジトリでは使えない。
  コンテナが持つ値そのものではなく、GitHub が知る形だけを見る。
- **コミットの前の hook（pre-commit）に足す**：コミットに入る前に止まるが、`--no-verify` や hook の前に作ったコミットは
  見ない。push の前なら、そのどれもが外に出る前に通る。コミットのたびに読む時間もかかる。
- **target-template の devcontainer（直接動くとき）にも hook を置く**：devcontainer のエージェントと人は、control-plane の
  作業領域を使わない。target-template の共通のファイルとすべてのターゲットに足すことになり、`core.hooksPath` を使う
  ターゲットとぶつかる。今はコンテナが認証情報を持つ control-plane 経由で守り、直接動くときは足さない。
- **`make check` の検査（ターゲットの `check-<関心>`）にする**：ターゲットごとに足すことになり、CI で落ちるときには、
  値はもう push されている。

## Consequences

- control-plane 経由のエージェントの push は、コンテナが持つ認証情報の値とよく知られた形の値を、外に出す前に止める。
  そのあと作る作業領域から効く（フックは作業領域を作るときに置く）。
- devcontainer で直接動くエージェントと、人の push は、このフックを通らない。GitHub の push protection（公開の
  リポジトリでは個人の push にも効く）に任せるが、このリポジトリで効いているかは確かめていない。
- 形で見る値は、試験のための偽の値でも止まる。試験は値を実行のときに組み立てて、ファイルに形のまま書かない。
