# 0050. Slack に投稿する前に、意味を変えずに直せる Markdown の形を直す

## Context

control-plane は、エージェントの最後の回答と状態メッセージを、標準の Markdown のまま Slack の markdown ブロックで
投稿している。Slack はそれを rich_text などのブロックに直して表示するが、規則が標準の Markdown（CommonMark と
GitHub の表）と少し違う。どう違うかは、slack プラグインの[Slack の markdown ブロックが読む形](../../../platform/plugins/slack/docs/reference/markdown.md)に
ある。過去の回答 382 件の保存されたブロックを読むと、次の崩れがあった（2026-10-25）。

- 裸の URL がリンクにならない：67 件。ほとんどは `PR：https://…` のように、URL の前が全角の記号だった。後ろに
  全角の文字が続くと、その文字までリンクに入る。
- `**` がそのまま出る：19 件。`**` の内側が ASCII の記号で、外側が全角の文字のとき。
- 表が表にならない：2 件。表のすぐ上が文字の行だったとき。
- 番号付きのリストの番号が 1 から振り直しになる：28 件（このときは 390 件ほどに増えていた）。項目の下に入れ子を置いた
  とき。Slack はリストを入れ子の前後で分け、後ろのリストに開始番号を付けない。

エージェントには slack スキルで「標準の Markdown で書く」とだけ伝えていた。同じ回答は CLI（`acp run`）にも返る。

## Decision

- slackbot は、投稿の前に、意味を変えずに機械で直せる形を直す。裸の URL は `<…>` で囲み、文字の行のすぐ下の表には
  前に空行を足す。コードブロックとインラインコードの中と、リンクの記法の中（`<…>`、同じ行で閉じる `[…]` の表示の文、`](…)` のリンク先）の URL は変えない。リンクの中にリンクは置けないため。
- URL は、空白、ASCII でない文字、URL に入らない記号（`<`、`>`、`` ` `` など）で終わるとみなし、末尾の文を終える
  記号と、対にならない `)` を外す。
- 機械では直せない形（太字の内側の ASCII の記号、番号付きのリストの項目の下の入れ子、見出しの中の書式、リストの中の
  コードブロック）は、slack スキルの書き方としてエージェントに伝える。エージェントは標準の Markdown で書き続け、Slack に
  固有の直しは Slack のアダプターに閉じる（ADR 0016）。
- slack スキルは依頼のメッセージを読むために使われるので、読み込まれても、最後の回答を書くときに書き方を当てはめるとは
  限らない。依頼のプロンプトに、回答を slack スキルの書き方で書くよう一文足し、ハーネスの契約にも書く。エージェントが
  自分で始めたターンにはプロンプトが届かないので、前のターンで読んだスキルと契約に頼る。

## Alternatives

- **エージェントの書き方だけで直す**：slackctl で自分で投稿するときにも効くが、今の崩れの多くは、書き方を知らないの
  ではなく、URL の前後のような気づきにくい所で起きている。機械で直せるものは仕組みで直す。書き方は、直せないものと、
  エージェントが自分で投稿するときのために残す。
- **太字も直す**：`**` が開きか閉じかは前後の文脈で決まり、空白を足す向きを誤ると、効いていた太字を壊す。正しく
  決めるには Markdown を構文として読む必要があり、今はそこまでしない。
- **control-plane が Markdown を構文として読み、rich_text のブロックを自分で組む**：太字も含めて CommonMark どおりに
  直せるが、Slack のブロックの制約（ブロックの数、表、入れ子）を control-plane が持つことになり、変換の量が大きい。
  直せる形の直しで足りない崩れが続くなら、そのときに考える。
- **Markdown のパーサー（goldmark など）で構文木を作り、直す場所だけを見つけて元の文を直す**：コードスパン、引用や
  リストの中のフェンス、リンクの記法、表の始まりをパーサーが正しく分ける。ただ、依存が一つ増え、構文木から元の文の
  位置へ戻すには節ごとの扱い（記号の位置を持たない節がある）が要る。URL の終わりは Slack に合わせて自分で決めるので、
  パーサーの自動リンクの規則もそのままは使えない。直すのは URL と表の始まりの 2 つで、行ごとの走査で足りる。直す形が
  増えるか、走査の誤りが続くなら、そのときに置き換える。
- **直しを slack プラグイン（`slackctl`）に置き、control-plane もそれを使う**：エージェントが `slackctl post` で投稿する
  ときにも同じ直しが効き、直しが一か所になる。ただ、control-plane は `slackctl` を通らず Go のライブラリで投稿し、
  `slackctl` は bash と jq で書いてあるので、共有するには control-plane がプラグインのコマンドを呼ぶことになる。
  エージェント自身の投稿の扱い（#231 の残り）を決めるときに、`slackctl` にも直しを入れるかを考え直す。
- **投稿のあとに保存されたブロックを読み、番号付きのリストの番号を直して書き換える**：Slack は番号付きのリストを入れ子の
  前後で分け、後ろのリストの開始番号（`offset`）を付けない。投稿の応答のブロックを読んで `offset` を足し、
  `chat.update` で書き換えれば直る。ただ、投稿ごとに書き換えが一回増え、書き換えるまで誤った番号が見え、表などを
  含むブロックをそのまま書き戻す扱いが要る。Markdown の段階では、リストを区切って番号を保つ書き方（HTML のコメントで
  区切る）が空行の置き方で効いたり効かなかったりし、間に空いた行も入るので、直しにできない。まず書き方で避ける。
- **番号付きのリストの、入れ子を持つ項目を、投稿の前に太字の段落（`**1. 題**`）に書き換える**：Slack は段落を挟んだ
  番号付きのリストの番号を保つので、行ごとの走査でも作れる。ただ、エージェントが書いたリストの形を変えて見た目が
  変わり、項目の中の太字と重なり（`**1. **重要****`）、子のリストの終わりを誤ると後ろの項目を巻き込む。崩れは番号だけで
  中身は読めるので、書き方で避け、崩れが続くならそのときに考える。
- **Slack 独自の mrkdwn で書かせる**：同じ回答が CLI にも返るので、エージェントに Slack の記法を選ばせたくない。

## Consequences

- 回答の中の裸の URL は、Slack では前後の文字によらずリンクになる。CLI に返る回答は変えない。
- ASCII でない文字を含む URL（日本語のパスなど）は、その文字の手前で切れる。エージェントが渡す URL は、ほとんどが
  GitHub の URL で ASCII に収まる。
- 字下げしたコードブロック（4 つの空白）の中でも、URL を囲み、表の形の行の前に空行を足す。エージェントはコードブロックをフェンスで書くので受け入れる。
- 太字と、番号付きのリストの入れ子の崩れは、エージェントが slack スキルの書き方を守るかにかかる。
