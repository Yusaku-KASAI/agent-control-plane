# 0019. チャットでは状態メッセージで進み具合を見せ、記号で流し込みと停止を指示する

## Context

セッションのプロセスは動き続け、ターンの始まりと終わり、使っているツール、残っているバックグラウンドの
処理をイベントとして出す（ADR 0017）。チャットから依頼する人には、エージェントが今何をしているかが
見えず、実行中のターンへの流し込みや停止も指示できない。

実行中に送った依頼を、Claude Code はそのターンに取り込むことも、次のターンに回すこともある。
`--replay-user-messages` を付けると、依頼を取り込んだ時点でその依頼を `uuid` 付きで出力し直す。

Claude Code では、`interrupt` は実行中のターンだけを止め、バックグラウンドの処理は動き続けて、終わると
エージェントが自分でターンを始める。ターンがない間に `interrupt` を送っても何も起きない。`stop_task` は
指定したバックグラウンドの処理を止め、その後の再開も起きない。

## Decision

- ターンが始まるたびに、そのセッションのスレッドに状態メッセージを投稿し、イベントと一定の間隔で書き換える。
  状態、経過時間、今の作業、待っている依頼とバックグラウンドの処理の数、セッション ID を示す。
- 本文が `:zap:` で始まる依頼は、実行中のターンに流し込む。依頼は ID を付けて送り、出力し直された時点の
  ターンをその依頼の答えとする。1 つのターンに複数の依頼が入ったときは、最初の依頼にだけ返信し、ほかの依頼の
  メッセージには `:white_check_mark:` を付ける。
- 状態メッセージに `:no_entry_sign:` のリアクションが付いたら、そのセッションを停止する。停止は、実行中の
  ターンへの `interrupt`、残っているバックグラウンドの処理への `stop_task`、受信箱の依頼の取り消しを
  まとめて行う。停止した依頼のメッセージにも同じリアクションを付ける。
- 停止を指示できるのは、そのエージェントに依頼できる人だけにする。
- ターンがなくバックグラウンドの処理だけが残っている間に届いた依頼は、待たせずに送る。

## Alternatives

- **依頼ごとに状態メッセージを出す**：エージェントが自分で始めたターンの様子が見えない。
- **停止を `interrupt` だけにする**：止めたつもりでも、バックグラウンドの処理が終わるとエージェントが再開する。
- **バックグラウンドの処理が終わるまで依頼を待たせる**：開発用サーバーのように終わらない処理があると、
  依頼がずっと進まない。

## Consequences

- Slack アプリに `reactions:read` のスコープと `reaction_added` のイベントが要る。
- Slack は受信の応答が遅れたイベントを送り直すため、同じメッセージへのメンションは一度だけ扱う。
- 状態メッセージの書き換えは数秒おきにまとめて行い、Slack の API の回数制限に収める。
