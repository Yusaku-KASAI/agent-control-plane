# 依頼の仕方

エージェントへの依頼の出し方と止め方。依頼がどう扱われるか（待つ順番、流し込み、停止で止まるもの、再起動での中断）と
何がスレッドに返るかは[依頼と知らせ](../architecture/app/requests.md "在りか")に、セッションの動きは
[セッション](../architecture/app/sessions.md "在りか")にある。

## Slack から

| すること | 操作 |
| --- | --- |
| 依頼する | エージェントの Bot をメンションする。結果はそのスレッドに返る |
| 同じセッションに続けて依頼する | 同じスレッドの中でメンションする |
| 実行中のターンに流し込む | 本文を `:zap:` で始めてメンションする |
| 止める | 依頼のメッセージに `:no_entry_sign:` を付ける。何が止まるか（取り消し、作業の停止、何もしない）は、その依頼の段階で決まる |
| セッションを今すぐ片付ける | スレッドの最初のメッセージに `:wastebasket:` を付ける。保持期間によらず判定し、残す理由がなければ消し、あれば理由をスレッドに返す |
| 失われるものを承知で片付ける | `:wastebasket:` で残す理由が返ったのを見てから（そのあと依頼していなければ）、スレッドの最初のメッセージに `:fire:` を付ける。作業ツリーの変更やどこにも入っていないコミットがあっても消す。開いている PR があるあいだは消さない。理由を見る前に付けた `:fire:` では何も消さない |

依頼がどこまで進んだかは、依頼のメッセージに付くリアクションで分かる（受け付けた、取りかかった、流し込まれた、答えた、
エラーで終わった、取り消した）。一覧は[依頼と知らせ](../architecture/app/requests.md "在りか")にある。

- エージェントは、依頼の本文を、依頼のメッセージを読みに行った時点で読む。待っている間にメッセージを書き換えると、
  書き換えたあとの本文が届く。書き換えても新しい依頼にはならず、取りかかったあとに書き換えても届かない。
- スレッドの中でも、メンションしない発言は依頼にならない。
- 片付ける前にエージェントに「締めて」と頼むと、残すものを Issue に残し、片付けられる状態にする。片付けると、同じ
  スレッドへの次の依頼は、前の会話を引き継がない新しいセッションになる（[片付け](../architecture/app/sessions.md#cleaner "在りか")）。
  同じスレッドで複数のエージェントを使っていれば、それぞれのセッションが片付けの対象になる。
- エージェントが作業しているあいだは片付けない。付け直すときは、リアクションを外してから付ける。

## CLI から

```bash
acp run --agent <name> [--session <id>] [--inject] [--server <url>] "<指示>"
acp stop --agent <name> --session <id> [--server <url>]
```

- サーバーの URL は `--server`、`ACP_SERVER`、`http://127.0.0.1:8787` の順で決まる。API トークンは
  `ACP_API_TOKEN` から読む。
- `--session` を省くと新しいセッションを始め、`--session <id>` を付けるとそのセッションの続きを依頼する。
  結果を stdout に、セッション ID と作業領域のパスを stderr に表示する。エージェントがエラー（使用上限を含む）で
  ターンを終えたときは、そう stderr に書き、終了コード 1 で終わる。
- `--inject` を付けると、実行中のターンに流し込む。`acp stop` はセッション全体を止める（実行中のターン、バックグラウンドの処理、待っている依頼）。
